# 动效

[区分用户触发、游戏判定与影片切点](time-and-input.md)。

先读清输入和状态，再选择表现手段。直接操作、离散切换和阅读停留需要不同的节奏。[交互手感](interaction-feel.md) 讲解提交、打断与恢复；本页是网页动效的实现选项。

## 1. 动效让界面"高级"的四个原因

1. **物理感**：东西有质量，起步加速、到位减速、偶尔轻微回弹。这来自弹簧曲线，而不是 `ease`。
2. **因果**：东西从哪里来、到哪里去——菜单从按钮里长出来，卡片展开成详情，删掉的条目让其余条目滑上来补位。
3. **秩序**：多个元素按阅读顺序依次到场，而不是同时砸下来。交错（stagger）是秩序的来源。
4. **跟手**：按下立刻有反馈（≤80ms），拖动 1:1 跟随，动画可以被打断。

## 2. 弹簧，而不是贝塞尔

`motion.css` 里有四档由真实弹簧物理算出的 `linear()` 缓动（用 `scripts/springs.py` 生成，可以自定刚度与阻尼）：

| 变量 | 物理参数 | 时长 | 过冲 | 用途 |
|---|---|---|---|---|
| `--spring-snappy` | k 520 c 38 | 455ms | 0.8% | 按压回弹、开关、勾选、小元素出现 |
| `--spring-smooth` | k 260 c 32 | 620ms | 0 | 面板、弹窗、卡片抬起、布局变化（默认） |
| `--spring-bouncy` | k 340 c 22 | 640ms | 9.6% | 有意的愉悦时刻：落位、点赞、完成、计数到达 |
| `--spring-gentle` | k 120 c 20 | 681ms | 0 | 大面积入场、首屏编排 |

```css
.panel { transition: transform var(--spring-smooth-dur) var(--spring-smooth); }
```

弹簧的标称时长看起来长（450–680ms），但运动的九成在前三分之一完成，后面是肉眼几乎察觉不到的停稳——感受上比同时长的 `ease` 快且顺。**不要把弹簧时长截短**，那会在末端产生一个突兀的停顿。

弹簧只用于 `transform`、`opacity` 这类"位置与存在"的变化。颜色、边框、阴影用 `--ease-out-quart`，120–240ms。

## 3. 三层动效

| 层 | 是什么 | 频率 | 原则 |
|---|---|---|---|
| **编排** | 首屏到场、区块第一次进入视口 | 每次访问一次 | 有时间表，有先后；总长按使用频率定（见下） |
| **微交互** | hover、按压、焦点、开关、勾选、输入 | 每次操作 | 处处都有；快（按压 ≤80ms 响应）；不挡路 |
| **状态转换** | 展开收起、增删条目、切换视图、数值变化 | 每次状态变化 | 连续而不是跳变；说明因果 |

按用户的阅读、操作频率和输入方式分配运动。工具可以直接显示可用状态，发布页可以有主镜头。用动画说明一次有意义的变化，并保留下一个动作的入口。

## 4. 首屏编排：一张时间表

**编排总长按使用频率定，不按档位。** 档位决定放多少东西（色面、物件、光），使用频率决定开场能占用户多久：

| 使用频率 | 例子 | 首屏编排总长 |
|---|---|---|
| 偶尔来一次 | 营销页、官网、活动页、年度报告 | ≤ 1.2s |
| 一周几次 | 预约、记账、借阅、订票这类消费 App 的首页 | ≤ 0.6s，只编排主角与一两个细节 |
| 每天很多次 | 编辑器、后台、聊天、工具栏 | 不编排，只留微交互与状态转换 |
| 游戏全屏菜单 | 关卡地图、商店、主菜单 | 1.2–2s，任意输入跳到终态 |

所以一个 3 档的预约小程序首页可以有色面、物件和光，但开场不超过 0.6s。

写首屏之前先写时间表。下面是一个 3–4 档页面的典型编排（总长约 1s）：

```
  0ms   导航            淡入 300ms
 80ms   眉题            data-reveal="up"
140ms   大标题          data-split（逐行从下方揭开，行间 80ms）
360ms   副标题与按钮    data-reveal="up"，交错 55ms
300ms   主视觉物件      data-reveal="scale"，--spring-gentle；同时背后光晕淡入
600ms   物件上的细节    数字滚动（data-count）、SVG 线条描绘（.draw）、状态点出现
900ms   次要信息        data-reveal="fade"
```

在 HTML 里用 `--delay` 或 `--i` 控制：

```html
<p class="eyebrow" data-reveal style="--delay:80ms">…</p>
<h1 data-split style="--delay:140ms">周六前，<br>去一趟图书馆</h1>
<div class="hero-object" data-reveal="scale" style="--delay:300ms">…</div>
<ul data-stagger>                       <!-- 子项自动编号 --i，按 55ms 交错 -->
  <li data-reveal>…</li><li data-reveal>…</li>
</ul>
```

规则：
- **按阅读顺序**；最重要的东西不必最先到，但要在 600ms 内到。
- **交错只给前 6–8 项**，其余同时出现。
- **大东西慢、小东西快**：物件用 gentle，文字用 expo-out 揭开。
- 首屏以下的区块：第一次进入视口时轻微淡入上移（`data-reveal`），只播一次。触发条件是元素**上沿**进入可视区（`threshold: 0` 加底部收进 6%），而不是露出某个比例——高的卡片按比例触发会在首屏里留下一块空白。每天打开好几次的工具页，跳过编排，只保留微交互与状态转换。

## 5. 微交互目录

| 元素 | 动效 | 写法 |
|---|---|---|
| 按钮 | 命中边界保持固定，按压改变表面明度。需要轻微缩放时只动内部图形 | `class="pressable"`，可选子元素 `data-press-face` |
| 可点卡片 | hover 抬起 3px、阴影升一档；按下回落 | `class="liftable pressable"` |
| 卡片高光 | 指针处一团柔光跟随 | `class="spotlight"` + `Motion.spotlight()` |
| 链接 | 下划线从左向右长出 | `class="ink-link"` |
| 开关 | 滑块用 snappy 弹簧，轨道颜色 200ms | |
| 勾选 | 勾号用 SVG 描绘 200ms，方框 scale 0.9→1 bouncy | |
| 点赞、收藏、完成 | 图标 scale 0.8→1.15→1（bouncy），可加一圈 6–8 个小点向外散开（300ms） | `Motion.spring(el, [...], 'bouncy')` |
| 数字变化 | 滚动到新值（ease-out-quart 1.1s），或旧值上滑淡出、新值下方滑入 | `data-count` / `Motion.count()` |
| 输入框 | 聚焦时边框色 150ms + 3px 外圈淡入；错误时左右抖动 3 次（总 300ms，幅度 4px） | |
| 复制 | 图标交叉淡化成对勾 1.2s 后换回 | |
| 菜单、弹窗 | 从触发点方向长出：scale 0.97 + 6px 位移，smooth 弹簧；退出 150ms 只做透明度 | `motion.css` 已覆盖 `[popover]` 与 `dialog` |
| Tab 指示条 | 在选项间滑动（FLIP 或 View Transition） | `Motion.flip()` |
| 骨架 → 内容 | 骨架淡出、内容淡入并上移 4px，200ms 交叉 | |

## 6. 状态转换与布局动画

**FLIP**：改变 DOM 前记下位置，改完再从旧位置弹到新位置。排序、过滤、增删、展开都靠它——这是让界面感觉"贵"的关键能力，CSS 做不到。

```js
Motion.flip(document.querySelectorAll('.row'), () => {
  list.prepend(newRow);          // 任何 DOM 变化
}, 'smooth');
Motion.spring(newRow, [{ opacity: 0, transform: 'scale(.96)' }, { opacity: 1, transform: 'none' }], 'snappy');
```

**删除**：先让条目高度收起（`grid-template-rows: 1fr → 0fr`，250ms）同时淡出，其余条目自然上移；或 FLIP。

**View Transition**：整块视图切换（列表 ↔ 详情、筛选结果更新）用 `Motion.swap(() => render())`。给共享的元素同一个 `view-transition-name`，它会从旧位置形变到新位置。

**数值变化**：任何会变的数字都不要跳变。

**进度与时间**：进度条宽度变化用 smooth 弹簧；SVG 曲线用 `.draw` 描绘出来。

## 7. 滚动

- 首屏以下的区块用 `data-reveal` 在第一次进入时淡入上移 18px。
- 长页里的图与物件可以用 `.scroll-in`（CSS 滚动驱动，零 JS）。
- 阅读进度：`.scroll-progress`。
- 吸顶导航滚动 8px 后出现底线与背景模糊。
- 视差只给背景层的大色块或底纹，幅度 ≤ 15%，不给文字。
- 不劫持滚动，不让内容等动画。

## 8. 时长与缓动速查

| 场景 | 时长 | 曲线 |
|---|---|---|
| 颜色、边框、阴影、透明度 | 120–240ms | `--ease-out-quart` |
| 按压 | 80ms 按下 / snappy 弹回 | `--spring-snappy` |
| 小元素出现、勾选、开关 | 455ms | `--spring-snappy` |
| 卡片抬起、面板、弹窗、布局变化 | 620ms | `--spring-smooth` |
| 落位、完成、点赞 | 640ms | `--spring-bouncy` |
| 首屏物件、大面积入场 | 681ms | `--spring-gentle` |
| 标题逐行揭开 | 900ms，行间 80ms | `--ease-out-expo` |
| 数字滚动 | 1.1s | ease-out-quart（脚本内置） |
| SVG 描绘 | 1.4s | `--ease-out-expo` |
| 退出 | 进入的 0.6 倍，只做透明度或小位移 | `--ease-in-quart` |
| 交错步长 | 40–80ms | |

## 9. 性能

- 只动 `transform`、`opacity`、`filter`、`clip-path`。要动高度用 `grid-template-rows` 0fr → 1fr。
- 不写 `transition: all`。
- `backdrop-filter` 与大范围 `filter: blur` 很贵，每屏最多一两处。
- 首屏动画用 CSS 过渡，由 `.is-in` 触发；不要用 JS 逐帧改样式。
- **入场动画不会吞掉元素自己的样式。** `motion.css` 的入场用 `animation`（不是 `transition`），结束后不留任何 transform、filter、transition——导航自己的背景过渡、物件的投影滤镜、被抽出的书的位移都照常生效。需要首屏数字和编排对齐时，用 `data-count` 配 `data-delay="600"`。
- **入场与状态不要抢同一个 `transform`。** `[data-reveal]` 的终态是 `transform: none`，优先级比组件自己的 `.out { transform: … }` 高，会把"被抽出""被选中"这类状态位移抹掉。状态位移改用独立属性 `translate` / `scale` / `rotate`，它们与 `transform` 叠加而不是互相覆盖；需要同时过渡时，在组件上重写 `transition` 并显式写出 `transition-delay` 列表，否则入场的交错延迟会丢。
- **内联动效库时**：内联脚本里（包括注释）不能出现字面的 script 结束标签，否则脚本被截断。入场动画会先把内容藏起来，脚本一挂就是整页空白——所以 `<head>` 里的那行同时设了失败保护：页面解析完 0.6 秒内脚本没跑起来就直接显示内容（见 `assets/motion.js` 开头）。网络字体的样式表要异步加载，否则字体慢时会挡住动效脚本、触发这个保护，入场动画就整个没了——脚手架生成的页面已经这样处理。

## 10. 减弱动效

套件保留完整展示动效的默认配置。新建页面可显式选 `scaffold.py --motion system`，此时操作系统开启“减少动态效果”会立即显示入场内容与读数、解开固定镜头、关闭装饰性位移。已有项目在 HTML 根节点加 `data-respect-reduced-motion` 即可启用相同策略。明确要求完整演示时选 `--motion full`。公共产品设计宜让使用者能遵循自己的动效偏好。[W3C 对这种技术的说明](https://www.w3.org/WAI/WCAG22/Techniques/css/C39)

在正常入口先检查普通偏好，再切换系统或浏览器模拟偏好。保留可操作的控件与结果文字。校验时维持页面的实际配置。关掉 JavaScript 另看关键内容，服务端或原始 HTML 应提供可读的初始状态。

产品演示的滚动镜头见 [产品展示与动效](product-showcase.md)。以同一参照物把进度映射到位移、裁切或透明度。直接拖动、滚动和回滚使用输入位置对应的状态，弹簧留给释放或离散状态切换。

## 10.5 滚动时保持高帧率

先在发生问题的视口录一段滚动，按出现慢帧的位置查同一时刻的脚本、布局、绘制或合成。下面是可逐项关闭作对照的候选原因。实际成本取决于覆盖面积、图层、浏览器和设备。

| 写法 | 为什么卡 | 换成 |
|---|---|---|
| 吸顶导航、浮层上的 `backdrop-filter` | 背后的内容每帧重新模糊 | 接近不透明的底色；确实要毛玻璃只留一处、半径 ≤ 12px |
| SVG `feTurbulence` 噪点、大半径 `filter: blur()` 光晕 | 进入视口时在 CPU 上现算，和视差、浮动叠加时每帧重算 | 预先生成的噪点图片平铺；光晕直接用 `radial-gradient` 画柔边 |
| `mix-blend-mode`、全屏 `position: fixed` 覆盖层 | 整块区域无法单独合成，有动画就整块重绘 | 带透明度的普通图层 |
| 动画或过渡 `box-shadow`、`width`、`height`、`top`、`filter`、`clip-path` | 每帧重新布局或重绘 | 只动 `transform`（translate / scale / rotate）和 `opacity`；阴影变化做成预先画好的一层再改透明度 |
| `<svg>` 里的 `<g>`、`<path>` 做持续动画 | 每帧重绘整张图 | 把动画放到外层 `<svg>` 或包着它的 `<div>` 上 |
| 滚动回调里读位置、改样式 | 交替读写让浏览器反复重新布局 | 进度条用 `animation-timeline: scroll()`；"滚过某处"用 IntersectionObserver；非用脚本不可时用 requestAnimationFrame 合并成每帧一次，先读完再写 |
| 滚动时改会被继承的 CSS 变量 | 整棵子树重算样式 | 用 `@property` 注册成不继承（`motion.css` 里的 `--py`、`--rx` 已经这样做） |

需要定位时运行 `python scripts/perf.py 页面.html --browser "允许的浏览器路径"`。它在受控环境重放输入，报告慢帧和位置。比较两版时保持视口、CPU 降速倍数与输入方式相同，实体设备上的手感另行实测。

## 11. 反模式

| 反模式 | 改法 |
|---|---|
| 什么都不动（只有 hover 变色） | 补上编排、按压、抬起、数字滚动、状态连续 |
| 每个区块都从下面飞进来，幅度 50px | 首屏编排一次；以下区块 18px、只播一次 |
| `ease` / `linear` 的位移 | 弹簧 |
| 回弹用在弹窗、菜单、抽屉上 | 这些用 smooth（无过冲）；bouncy 只给愉悦时刻 |
| 无限循环的浮动、脉冲、渐变流动 | 删除；只有"正在发生"的东西可以循环（同步中、录制中） |
| 动画期间不能操作 | 动画中的元素即可交互；新动画打断旧动画 |
| 数字跳变、列表重排瞬间完成 | `Motion.count()`、`Motion.flip()` |
| 截短弹簧时长 | 保留完整时长，弹簧的尾巴是停稳的过程 |
| 遵守减弱动效时自己另写一套 | 在 `<html>` 加 `data-respect-reduced-motion`，`motion.css` / `motion.js` 已处理 |
