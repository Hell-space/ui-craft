组件的品质体现在两处：**静态时的比例**，和**交互时每一种状态都被考虑过**。

## 1. 状态总表

每个可交互元素都要逐项过一遍。没有设计的状态会由浏览器默认样式填补，那通常是界面里最显眼的破绽。

| 状态 | 触发 | 视觉处理 |
|---|---|---|
| 默认 | — | 基准 |
| Hover | 指针悬停 | 背景或边框明度变化 0.03–0.05；100–150ms 过渡。仅在 `@media (hover: hover)` 下生效，避免触屏上残留 |
| Focus-visible | 键盘聚焦 | 2px 强调色外描边 + 2px 间隙。**不可省略**，不可只是颜色微变 |
| Active / pressed | 按下 | 比 hover 再深一档；可加 `scale(0.97–0.98)` |
| Selected / current | 已选中、当前页 | 强调色浅底或指示条；必须与 hover 可区分 |
| Disabled | 不可用 | 低对比文字与底色，`cursor: not-allowed`；说明为什么不可用（提示或辅助文字） |
| Loading | 等待响应 | 保持尺寸不变，内容换成加载指示；禁止重复提交 |
| Invalid | 校验失败 | 危险色边框 + 图标 + 文字说明 |
| Read-only | 只读 | 去掉边框或用凹陷底，区别于 disabled |

焦点环的通用写法：

```css
:focus-visible {
  outline: 2px solid var(--focus-ring);
  outline-offset: 2px;
}
/* 永远不要写 outline: none 而不提供替代 */
```

## 2. 按钮

### 层级

一个视图里按钮分三级，**主要按钮每屏只有一个**：

| 层级 | 样式 | 用途 |
|---|---|---|
| 主要 | 强调色实底 | 这一屏最重要的那个动作 |
| 次要 | 中性描边或浅底 | 并列的其他动作 |
| 三级（ghost） | 无底无边，仅文字 | 低频、取消、工具栏 |
| 危险 | 危险色（常为描边或浅底，确认时才用实底） | 删除等不可逆操作 |

两个实底按钮并排，用户就不知道该点哪个。

### 比例

- 高度：28（紧凑）/ 32 / 36（默认）/ 40 / 44（触屏）。与同行的输入框等高。
- 横向内边距约为高度的 0.35–0.45 倍（36px 高配 14–16px）；纯图标按钮为正方形。
- 文字 13–15px，字重 500–600，不换行。
- 图标 16px（小按钮）或 18–20px，与文字间距 6–8px；带前置图标时该侧内边距可减 2px 以求光学平衡。
- 圆角取自阶梯，与输入框一致。

### 细节

- 主按钮的"可按"质感：`box-shadow: 0 1px 2px oklch(0.2 0.02 H / 0.2), inset 0 1px 0 oklch(1 0 0 / 0.14)`——一道贴底影加 1px 内高光，不做渐变。
- 按下：背景再深一级并 `translateY(0.5–1px)`；带箭头的按钮 hover 时箭头右移 3px。
- 禁用：明确的凹槽底加淡字。实底按钮用 `opacity: 0.5` 也可以接受；叠在彩色或图像背景上的元素不行——半透明叠出来的颜色不可预测。
- 加载态：保持宽度，文字换成或加上 spinner，文案换成进行时（"保存中…"），避免按钮宽度跳动。
- 按下反馈要即时（不等过渡结束）。
- 文案用动词并说清对象："保存修改""创建项目""删除 3 个文件"，而不是"确定""提交""OK"。
- 触屏上点击区不小于 44px，即使视觉上更小（用伪元素扩大热区）。
- 链接是去某处，按钮是做某事。导航用 `<a>`，动作用 `<button>`。

## 3. 表单与输入

- **标签始终可见**，放在输入框上方、左对齐。不要用 placeholder 充当标签——一输入就消失，且对比度通常不足。
- **placeholder 只放示例格式**（"name@example.com"），可有可无。
- 标签到输入框 6–8px，字段到字段 20–24px，分组到分组 32–40px。
- **单列布局**完成率最高。只有天然成对的短字段（省/市、年/月）才并排。
- **输入框宽度暗示内容长度**：邮编不该和地址一样宽。
- 边界要清楚：输入框边框需与背景有 3:1 对比（用 `--border-control`），或用明显的凹陷底色。
- 高度与按钮一致；内边距横向 10–12px。
- **帮助文字**放在输入框下方，13px，次要色；**错误信息**出现在同一位置并替换它，配图标，说明如何修正。
- **校验时机**：失焦时校验，而不是每敲一个字就报错；提交失败时聚焦到第一个出错字段。
- 必填/选填：标记数量较少的那一类。
- 用对控件：2–5 个互斥选项用单选组或分段控件，而不是下拉；开关用于即时生效的设置，复选框用于需要提交的选择。
- 复选框、单选、开关都要重新设计到与整体一致，至少用 `accent-color` 统一颜色。
- 当用户已进入编辑任务时，可以聚焦首个待填字段。阅读详情优先让层内标题或可见控件接收焦点，避免手机过早弹出键盘。按字段选择 `type`、`inputmode` 和 `autocomplete`。
- 提交按钮左对齐于字段（与标签同一条线），不要孤零零飘在右下角。

## 4. 卡片

**先问是否需要卡片。** 卡片表示"一个独立的、可整体操作的对象"。若只是为了给内容分组，间距或一条线更合适。满屏卡片（card soup）会抹平层级。

确实用卡片时：

- 内边距 16–24px，且不小于内部元素间距。
- 静止的卡片：1px 边框；或"影子线"——`box-shadow: 0 0 0 1px var(--border), 0 1px 2px rgba(暖色, .04)`，一圈 1px 的环加几乎看不见的贴底影，不占布局尺寸。不要粗边框加重阴影。纸墨语域里卡片常常干脆没有阴影，只靠比纸亮一档的卡面。
- 嵌套圆角同心：卡片圆角 12px、内边距 8px 时，内部图片圆角为 4px。
- 可点击的卡片：整卡是一个点击目标，hover 只把 `border-color` 从 `--border` 变到 `--border-strong`，150ms。不抬起、不加阴影。只有营销页的大卡片可以 `translateY(-2px)` 加 `--shadow-2`。不可点击的卡片没有 hover 态。
- 卡片内的层级：一个主信息（标题或关键数字）、一两条次要信息、至多一个主要动作。
- 同一网格里的卡片结构一致、内部元素跨卡对齐。
- 不要卡片套卡片。内层用凹陷底色或分隔线。

## 5. 表格与列表

表格是数据密集界面的核心，值得细做。

- **对齐**：文字左对齐，数字右对齐并用 `tabular-nums`，状态和操作可居中或右对齐。表头与其列同向对齐。
- **表头**：12–13px、次要色、字重 500，可用全大写加字距（西文）；与数据行明显区分但不抢戏。
- **行高**：紧凑 32–36px，默认 40–44px，舒适 52px 以上。
- **分隔**：只用横向细线，或只用斑马纹，不要两者并用，更不要画满格线。
- **行 hover** 给极淡的底色，帮助视线横向追踪。
- **第一列是主键列**，用主文字色和稍重的字重；其余列用次要色，层级立现。
- **长内容**：单行截断加 tooltip，或允许换行但限制行数。
- **吸顶表头**与首列冻结，用于长表与宽表。
- **行内操作**：低频操作收进"更多"菜单；hover 才显现的按钮必须同时在键盘聚焦时显现。
- **排序与筛选**状态要可见（箭头、已选筛选的胶囊标签）。
- **数值**带单位时，单位放表头而非每个单元格；正负用符号加颜色，不只靠颜色。
- **空表格**不要只剩表头：给出说明和下一步动作。
- 窄屏：横向滚动（首列冻结），或改成卡片列表，只保留最关键的两三个字段。

列表项：左侧图标或头像、中间标题加一行次要信息、右侧元信息或操作。行高至少 44px（可点击时）。

## 6. 导航

- **当前位置必须清晰**，并且与 hover 可区分：
  - hover = 中性叠层（`--text` 的 4%）；
  - 侧栏选中 = 中性叠层 7% + 主文字色 + 500 字重，图标也回到主文字色；
  - 列表选中行 = 强调色极淡的底 + 左侧 2px 强调色竖条（"竖条是给余光看的，底色是给正视看的"）；
  - 筛选胶囊、分段控件选中 = 强调色浅底 + 强调色文字。
  并设 `aria-current="page"` 或 `aria-selected`。
- **侧栏**：宽 228–240px；项高 32px、内边距 8px、圆角 6px；图标 16px、与文字 gap 8px；字号 13–14px；项间距 1–2px；分组标题 11–12px 次要色，分组间距 16–24px。这些尺寸互相对齐，是后台显得规整的关键。
- **顶栏**：后台 48–56px、营销 64px；与侧栏顶部的切换器同高，底边一条线贯通各栏。营销页的导航默认透明无边框，滚动超过 8px 才出现底线与背景模糊。项数不超过 5–7 个。
- **外壳要安静**：导航、工具栏、标签全部用次要色、13px、500 字重，图标比相邻文字淡一档。外壳的视觉重量应明显轻于内容。
- **快捷键提示**用键帽样式的 `<kbd>`：`font: 500 11px/1 mono; padding: 3px 5px; border: 1px solid; border-bottom-width: 2px; border-radius: 4px`。
- **标签页（tabs）**：用于同一对象的并列视图；指示线 2px，切换时可平滑移动。不要用标签页做步骤流程。
- **面包屑**：层级深于两层时提供；当前页不是链接。
- **移动端**：3–5 个主要目的地用底部标签栏；更多则用抽屉。底部栏图标配文字标签。
- 导航项的文字是名词（去哪），按钮的文字是动词（做什么）。

## 7. 弹窗、抽屉、浮层

**尽量少用模态。** 它打断用户、遮住上下文。能内联就内联（行内编辑、展开面板），能用非模态浮层就不用模态。

| 类型 | 尺寸 | 入场 | 说明 |
|---|---|---|---|
| 对话框 | 宽 400–560px，最大高度 85vh，内容区滚动 | 淡入 + `scale(0.96→1)`，200–250ms | 遮罩 `oklch(0 0 0 / 0.4–0.6)` |
| 抽屉 | 宽 360–480px，或移动端底部弹出 | 从边缘滑入，250–300ms | 适合编辑详情、筛选 |
| 下拉菜单 / 气泡 | 宽 180–320px | 淡入 + 向内 4px 位移或 `scale(0.96)`，120–160ms，从触发点方向展开 | 阴影第二级 |
| Tooltip | 最大宽 240px，12–13px 字 | 延迟 300–500ms 出现，淡入 100ms | 只放补充信息，不放必要信息或可交互内容 |
| Toast | 宽 320–420px | 从边缘滑入 | 4–6 秒自动消失；含操作的要更久或可手动关闭 |

对话框要点：

- 用原生 `<dialog>` 或可靠的无障碍组件；打开时焦点移入并困在其中，Esc 关闭，关闭后焦点回到触发元素。
- 标题说明这是什么；正文简短；动作按钮右对齐（主要动作在最右）或遵循平台惯例。
- **危险确认**：按钮文字写出具体动作（"删除项目"而不是"确定"），高风险操作要求输入名称确认。
- 遮罩点击可关闭——除非有未保存的输入。
- 模态打开时锁住背景实际滚动的容器。关闭、进入下一层与退回上一层的坐标和焦点验收见[主页面位置](frontend-workmanship.md#主页面位置)。

**浮层一定同时用环和投影。** 只有阴影的浮层在白底上轮廓发虚，只有边框的浮层没有高度感。这是让界面从"干净"变成"精致"的最小手段：

```css
/* 下拉、popover、toast */
box-shadow: 0 0 0 1px oklch(0.25 0.02 H / 0.08),
            0 2px 4px -1px oklch(0.25 0.02 H / 0.06),
            0 12px 24px -6px oklch(0.25 0.02 H / 0.14);
/* 弹窗：把最后一层换成 0 24px 48px -12px … / 0.20 */
/* 暗色：环换成 oklch(1 0 0 / 0.10)，投影不透明度约乘 3 */
```

任何一层的不透明度不超过 0.22，模糊半径不超过 48px；颜色带底色的色相，不用纯黑。`assets/tokens.css` 里的 `--shadow-2`、`--shadow-3` 就是这个写法。

滚动容器的小处：横向滚动的标签栏、长列表的边缘用 `mask-image` 渐隐；滚动条 `scrollbar-width: thin; scrollbar-color: var(--border-strong) transparent`。

## 8. 反馈：加载、空、错误、通知

这些"非理想状态"占用户实际体验的很大比例，却最常被遗漏。

**加载**

- 少于约 300ms 不显示任何指示（闪一下反而更糟）。
- 内容区用**骨架屏**，其形状要与真实布局一致；配一个缓慢的微光或脉冲动画。
- 按钮和局部操作用小 spinner。
- 耗时长的操作给出进度和说明（"正在导入第 240 / 1,200 行"）。
- 乐观更新：能预判成功的操作先更新界面，失败再回滚并告知。

**空状态**

空状态是引导的机会，不是死胡同。包含：一句说明这里将会有什么、一个开始的动作，可选一个简洁的图示。区分三种空：首次使用（引导创建）、筛选无结果（提供清除筛选）、已全部处理完（给一点正向反馈）。

**错误**

- 说人话：发生了什么、为什么、接下来怎么办。不要只给"出错了"或错误码。
- 就近显示：字段错误在字段下，区块错误在区块内，全局错误才用横幅或 toast。
- 永远给出路：重试、返回、联系支持。
- 不责怪用户（"邮箱格式不正确"优于"你输入了无效的邮箱"）。
- 保留用户已输入的内容。

**通知**

- 成功提示简短，自动消失。
- 可撤销的操作在 toast 里提供"撤销"，比事前弹确认框更流畅。
- 不要用 toast 承载需要用户阅读或操作的重要信息。
- 屏幕阅读器：状态变化用 `role="status"` 或 `aria-live`。

## 9. 徽标、标签、头像

- **状态徽标**用"浅底深字"的低饱和样式（语义色的浅底 + 同色相深色文字），不要每个都是高饱和实底——那会让表格像圣诞树。
- 徽标高 20–24px，字 11–12px，字重 500，横向内边距 6–8px。圆角与整体语言一致（不一定是全圆）。
- 状态除了颜色再加一个小圆点或图标，不单靠颜色。
- 计数徽标：超过 99 显示"99+"；为 0 时隐藏。
- **头像**：圆形或圆角方形，尺寸 24 / 32 / 40 / 64；无图时用首字母加由名字派生的底色；堆叠时互相遮挡并加与背景同色的描边。
- 没有信息量的装饰徽标（"✨ 全新"）删掉。

## 10. 图标

- **用一套**，线宽统一、风格统一（全线性或全填充；可用填充态表示"选中"）。Opus 5.5 的八个样本全部是自己画的内联 SVG、1.3–1.6px 描边；用图标库时选 Lucide、Phosphor、Tabler 这类线宽一致的。
- 线宽跟随字重：400 的正文配 1.5px，500–600 的按钮文字配 1.75–2px。
- 尺寸：16px 图标配 13–14px 文字，20px 配 16px；图标按钮是 28 / 32 / 36 的正方形。垂直方向做光学对齐。
- 颜色跟随文字（`currentColor`），比相邻文字淡一档；**当前选中项的图标回到主文字色**。
- **状态图标用形状编码含义**：进度饼（空环、半饼、四分之三饼、实心勾）、信号条表示优先级、紧急用完全不同的形状。只靠颜色区分的状态，色觉缺陷用户读不出来，列表也会变成彩虹。
- **不要用 emoji 当界面图标**：跨平台不一致、风格不可控、无法跟随主题色。
- 纯图标按钮必须有 `aria-label` 和 tooltip。
- 不认识的图标等于噪音：除了通用图标（搜索、关闭、设置、更多），其余都配文字标签。
- 不是每个标题、每个列表项都需要图标。图标过多会让界面变成象形文字墙。
- 内联 SVG 设置 `aria-hidden="true"`（装饰性）或提供标题（表意性）。

## 11. 微文案

文字是界面的一部分，也需要设计。

- **命名跟任务走。** 导航、筛选和字段用用户熟悉的短名；确有结论的数据故事才把结论写在标题里。口径、条件和出错后的下一步放在需要它的对象附近。
- **用实际断行定长度。** 标题让人识别内容，按钮写清动作及必要的对象。手机上仍能区分两个相邻操作时就可以停笔。
- **危险确认**：两个按钮都写具体动作——"中止烧制"与"继续烧制"，而不是"确定"与"取消"；正文给出具体后果（多少件、会怎样）。
- **诚实**：示意图标"非实际比例"；统计数字写出处与时间窗口；不放假评价、假 logo 墙、编造的资质编号。
- **简短、具体、主动语态。** "已保存"优于"您的更改已经被成功保存"。
- **一致**：同一个概念全程用同一个词（不要"删除""移除""清除"混用）。
- **按钮说清结果**；标题说清这是什么；说明文字回答"为什么"和"会怎样"。
- **数字要人性化**：1,284 而不是 1284；"3 分钟前"而不是完整时间戳（悬停显示完整）；合理的精度（12.4% 而不是 12.384615%）。
