# 操作手感

## 先画一次动作

找用户反复做的真实动作，写下输入、临时预览、提交、取消各自的所有者。按下和确认可能相隔很久。数据变化、画面反馈和声音都订阅同一个提交结果。这样即使动画被打断，模型中的选项、消耗或顺序仍然确定。

| 情境 | 第一个响应 | 提交与恢复 |
|---|---|---|
| 常规按钮、开关 | 按下改变接触面、描边或明度，保持命中框固定 | 系统 click / activated 提交一次。指针移出再松开遵从平台惯例。键盘用控件原生激活行为 |
| 裁切、排序、时间轴 | 命中手柄后给出抓取态，移动时按手指或指针位置更新同一对象 | 开始时存快照，松开提交，Esc、失去捕获或系统取消还原。给方向键、数值输入或移动按钮等替代入口 |
| 异步保存、购买、提交 | 立刻说明已接收，保留动作用于哪个对象 | 完成时核对最新请求与对象。失败还原可编辑状态，保留输入；重复确认遵守幂等或防重规则 |
| 弹层、子菜单、背包 | 原控件立即呈现打开状态；打开层取得键盘或手柄焦点 | 每次返回退出最上层。关闭恢复来源控件，原对象不存在时找邻项。负责关闭的按键由该层消费 |
| 数值、进度、冷却 | 当前值和可用性按真实模型更新，提示落在变化发生处 | 视觉追随层可稍后追上。连续变化接住当前显示值。切场景、减少动态或跳过时终止旧回调 |

## 指针、键盘与手柄

普通按钮、滑块、单选和对话框优先用平台实现。自制手势要明确鼠标主键、笔和触屏行为。拖动发生在手柄上时，可从约 4–8 个 CSS 像素的移动阈值试调；画布上的触屏手势还要与纵向页面滚动和双指缩放共存。按开始值与当前绝对坐标计算预览，避免把每帧增量反复累加。在释放阶段统一提交。浏览器中配对处理 `pointercancel`、`lostpointercapture` 与失焦，忽略其他指针。

键盘要能到达同一结果，视觉焦点和应用的已选值分别表示。保留文本编辑、组合输入、平台快捷键，以及 Tab 的自然去向。允许长按方向键重复移动；触发一次交易、打开菜单、切换开关的操作用按下边沿或控件原生激活。拖动的单指替代也应可用，例如点选对象后用上移或下移按钮完成排序。[W3C 拖动操作](https://www.w3.org/WAI/WCAG22/Understanding/dragging-movements.html) · [W3C 指针取消](https://www.w3.org/WAI/WCAG22/Understanding/pointer-cancellation.html)

游戏里的输入由最上层可交互界面接管。确认、返回与移动按逻辑动作映射，提示跟随最后一次有意输入。摇杆采用死区，需要一段连续移动时区分进入阈值和回中阈值；方向键支持停稳的重复节奏。成为活动设备前应过滤摇杆漂移和无位移的鼠标事件。平台或玩家重映射了按键时，提示取自映射。引擎有导航系统就用它维护空间关系。[Xbox 焦点与导航指南](https://learn.microsoft.com/en-us/xbox/accessibility/xbox-accessibility-guidelines/112)

## 动作能被接住

按下反馈可以是一次明度变化或按键表面的轻微下沉。位移只加在图形层，让可点击区域和对齐线稳定。频繁动作尽早可再操作。短距离归位可从约 100–220ms 起试；直接拖动阶段让图形跟手，减少动态时保留焦点、文字和最终状态。以目标设备实际操作调整这些数值。

对开关、展开和快速切换，先记录屏幕当前状态，再取消自己上一次的动画，重算目标。只有最新状态能写入结果。一个组件的取消操作只终止它拥有的动画。按键确认的逻辑不用等待弹簧或声效。慢速返回的网络回复也应用同一条归属规则。

### 网页里的实现入口

自制画布手柄可复用 `Motion.drag(handle, callbacks, {threshold: 5})`。在专用手柄上设置合适的 `touch-action`，其余区域保留页面滚动。回调收到视口坐标 `x/y`、起点 `startX/startY`、总位移 `dx/dy` 和事件。越过阈值时抓取一次业务快照，随后更新预览。失焦、Esc、捕获丢失、系统取消或卸载会还原预览。用返回对象的 `cancel()` 让键盘接管，`dispose()` 解绑。

```js
let original;
const gesture = Motion.drag(grip, {
  start() { original = editor.crop; },
  move({ dx, dy }) { view.previewCrop(editor.offsetCrop(original, dx, dy)); },
  commit({ dx, dy }) { editor.setCrop(editor.offsetCrop(original, dx, dy)); },
  cancel() { view.previewCrop(original); }
});
function nudge(dx, dy) {
  gesture.cancel();
  editor.setCrop(editor.offsetCrop(editor.crop, dx, dy));
}
// 点击微调、触屏按钮和键盘都调用 nudge。组件卸载时调用 gesture.dispose()。
```

列表重排的 `Motion.flip(rows, mutate)` 会从当前显示位置接续快速反转，只取消自身创建的布局动画。对动态读数传 `Motion.count(label, {to: 新值})` 可覆盖旧目标，`duration: 0` 直接到终值；`Motion.stopCount(label)` 停掉延时和帧回调。金额、冷却、库存与结算仍由业务模型计算。

混合设备上鼠标与触屏可各有一个主指针。仅检查 `isPrimary` 或只在旧手柄中过滤指针 ID，无法覆盖另一项按钮的 click。将移动、撤销、删除和刷新集中到同一组业务动作中：每条替代路径先取消尚未提交的手势，再读取当前数据并执行自己的更改。测试时抓住 A 不松手，用触屏移动 B，最后松开鼠标；最终应只有 B 的一次编辑，撤销也恰好还原这一次。

[声序片段编排工作台](../examples/clip-workstation.html) 是可离线操作的完整案例。它用同一组片段身份关联列表、波形、试听和撤销。方向键选择片段，Alt 加上、下方向键调整顺序。把一段拖过相邻项，再改用键盘或另一行的移动按钮，观察预览、已提交顺序和焦点分别归到哪里。

## 实测一次完整往返

1. 在实际控件上按下、暂停、移出、松开。再连按，然后在动画中反向。分别观察第一次反馈、提交次数、最终状态和下一次输入是否立即可用。
2. 在拖动中取消、切窗口或改变视口；用键盘或替代按钮达到同一位置。打开下一层、反向退出并立刻操作，查焦点、滚动位置和输入穿透。
   例如保持鼠标按下时用键盘移动选中的片段，再松鼠标，过期的释放应产生零次额外提交。点“上移”到列表首位后该按钮失效，应把键盘焦点留在同一片段的可用控件上，随后立即尝试反向移动。
3. 对等待型操作模拟慢成功、失败及快速重试。先完成的旧请求不得盖过新结果。涉及 undo 时在连续两次编辑后撤销一次，检查只回退约定的粒度。
4. 开启减少动态，关闭声音再走一遍。游戏再测方向键、手柄方向与确认释放，切回键鼠，观察一次快速连续的 HUD 状态变化。看亮景和暗景时同时保留真正的玩法画面。

可以记录输入处理、下一绘制回调、业务提交和动画结束的顺序，或录制真实设备慢动作。脚本事件和下一次帧回调只证明引擎或浏览器中的状态变化；端到端硬件延迟、真实触感和实体手柄震动需要对应设备验证。
