## 1. 营销落地页 / 官网

**用户状态**：陌生、没耐心、几秒内决定去留。表现力的预算最高，密度最低。

**先确定访客的任务。** 工具介绍首屏可以直接给实际工作结果和入口。单件作品页让人认得对象、有效规格和关键细节，配全貌、展开或局部的真实切换。[金工图形校样](../examples/metal-study.html)中的铰链共用同一件物体与轴心。下面的选项按传播任务取用。

- 一句具体的标题（说结果，不说形容词。"把周报从两小时缩到十分钟"优于"下一代智能效率平台"）。
- 一两句补充说明。
- 一个主要行动按钮，至多再加一个次要的。
- 一个主视觉：真实的产品画面、有力的排版、或与题目相关的图像。**产品本身的界面通常是最好的主视觉。**
- 可选：一条信任信息（客户、数据、评价）。

**首屏构图看主视觉有没有内容。** 当产品界面本身好看、能当主视觉时，"标题 + 下方一块带边框的真实产品片段"完全成立——失败的是下面放了抽象插画、渐变球或假的仪表盘。Opus 5.5 的落地页样本是：标题左对齐、宽度限制在约 820px，真实感的产品界面横跨全宽放在下方——"先读承诺，再看证据"。其他可选：比例分栏（4:7、5:6）、超大排版占满首屏、整版色块加一行字。一律禁止某种构图只会制造新的套路。

**全页的节奏。** 作品目录可以先陈列多件同尺度对象；品牌故事可以从一件实物的细节进入工序；产品比较适合共享基线。在已给证言、价格和案例时，放在访客需要用它们判断的地方。宽窄屏都要能从主视觉追到对应物件或规格。

**要点**

- 特性不要排成三张等大的图标卡片。改为：一大带几小的 bento；图文左右交错；带真实界面截图的逐条展开；一张对比表。
- 每个区块只讲一件事，区块之间用留白或底色变化分隔，节奏有松有紧。
- 文案具体：真实数字、真实客户名、真实场景。删掉"强大""无缝""赋能""革命性"。
- 行动召唤在长页面里重复出现，文案一致。
- 定价表：推荐方案用视觉重点标出；价格数字要大；特性列表对齐可比。
- 页脚不是垃圾桶：分组清晰，对比度够。
- 这是最值得做首屏入场编排的类型，也是最容易动效过度的类型。
- 性能即设计：首屏图片优化、字体预加载、避免布局跳动。

## 2. Dashboard / 数据面板

**用户状态**：带着问题来——"现在情况如何？有没有需要我处理的？"

**最常见的失败**：顶部四个统计卡 + 一张折线图 + 一张表，每块同等权重，没有回答任何问题。

**先分清是"盯盘"还是"每天读一次"。** 后者是一份晨报，不是一面监控墙：主角是一段用人话写的摘要（昨天怎么样、离目标差多少、今天先做什么），数字退到第二层去佐证这段话，图表退到第三层供追问。待办不是通知列表——每条写明原因和建议动作，按影响排序。这类页面不做入场动画和数字滚动。样本见 `specimens/02-dashboard`。

**做法**

- **先确定这个面板要回答的头三个问题**，据此决定层级。最重要的那个数字或那张图要明显更大。
- **进度要带对照物**：目标进度条上加一根"时间进度"的刻度，并直接写出差额（"落后 ¥31 万"）。环形图表达不了这个对照，所以不用环形图。
- **每个指标写明对比基准和口径**（"较上周一"，周一对周一避开星期效应；"可售天数已扣预售锁定"）。
- **颜色表达好坏，箭头表达方向**：退款率下降是绿色。只有最大的那个系列用强调色，其余用灰，不用彩虹配色区分渠道。
- **数字要有上下文**：单独一个"12,480"没有意义。配上环比、目标、趋势迷你图、与昨天的对比。
- **层级**：概览（发生了什么）→ 趋势（怎么变的）→ 明细（具体是哪些）。从上到下、从粗到细。
- **不要把每个指标都装进卡片。** 一行用细线分隔的指标带往往比四张卡片更干净、更省空间。
- **异常要跳出来**：正常状态安静，只有需要注意的东西才用颜色。满屏彩色等于没有重点。
- **密度偏高**：专业用户希望一屏看全。紧凑但对齐严格。
- **筛选与时间范围**放在固定、显眼的位置；当前筛选状态始终可见。
- **图表**：选对图表类型；去掉多余的网格线和边框；直接标注而不是依赖图例；颜色有语义且一致；坐标轴文字用次要色。若环境里有专门的数据可视化 skill，做图表前先用它。
- **数字排版**：tabular-nums、千分位、合适的精度、单位弱化。
- **加载与空状态**：每个模块独立加载，用匹配布局的骨架屏；无数据时说明原因。
- **可定制**不是必须，但默认布局必须有主见。

## 3. 工具型应用（编辑器、管理后台、生产力工具）

**用户状态**：每天用几小时，追求效率与可预测性。表现力预算最低，一致性与密度要求最高。

- **界面外壳（chrome）最小化**，把空间让给内容与工作区。
- **标准外壳**：左侧导航（可折叠）+ 顶部上下文栏（标题、面包屑、主要操作）+ 主工作区 + 可选的右侧详情面板。
- **一致性压倒一切**：同样的操作在每个页面都在同一个位置、长同一个样子。
- **键盘优先**：全部可 Tab 到达；常用操作有快捷键并在界面上提示；提供命令面板（Ctrl/⌘+K）。
- **列表—详情**是最常见的模式：左列表右详情，或点击后进入详情页；保持列表的滚动位置与选中状态。
- **批量操作**：多选后出现操作栏。
- **行内编辑**优于弹窗编辑；**撤销**优于确认框。
- **状态的持久化**：记住筛选、排序、列宽、折叠状态。
- **参数**：一个无衬线家族或系统字体，13px 正文、12px 次要、行高落在 4px 网格上；控件 28px（工具栏）与 32px（表单）；圆角 4 / 6 / 8；面板之间 1px 分隔、无间隙；侧栏 228–240px、项高 32px；列表行 38px；图标 16px、1.5px 描边；所有过渡不超过 150ms；强调色只出现在主按钮、焦点环、选中、进度。样本见 `specimens/03-tool-app`。
- **多栏同时可见**：高频动作是"在列表里上下走、在右边读"，不要用页面跳转或抽屉打断它。详情区按文档排版（可编辑的标题、一行行可点的属性值、正文限 66ch），不是表单。
- **行内用列网格代替表头**：让优先级、ID、状态、头像、时间在所有行上纵向对齐成列，小规模列表就不需要列头。
- **状态只用小图标，不用彩色胶囊**——否则列表会变成彩虹。已完成、已取消的行在视觉上退后（降一级颜色、删除线）。
- **不突然换掉用户正在看的东西**：改动让一条记录离开当前视图时，用 toast 告知，详情保持不变。
- **空状态**在工具型应用里是新用户看到的第一屏，要用心做。
- 明暗主题都要支持，很多专业用户全天使用暗色。
- 个性体现在细节而非装饰：精确的间距、考究的图标、恰到好处的过渡、一个克制的强调色。

## 4. 表单、流程、引导

**用户状态**：想尽快完成。每多一个字段都在流失用户。

- **只问必要的**。能推断、能稍后再问的都删掉。
- **单列**；相关字段分组，组有标题。
- **长表单分步**：每步一个主题；显示进度（第 2 步，共 4 步）；可返回且不丢数据；最后有确认汇总。
- **一屏一个主要动作**，按钮文案说明下一步是什么（"继续填写地址"）。
- **即时而温和的校验**（失焦时），错误就近、具体、可修正。
- **合理的默认值与自动填充**。
- **成功页**：明确告知完成了什么、接下来会发生什么、可以去哪。
- **登录/注册**：居中的窄卡片（400px 左右）是合理惯例；或左侧表单、右侧品牌视觉的分栏。社交登录按钮遵循各平台的品牌规范。密码可显示/隐藏。
- **新手引导**：让用户尽快到达"第一次成功"；用真实任务引导而不是一串说明气泡；可跳过。

## 5. 内容、文档、博客

**用户状态**：来阅读。一切为可读性服务。

- **正文**：16–18px（中文 16–17px），行高 1.6–1.75（中文 1.75–1.9），行长 65ch（中文 36em 左右）。
- **段落间距**约为一行高；标题上方间距明显大于下方。
- **标题层级**清楚但不夸张，文内标题带锚点链接。
- **链接**在正文中要有下划线（不只靠颜色）。
- **代码块**：等宽字、凹陷底、语法高亮配色与主题协调、可复制、长行横向滚动。行内代码有浅底。
- **引用、提示框、表格、图片与图注**都要有专门的样式。
- **文档站**三栏：左侧目录树、中间正文、右侧本页大纲（滚动高亮）；顶部搜索；上一篇/下一篇。
- **博客列表**：标题是主角，日期与摘要次之；不必每篇都配图。
- 提供暗色主题；长文提供阅读进度指示（可选）。
- 衬线正文是一个值得考虑的选择，它立刻把"阅读"与"界面"区分开。

## 6. 电商

- 看用户需要比较的特征。集合页让同类商品有稳定的比例与信息次序；单件作品适合给原图和关键细节更大的面积。窄屏重选取景，保留全貌入口。
- 售价、规格和下一步在决策点相遇。库存、配送、退换、评论等只展示有依据的内容，数量变化即时反映金额。筛选和回退保留用户正在看的对象。
- 发售页要能走向订购。原型可生成本地草稿，并明确保存到了哪里；真实交易接入已授权的数据或服务。走完一次加购或订购，再返回详情确认状态。只看图或只打印规格适用于作品目录，与发售流程的对应关系需另行核对。

## 7. 移动端（iOS / Android / 小程序 / H5）

**通用**

- 触控目标 ≥ 44×44pt（iOS）/ 48×48dp（Android），目标间距 ≥ 8。
- 主要操作放在屏幕下半部的拇指区；顶部留给标题与次要操作。
- 3–5 个主要目的地用**底部标签栏**（图标加文字）。
- 尊重安全区（刘海、灵动岛、底部横条）：`env(safe-area-inset-*)`。
- 全高用 `100dvh`；输入框字号不小于 16px（否则 iOS Safari 聚焦时会自动放大页面）。
- 没有 hover：所有信息与操作都必须不依赖悬停。
- 底部弹层（bottom sheet）代替居中弹窗；滑动手势要有可见的替代操作。
- 列表项高度 ≥ 44–56px；整行可点。
- 内容优先，减少装饰；一屏一个任务。
- 正文 16–17px；注意弱网下的加载状态。

**iOS**：系统字体 SF Pro（中文苹方），正文 17pt；大标题导航栏、返回手势、底部标签栏；遵循 Human Interface Guidelines 的导航与模态惯例。

**Android**：Material Design 3；系统字体 Roboto（中文思源黑体/各厂商字体）；正文 14–16sp；底部导航、悬浮操作按钮（FAB）、系统返回手势；可跟随动态取色。

**微信小程序**：配色用 `python scripts/palette.py "#题材色" --export wxss` 写进 app.wxss（含暗色）。以 750rpx 为设计宽度；右上角胶囊按钮区域不可遮挡，自定义导航栏要按胶囊位置计算高度；遵循微信的交互惯例（底部 tabBar、下拉刷新）。

**同一产品跨平台**：品牌层（颜色、字体气质、图标、语气）保持一致，交互层（导航方式、控件形态、转场）跟随各平台。

## 8. Windows 桌面应用

**Python 小工具（tkinter / PySide）** 可沿用平台主题，把精力放在窗口缩放、长内容、输入焦点和反馈。已有 ttk 或 Qt 项目，直接复用它的字体、控件与主题。新建窗口需要套件时，可取 `scaffold.py --type tk` 或 `palette.py --export ttk`、`--export qss`。使用套件的 DPI 接口时，在创建 Tk 根窗口之前初始化，再应用主题。

采用 Windows 系统风格的应用，可借用 Fluent 的层级与控制习惯；跨平台工具、创作软件和已有部署沿用其实际交互。以下尺寸及主题做法按产品支持范围取用。

**字体**

- 西文 Segoe UI Variable（Windows 11）/ Segoe UI；中文 Microsoft YaHei UI（"UI"版本行距更适合界面）。
- 字号阶梯（px / 行高）：说明 12/16 · 正文 14/20 · 正文强调 14/20 半粗 · 副标题 20/28 半粗 · 标题 28/36 半粗 · 大标题 40/52 半粗。
- 正文 14px 是 Windows 的基准，不是 16px。
- 注意微软雅黑没有 Medium/Semibold（见 `typography.md` 第 6 节），中文的"半粗"会显示为粗体。

**几何与间距**

- 控件圆角 4px；浮层、对话框、卡片圆角 8px；窗口圆角由系统处理。
- 4px 网格；控件间距 8px，相关组之间 12–16px，区块之间 24px 以上；内容区边距 16–24px（宽窗口 36–56px）。
- 标准控件高度 32px；紧凑模式 24px。

**材质与层次**

- **Mica**：长期存在的窗口背景（透出一点桌面壁纸的色调）。
- **Acrylic（亚克力）**：临时浮层，如菜单、弹出面板。
- 内容区在基底之上用"层"（略亮/略暗的卡片表面加 1px 描边）区分；阴影只用于浮层和对话框。
- 强调色**跟随系统强调色**（用户在设置里选的颜色），不要硬编码品牌色覆盖一切。

**结构**

- 导航：左侧 NavigationView（可折叠为图标条，窄窗口变为汉堡菜单）或顶部导航；设置入口固定在导航底部。
- 标题栏：内容延伸到标题栏，自定义标题栏高度 32px（含搜索框等内容时 48px），保留系统的最小化/最大化/关闭按钮并保证可拖拽区域。
- 命令栏（CommandBar）放页面级操作；次要操作收进"更多"。
- 设置页用成组的卡片行（SettingsCard 样式）：左侧图标与标题说明，右侧控件。
- 对话框用 ContentDialog：标题、内容、底部一到三个按钮，主要按钮用强调色。
- 图标用 Segoe Fluent Icons（线性、1px 线宽、16/20px）。

**必须适配**

- **明暗主题与高对比度**跟随系统并实时切换。
- **高 DPI 与缩放**（100%–300%）：用与设备无关的单位，图标用矢量。
- **窗口尺寸可变**：设最小尺寸；窄窗口下导航折叠、布局重排。
- **键盘与辅助功能**：完整的 Tab 顺序、访问键、焦点矩形（Fluent 的双环焦点框）、UI 自动化属性。
- **动效**短促（约 83ms、167ms、250ms 几档），使用系统的连贯动画与页面转场。

WPF 界面可沿用项目资源字典。需要新版 Fluent 外观时先在现有控件上试主题，检查高对比、焦点与缩放。

## 9. macOS 桌面应用

- 遵循 Apple Human Interface Guidelines；字体 SF Pro（中文苹方），界面正文 13pt。
- 结构：左侧半透明侧栏 + 统一的工具栏 + 内容区；可选右侧检查器。
- 窗口控制按钮（红黄绿）在左上；工具栏与标题栏合并。
- 菜单栏是一等公民：所有功能都应能从菜单栏到达，并标注快捷键（⌘ 为主修饰键）。
- 控件偏小而精致；圆角、材质与系统版本保持一致（跟随当前系统的视觉语言）。
- 强调色跟随系统设置；支持明暗外观与自动切换。
- 设置窗口用顶部标签或侧栏分类。
- 对话框按钮顺序：主要动作在最右，取消在其左。

## 10. Electron / Tauri 等跨平台桌面

- 目标是"感觉像桌面应用"，而不是"装在窗口里的网页"：
  - 禁用文本的随意选中（界面文字 `user-select: none`，内容文字保留可选）。
  - 鼠标指针在按钮上保持默认箭头（桌面惯例），链接才用手型。
  - 去掉网页式的点击高亮与橡皮筋滚动；自定义与平台协调的滚动条。
  - 窗口可拖拽区域（`-webkit-app-region: drag`）设置正确，其上的按钮设为 `no-drag`。
  - 右键菜单用原生菜单或与平台风格一致的自绘菜单。
  - 启动时先以正确的背景色显示窗口，避免白屏闪烁。
- 使用系统字体栈让文字渲染与系统一致。
- 按平台调整：窗口控制按钮的位置、快捷键的修饰键（Ctrl 与 ⌘）、标题栏样式、菜单位置。
- 响应系统主题变化；记住窗口大小与位置。
- 密度按桌面标准（13–14px 字，28–32px 控件），不要用移动端的大尺寸。

## 11. 邮件模板

- 邮件客户端的 CSS 支持远落后于浏览器：用表格布局、内联样式；不依赖 flex/grid、自定义属性、网络字体。
- 宽度 600px 左右；单列；系统字体栈。
- 图片可能被默认屏蔽：关键信息用文字，图片设 alt，不要把整封邮件做成一张图。
- 一个明确的行动按钮（用带背景色的表格单元格实现，保证各客户端可点）。
- 暗色模式下客户端可能自动反色：避免纯白背景上的透明 logo 等会出问题的组合，并测试。
- 正文 15–16px，行高 1.5 以上，对比度充足。

## 12. 终端 TUI

- 已有单色终端沿用字符、反显、光标与状态词。项目需要彩色主题时，优先采用宿主配色，或用 `palette.py --export textual`、`--export rich` 起步；在实际终端确认所用颜色与字符都能辨认。

- 栅格单位是终端单元格。按实际渲染宽度对齐文件名与数字；汉字、组合字符和 emoji 可能占不同数量的格。使用项目已有的显示宽度函数，截断时保留用户区分相邻项所需的片段。
- 选择、输入焦点和任务状态分别可辨。当前行可有光标标记，状态可用短词；在无颜色环境里走一遍浏览与确认。支持 `NO_COLOR` 的程序在变量非空时默认省略 ANSI 颜色，沿用程序已有的显式设置优先级。[NO_COLOR 约定](https://no-color.org/)
- 缩窄终端时优先保住对象、状态、当前操作。比较相邻数值时让列留在一起；展开详情后返回原行。页脚只显示本状态可用且用户需要的按键。重绘时检查光标、中文边缘和滚动位置。

## 13. 嵌在别的软件里：浏览器扩展、编辑器与笔记插件

宿主优先：界面跟着宿主的主题走，不带自己的整套配色。

- **浏览器扩展**：弹出窗口宽 320–400px、高度不超过 600px，一屏讲清当前页面的状态和一个主操作；设置页用完整页面。注入到网页里的界面放进 Shadow DOM，样式不外泄也不被网页样式污染；字号、行高写死像素，不继承网页。跟随系统明暗（`prefers-color-scheme`）。
- **VS Code 扩展的 Webview**：只用 VS Code 提供的主题变量（`var(--vscode-editor-background)`、`--vscode-foreground`、`--vscode-button-background`、`--vscode-focusBorder` 等）和 Codicons 图标，这样用户换任何主题都对。不引入自己的强调色。
- **Obsidian 插件**：用 Obsidian 的变量（`--background-primary`、`--text-normal`、`--text-muted`、`--interactive-accent`、`--background-modifier-border`），设置页用原生 `Setting` 组件。
- **Figma 插件、Chrome DevTools 面板、Office 加载项**：同样先用宿主的设计系统（Figma 的 UI 变量、DevTools 的样式、Fluent UI），面板窄就一列，主操作贴底。

## 14. 数据应用：Streamlit、Gradio、Dash、Jupyter

- 筛选、图例、数轴和明细围绕使用者要判断的问题布局。若要比较同级系列，给它们等价的笔形和可区别的编码；需要追踪异常时再强调对应那一条。
- Streamlit、Gradio 或 Dash 可沿用现有主题；需要自定义色阶时可从 `palette.py --export streamlit`、`--export gradio` 或图表导出器开始。概览可先给摘要，检索工具可直接给筛选与记录。

- 长时间计算给出进度和预计时间（`st.status`、`gr.Progress`），失败时说清楚哪一步错了、怎么改输入。
- 自定义 CSS 只做少量覆盖，跟着框架升级容易坏。

## 15. 原生跨平台：Flutter、Jetpack Compose、SwiftUI

- 已有应用接入项目的 ColorScheme、系统动态色或原生主题。需要重定品牌时，`palette.py --export flutter`、`--export compose` 和 `--export swiftui` 可提供一组初值；在项目实际主题里复看前景与背景。
- 使用本平台已有的导航与控件习惯；自定义控件时保留有效触区、焦点、系统返回和辅助功能。

- 字号跟随系统的动态字体（Dynamic Type、sp），在最大字号下看一次换行。

## 16. 聊天机器人与协作工具里的消息卡片

Discord 嵌入卡片、Slack Block Kit、飞书 / 钉钉 / 企业微信卡片：标题一句结论，下面两到四个"字段：值"，最多一个主按钮；侧边颜色条只表达状态（成功、警告、失败），不当装饰；时间和数字带单位；长列表折叠成"查看全部"。
