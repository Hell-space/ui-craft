# 布局与间距

布局回答两个问题：**东西之间是什么关系**（间距），以及**眼睛按什么顺序走**（构图）。

## 1. 间距系统

以 4px 为基准的阶梯：

```
2  4  8  12  16  24  32  48  64  96  128
```

阶梯越往上跨度越大——小间距需要精细区分，大间距之间差 8px 没人看得出来。所有 margin、padding、gap 都从阶梯里取，不出现 15px、22px 这样的值。

三个尺度，各有职责：

| 尺度 | 取值 | 用在 |
|---|---|---|
| 微观 | 2–12 | 图标与文字之间、标签与输入框之间、同组内的行 |
| 中观 | 16–32 | 卡片内边距、组与组之间、表单字段之间 |
| 宏观 | 48–128 | 页面区块之间、首屏上下留白 |

流体间距让宏观留白随视口变化：

```css
padding-block: clamp(3rem, 2rem + 6vw, 8rem);
padding-inline: clamp(1rem, 4vw, 3rem);
```

优先用 `gap`（flex/grid）而不是给子元素加 margin——间距归容器管，增删子元素不会留下多余边距。

## 2. 间距表达关系

这是布局里最重要的一条：**距离即归属**。

- **组内紧、组间松。** 相关元素之间的距离要明显小于与无关元素的距离，至少差一倍（8 对 24，而不是 16 对 20）。
- **标题属于它下面的内容。** 标题上方的间距应大于下方（如上 32、下 12）。上下等距的标题会"漂"在两段之间。
- **标签属于它的控件。** 表单 label 到输入框 4–8px，字段到字段 20–24px。
- **容器内边距不小于内部元素间距。** 卡片里元素间隔 16px 而内边距只有 12px，内容会显得要挤出边框。
- **留白是主动的设计。** 重要的东西周围留更多空，本身就是一种强调；填满每一块空白会让所有东西一样不重要。

检验方法：把所有边框和背景色去掉，只凭间距还能看出分组吗？能，间距就做对了。

### 节奏

均匀是单调的。让疏密有变化：

- 区块之间的间距不必全相同。首屏之后可以更松，密集的数据区之间可以更紧。
- 一段紧凑的内容之后给一段开阔的，像呼吸。
- 用一个明显更大的留白来标记"换话题了"。

## 3. 分隔手段的优先级

需要区分两块内容时，按从轻到重的顺序尝试，**用最轻的那个够用的手段**：

1. **间距**——什么都不加，只拉开距离。
2. **背景明度差**——两块区域的底色差一点点（0.985 与 0.965）。
3. **分隔线**——1px、低对比。
4. **边框盒**——四周描边。
5. **阴影**——只给真正"浮起来"的东西：下拉菜单、弹窗、拖拽中的元素。

常见的过度设计是直接跳到第 4、5 级，并且两者同时用。经验法则：**先试着把线删掉**，看看是否仍然清楚。

线与边框的细节：

- 1px 就够；颜色用专门的 `--border`，对比度很低即可（装饰性分隔线不需要 3:1，控件边界才需要）。
- 列表项之间的分隔线可以不通栏——左侧缩进到与文字对齐，更精致。
- 表格优先只用横线，不要画成格子。

## 4. 对齐与栅格

**对齐创造秩序。** 页面上的每个元素都应与至少一个其他元素对齐。看不见的对齐线越少、越强，画面越整洁。

- **建立一条强左对齐线**，让标题、正文、按钮都从它开始。这比居中更有结构感，也更易读（眼睛每行回到同一位置）。
- **居中的适用范围很窄**：短标题、空状态、弹窗、仪式性的首屏。不要让整页都居中。
- **光学对齐优先于数学对齐**：
  - 图标与文字并排时，图标通常要比数学居中再下移或上移 0.5–1px 才显得齐。
  - 三角形（播放键）要向尖端方向偏移才显得居中。
  - 圆形、带圆角的元素看起来比同尺寸的方形小，需要略放大。
  - 有内边距的按钮与无内边距的文字左对齐时，按钮的文字（而非按钮边缘）应与其他文字对齐，或接受边缘对齐并保持一致。
  - 大号标题的左侧字母（T、W、引号）可以略微外凸以求视觉齐平。
- **基线对齐**：同一行里不同字号的文字用 `align-items: baseline`。

### 栅格

- 12 列栅格灵活（可分 2/3/4/6），但不必拘泥；内容决定列数。
- **不对称比等分更有张力**：5:7、4:8、1:2 的分栏比 6:6 更有主次。
- 卡片网格用自适应列：

```css
display: grid;
grid-template-columns: repeat(auto-fill, minmax(min(280px, 100%), 1fr));
gap: var(--space-6);
```

- 卡片内部元素要跨卡片对齐（标题、价格、按钮在同一水平线）时用 `subgrid`。
- 让某些元素**打破栅格**——出血到边缘的图片、跨越分栏的大标题——是制造记忆点的常用手法，但前提是其他部分严格守栅格。

### 容器宽度

| 内容 | 最大宽度 |
|---|---|
| 阅读型正文 | 65ch（中文约 36em） |
| 表单 | 400–560px |
| 一般页面内容 | 1080–1200px |
| 宽布局、dashboard | 1280–1440px，或铺满 |

超宽屏上不要让内容无限拉伸；也不要把一切都锁在窄容器里——数据表格、画布、地图应该用足空间。

## 5. 构图与视线

- **一屏一个焦点。** 先决定第一眼看哪，再安排第二眼、第三眼。焦点靠尺寸、对比、留白和位置共同确立。
- **阅读路径**：信息型页面常呈 F 形（左上起，逐行向下，越往下越只扫左侧），营销页常呈 Z 形。把关键信息放在路径上。
- **视觉重量**：大、深、饱和、有纹理、位置偏上偏左的元素更重。左右两栏、上下区块的重量要么平衡，要么有意失衡。
- **尺度对比**：一个很大的元素旁边放很小的元素，比一堆中等大小的元素有戏剧性得多。具体的量：hero 标题 `clamp(40px, 6vw, 72–88px)`、`max-width: 13–18ch`；主数字是旁边说明文字的 3–4 倍（76px 的倒计时配 12px 的标签）；区块标题是正文的 2–2.5 倍。低于 2 倍的对比不算"大"。
- **结论在上，证据在下**：最重要的结论（一个数字、一段摘要）直接排在纸面上，不进卡片；从图表开始才用容器。
- **比例分栏，一高一低**：标题列窄、说明列宽（4:7、5:6），底对齐，让标题与说明错落而不是居中对称。全页每个栏目重复同一个"编号 + 标题 + 一句说明"的骨架，像书的版式。
- **图可以出格，文字不出格**：图片、引语、产品片段可以外扩到比正文更宽的轨道，图注再缩回与正文对齐。用命名网格线（`full / wide / text`）控制。
- **重复与变化**：重复建立规律（同类卡片同样结构），在规律中打破一次制造重点（其中一张卡片跨两列、换底色）。
- **首屏**：让用户不滚动就知道这是什么、能做什么；同时露出一点下方内容，暗示可以继续滚。

## 6. 密度

密度是产品性格的一部分，也直接影响效率。

| 档位 | 行高/控件高 | 内边距 | 适用 |
|---|---|---|---|
| 紧凑 | 28–32px | 8–12px | 专业工具、数据表、IDE、交易终端——用户长时间使用、需要同屏看到更多 |
| 默认 | 36–40px | 12–16px | 多数 Web 应用 |
| 舒适 | 44–52px | 16–24px | 触屏、面向大众的产品、营销页 |

- 专业用户要的是密度而不是留白；把后台做得像落地页一样疏朗是一种失职。
- 高密度不等于拥挤：靠严格的对齐、一致的行高、克制的分隔线来保持清晰。
- 同一产品内可以分区采用不同密度（导航舒适、数据区紧凑），但同一区域内要一致。

## 7. 响应式

- **移动优先**：先让窄屏成立，再为宽屏增强。窄屏迫使你排出真正的优先级。
- **断点跟着内容走**：把窗口慢慢拉宽，在布局开始显得别扭的地方加断点，而不是套用固定的设备宽度。
- **组件用 container queries**：同一个卡片放在侧栏和主区应有不同形态，这取决于它的容器宽度而非视口。

```css
.card-wrap { container-type: inline-size; }
@container (min-width: 480px) {
  .card { grid-template-columns: 160px 1fr; }
}
```

- **不只是堆叠**：窄屏不是把多栏简单摞成一栏。重新考虑顺序（最重要的上移）、取舍（次要信息折叠或移除）、形态（表格变卡片列表、侧栏变底部标签或抽屉）。
- **触屏。** 频繁点按的独立按钮可从 44 CSS px 左右的命中高度试起，小图标的可点范围可以更大。WCAG 2.2 AA 的通用最低目标为 24×24 CSS px，另有足够间距、行内文本、等效控件等例外。用单手可达性和相邻误触实际判断布局。[WCAG 指针目标尺寸](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)
- **安全区**：`padding: env(safe-area-inset-*)`；全高布局用 `100dvh` 而非 `100vh`（避开移动浏览器地址栏的伸缩）。
- 按 WCAG 重排检查以垂直阅读为主的网页时，可使用 320 CSS px 宽；地图、数据表等有二维关系的部分可局部滚动。页面其他内容仍应可读可操作。[WCAG 重排](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)

- **横向溢出是最常见的窄屏缺陷**：长单词、长 URL、固定宽度的元素、没有 `min-width: 0` 的 flex/grid 子项、宽表格。表格放进可横向滚动的容器，长文本 `overflow-wrap: anywhere`。
- **图片**：设 `aspect-ratio` 预留空间防止布局跳动；`max-width: 100%`；`object-fit: cover` 配合焦点位置。

## 8. 常用骨架

### 应用外壳：侧栏 + 主区

```css
.app {
  display: grid;
  grid-template-columns: 248px minmax(0, 1fr);
  min-height: 100dvh;
}
.sidebar { position: sticky; top: 0; height: 100dvh; overflow-y: auto; }
.main    { min-width: 0; }            /* 允许内部内容收缩，防止撑破 */
@media (max-width: 860px) {
  .app { grid-template-columns: 1fr; }
  .sidebar { display: none; }         /* 改为抽屉或底部导航 */
}
```

### 内容页：居中容器 + 可出血的全宽区

```css
.page {
  --gutter: clamp(1rem, 4vw, 3rem);
  display: grid;
  grid-template-columns:
    [full-start] minmax(var(--gutter), 1fr)
    [content-start] minmax(0, 72rem) [content-end]
    minmax(var(--gutter), 1fr) [full-end];
}
.page > *        { grid-column: content; }
.page > .bleed   { grid-column: full; }
```

### 不对称分栏

```css
.split {
  display: grid;
  grid-template-columns: minmax(0, 5fr) minmax(0, 7fr);
  gap: clamp(2rem, 5vw, 5rem);
  align-items: start;
}
@media (max-width: 760px) { .split { grid-template-columns: 1fr; } }
```

### Bento（大小不一的格子）

```css
.bento {
  display: grid;
  grid-template-columns: repeat(6, 1fr);
  grid-auto-rows: minmax(160px, auto);
  gap: var(--space-4);
}
.bento > .feature { grid-column: span 4; grid-row: span 2; }
.bento > .small   { grid-column: span 2; }
```
Bento 成立的条件是格子大小**反映内容的重要性**；随意分配大小只是装饰。

### 吸顶导航

```css
.header {
  position: sticky; top: 0; z-index: var(--z-sticky);
  border-bottom: 1px solid transparent;
  transition: border-color 200ms ease, background-color 200ms ease;
}
/* 滚动超过 8px 才出现底线和模糊——首屏不多一条无意义的线 */
.header.scrolled {
  background: color-mix(in srgb, var(--bg) 80%, transparent);
  backdrop-filter: blur(12px) saturate(1.4);
  border-bottom-color: var(--border);
}
html { scroll-padding-top: 5rem; scrollbar-gutter: stable; }
```
```js
addEventListener('scroll', () =>
  document.querySelector('.header').classList.toggle('scrolled', scrollY > 8), { passive: true });
```

### 保住对齐线的负外边距

可点的值、可选的列表项：用负 margin 抵消自身内边距，文字与上下的标签严格左对齐，hover 或选中的底色向外扩，而不是把文字推开。

```css
.item { padding: 6px 14px; margin-inline: -14px; border-radius: 10px; }
.item:hover { background: var(--hover-overlay); }
```

### 用 HTML/CSS 搭一个可信的产品片段当主视觉

没有截图和摄影时，这是落地页里最影响成品水准的一件事：

- 一个窗口框：圆角 12px、1px 边框、`--shadow-2`，顶部 36px 的标题栏；
- 里面放真实感的界面（侧栏、列表、详情），文字用真实内容，字号比真实界面小一档（12–13px）；
- 片段宽于文字列（文字 640–820px，片段 1080–1200px），可以向下溢出首屏，或用 `mask-image: linear-gradient(to bottom, #000 70%, transparent)` 淡出；
- 片段里的数据与页面其他地方讲同一个故事（同一个项目、同一条引文、同一个编号）。

### 层叠顺序

给 z-index 一个阶梯并只用它：基础 0、吸附 100、下拉 200、遮罩 300、弹窗 400、通知 500、提示 600。出现 `z-index: 9999` 说明层级已经失控。

## 9. 常见问题与修正

| 症状 | 原因 | 修正 |
|---|---|---|
| "乱" | 对齐线太多；间距值太杂；分隔手段过重 | 收敛到一两条对齐线；所有间距回到阶梯；删掉多余的线和框 |
| "挤" | 内边距小于内部间距；行高不足；没有组间留白 | 加大容器内边距和组间距，而不是均匀放大所有间距 |
| "空、散" | 间距处处一样大，看不出分组；内容太少却铺太开 | 收紧组内间距；缩小容器或增大字号与元素尺度 |
| "平、没重点" | 所有元素尺寸与重量相近 | 确立一个焦点并放大；削弱其余 |
| "像模板" | 全居中、等分三列、均匀间距 | 左对齐、不对称分栏、疏密变化、让某个元素打破栅格 |
| 标题"漂着" | 上下间距相等 | 上大下小 |
| 窄屏横向滚动 | 固定宽度、长字符串、flex 子项未设 `min-width: 0` | 见第 7 节 |
| 卡片参差不齐 | 内容长度不同导致内部元素错位 | `subgrid`，或让按钮 `margin-top: auto` 贴底 |
