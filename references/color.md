# 色彩

色彩在界面里有三份工作：建立**氛围**（中性色的色温）、指示**可交互与重要**（强调色）、传达**状态**（语义色）。三份工作各用各的颜色，互不越界，画面就干净。

## 1. 为什么用 OKLCH

`oklch(L C H)`：L 明度（0–1），C 彩度（0 约到 0.37），H 色相（0–360）。

在 OKLCH 中可以分别调亮暗、彩度和色相。同一个 L 方便预测一组色阶的关系。不同色相的最终 sRGB 相对亮度、透明度合成与周围色面仍会影响文字和细轮廓，制作后在实际背景取样。

常用色相参考：红 25 · 橙 50 · 琥珀 75 · 黄 95 · 黄绿 125 · 绿 150 · 青绿 180 · 青 210 · 蓝 250 · 靛 275 · 紫 300 · 品红 330 · 玫红 0。

注意：高彩度颜色可能超出 sRGB 色域（尤其是 L 很高或很低时）。浏览器会自动映射，但结果可能与预期有偏差——亮色和暗色两端的 C 要收着用。

## 2. 构建调色板的五个步骤

**第一步，确定强调的来源。** 品牌、宿主、已约定的数据编码、作品材料和环境照明都可以给出颜色。若设备只有单色显示，先试反显、行标与笔形。茶品牌样本从岩、茶汤和焙火取色，交通图则需让交叉线路在同一底图上可辨。

给每一种强调安排可识别的职责。单主动作页面适合集中用色。多线路交通图、节庆对战和对照型工具可以同时使用几种饱和色。让每种角色同时有形状、位置或线型的线索。在交汇点、选中行、低血而且正在攻击的画面复核用法。

**第二步：选大面积底色。** 把候选颜色铺到它实际占用的区域，再放上真实文字、材料边缘或单位。安静工具可以使用近白、冷灰或暖纸色；暗场的深色随环境光走；品牌本身可以占据整屏。八个界面样本偏暖。换题材时，按相邻颜色、目标视距、媒介和状态重新判断。半透明面要在它实际覆盖的几种背景上看。需要主题时再做中间色阶。

**需要明暗和状态变体时，再派生色阶。** 按平台支持的默认、悬停、按下、选中、键盘焦点和危险态取用。深字配亮底也可以成立。在实际合成的背景上量对比，用符号、文案、轮廓或线型辅助表达关键差别。

多人维护的主题可把值映射成文字、底层、焦点等角色。项目已有令牌和原生主题时优先对接，小型静态作品按画面所需颜色直接落稿。

### 检查大面积偏色

将主图、文字、选中态和临近背景在最终尺寸并排看。自由定色时，从接近原明度的中性底开始，局部比较冷暖或明暗，决定哪些材料和动作需要拉开。暖纸、单色、雾景和高饱和场面都可以成立，只要能读出项目需要的关系。

本技能禁用墨绿色，包含偏松针、瓶绿的深色和明显发绿的近黑。先查共用主题和素材源，再查暗色模式、描边、阴影、渐变的深端、透明叠色、成功和选中态。用真实合成图核对，色值搜索会漏掉混色、纹理和 Canvas。成功等含义可以由勾形、文字与位置表达。确需局部明亮草绿或浅薄荷时，检视同一对象的背光、按下态和暗色衍生值。创作时从其他颜色选暗部。可用 audit.py 定位明确写出的不透明禁色，再看焦点环、时间轴、导出图标和着色器实际叠出的颜色。旧作取样中的禁色只供核对来源。

## 3. 角色映射

| 角色 | 浅色主题（L） | 暗色主题（L） | 用途 |
|---|---|---|---|
| `--bg` | 0.974 | 0.17 | 页面底色（暖纸灰，不是纯白） |
| `--surface` | 0.995 | 0.205 | 卡片、面板、工作区 |
| `--surface-raised` | 1.0 | 0.24 | 弹出层、菜单 |
| `--surface-sunken` | 0.952 | 0.15 | 凹陷区、表头、代码块、禁用底 |
| `--border` | 0.905 | 白 8% | 分隔线、卡片描边 |
| `--border-strong` | 0.83 | 白 14% | 输入框、次按钮；卡片 hover 的落点 |
| `--border-control` | 0.64 | 0.54 | 需严格满足 3:1 时的控件边界 |
| `--text` | 0.235 | 0.935 | 主文字 |
| `--text-muted` | 0.435 | 0.75 | 次要文字 |
| `--text-subtle` | 0.53 | 0.64 | 辅助文字、占位符（仍过 4.5:1） |
| `--text-faint` | 0.70 | 0.48 | 坐标刻度、分隔符——不读也行的东西 |
| `--accent` | 0.47–0.53 | 0.68–0.74 | 主操作、选中、焦点 |
| `--accent-fg` | 0.985 | 0.17 | 强调色之上的文字（暗色下是深字） |
| `--accent-subtle` | 0.945 | 0.285 | 强调色的浅底 |

`assets/tokens.css` 实现了这张表（工具语域）；`assets/tokens-paper.css` 是纸墨语域的 hex 版本。

**关于第三级文字的取舍**：Opus 5.5 的样本里，辅墨在 L 0.55–0.62 之间，一半过 4.5:1、一半只有约 3.5:1。它的理由是："三级都过 4.5 的话，第二、三级的明度差只剩 0.08，层级被压扁，于是又开始用字号去区分，界面变吵。"它自己也说明这是偏好，严格的 WCAG 项目不适用。本 skill 的处理是拆成两级：`--text-subtle` 取它范围里较深的一端并过 4.5:1，承载信息；`--text-faint` 明确只给非必要的东西。

**面积与时间一起算。** 在工作台截普通、选中、失败三帧；在游戏截巡航、敌方预警、命中和结果。把画面缩小，看最亮或最艳的一块如何换手。品牌海报可让识别色占满，战斗警示需要在危险发生时夺回注意。有两个同等重要的比较对象时，为它们留出同等权重。

让品牌识别、可操作状态与数据编码各自有稳定用法。若品牌规范要求精确色值，保留它用于标识、图形或色面，另设实际文字和按钮所需的前景色。项目里使用同一色相不等于要给所有用途同一个亮度。

## 4. 在实际背景上量对比

普通文字以 4.5∶1 为 AA 最低对比，大字以 3∶1 为最低对比。常用换算是常规文字 24 CSS px，或粗体约 18.67 CSS px。标志字、非活动控件等有适用例外；实际阅读用的次要信息仍要清晰。半透明层取合成后的前景和背景，渐变及图片取文字覆盖的最差位置。可用 `scripts/contrast.py` 对具体色对复核。[WCAG 文字对比](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)

用户辨认控件、状态或图形所必需的视觉信息，通常应与相邻颜色达到 3∶1。装饰线与已由其他视觉信息充分标识的边缘不需要一概加深。焦点还应在实际背景上清楚可见。[WCAG 非文字对比](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)

当色相负责传递业务含义时，补一种可见线索。例如错误跟随说明、折线直接标名、当前行以位置和选中标志共同标识。灰阶校样有助于发现歧义，最终还要在实际颜色与交互状态下确认。[WCAG 颜色的使用](https://www.w3.org/WAI/WCAG22/Understanding/use-of-color.html)

## 5. 暗色模式

暗色不是把浅色反过来。逐项重新设计：

**底色不用纯黑。** `#000` 上的亮色文字会产生光晕感，也无法再表达"更低"的层级。用 L≈0.14–0.18 的深色并带一点色相。（例外：有意为 OLED 设计的纯黑界面。）

**层级靠明度，不靠阴影。** 暗底上阴影几乎不可见。越靠近用户的表面越亮：底 0.16 → 卡片 0.20 → 弹出层 0.235。可再加一条顶部的 1px 内高光（`inset 0 1px 0 oklch(1 0 0 / 0.06)`）模拟受光边。

**边框用半透明白或略亮的中性色。** `oklch(1 0 0 / 0.08)` 这类边框在各层表面上都协调。

**文字不用纯白。** 主文字 L≈0.93–0.95，次要 0.72，辅助 0.63。纯白在深底上过亮，长时间阅读疲劳。

**强调色提亮、降彩。** L 从 0.47–0.56 提到 0.68–0.76，C 乘 0.8；主按钮改成"浅底深字"（文字 `oklch(0.17 0.03 H)`），而不是把浅色版的深色原样搬过来——深蓝在深底上对比不够。提得太高（>0.76）在暗底上会发白发光。

**语义色同理**：浅底色改为深而略带色相的底（L≈0.275–0.295，C≈0.04–0.06），文字色提亮到 L≈0.72–0.82。

**暗色跟着语域走。** 纸墨的暗色是暖炭灰（`#171512` 一带，H 60–80），墨色仍然偏暖（`#ECE5D8`）；工具的暗色可以冷一点（H 260–270）。

**黄色系的特例**：黄做文字必须更暗才过对比度，做填充又必须更亮才像黄色——拆成"文字用"（L 0.52–0.56）和"填充用"（L 0.78–0.88，配深色文字）两个值。

**图像与插画**：必要时略降亮度与对比（`filter: brightness(0.9)`），避免在暗界面里成为刺眼的亮块。

**实现**：

```css
:root { color-scheme: light dark; }
:root[data-theme="light"] { color-scheme: light; }
:root[data-theme="dark"]  { color-scheme: dark; }

/* light-dark() 跟随 color-scheme，一处定义两套值 */
:root { --bg: light-dark(oklch(0.985 0.004 75), oklch(0.16 0.006 75)); }
```

默认跟随系统，提供手动切换并记住选择。切换时给颜色属性一个 150–200ms 的过渡会更顺滑，但不要 `transition: all`。

## 6. 状态色与派生色

不要为每个状态手写一个新颜色，从基色派生：

```css
.btn-primary {
  background: var(--accent);
}
.btn-primary:hover {
  /* 浅色主题向深走，暗色主题向亮走；混入文字色可同时适配两者 */
  background: color-mix(in oklch, var(--accent) 88%, var(--text));
}
.btn-primary:active {
  background: color-mix(in oklch, var(--accent) 78%, var(--text));
}

/* 中性的 hover 底：在当前表面上叠一层极淡的文字色 */
.row:hover {
  background: color-mix(in srgb, var(--text) 4%, transparent);
}
```

**与 `transparent` 混色时用 `in srgb`（或 `in oklab`），不要用 `in oklch`。** `color-mix(in oklch, 近中性色 84%, transparent)` 在 Chromium 里会把低彩度颜色的色相判成 `none`，渲染时按 0° 处理：暖米色的半透明导航会泛粉，暖墨的 hover 叠层会偏红。这套审美里最常用的颜色（纸、墨，彩度 0.005–0.02）恰好全部中招，而彩度高的强调色不受影响，所以很难从代码里看出来。两个不透明颜色之间的混色用 `in oklch` 没有问题。

- **Hover**：明度变化 0.03–0.05，足以察觉但不跳。
- **Active/pressed**：再进一步，变化量约为 hover 的两倍。
- **Selected**：强调色浅底 + 强调色文字或左侧/底部指示条；与 hover 必须可区分。
- **Disabled**：降低对比（文字用 `--text-disabled`，底用 `--surface-sunken`），不要只靠 `opacity: 0.5`——半透明叠在不同背景上结果不可控。
- **Focus**：2px 强调色描边加 2px 间隙，与任何背景都要有 3:1 对比。

## 7. 渐变、质感与氛围

纯平的单色背景有时显得贫乏，但"加个渐变"不是唯一答案。

**渐变的用法**

- 色相跨度小：同色相内的明度变化，或相邻色相（差 30–60°）。大跨度的彩虹渐变是廉价感来源。
- 用 OKLCH 插值避免中段发灰：`linear-gradient(in oklch, …)`。
- 面积大、对比低：作为氛围，而不是作为主体。
- 径向渐变模拟光源（左上或顶部一团很淡的亮），比线性渐变更自然。
- 大面积渐变容易出现色带，叠一层极淡的噪点可以消除。

**渐变之外的氛围手段**

- 细噪点/颗粒纹理（SVG `feTurbulence` 或小尺寸 PNG 平铺，透明度 2–5%）——给平面以纸张或胶片的质感。
- 细网格、点阵、等高线等几何底纹，颜色只比背景深或浅一点点。
- 一张真实照片或插画，胜过任何抽象渐变。
- 大面积的纯色块（强调色或其深色调）作为区段背景，比渐变更有主见。
- 分区用背景色的微小明度差（0.985 与 0.965），而不是线。

## 8. 色彩策略与示例调色板

### 策略

| 策略 | 做法 | 气质 |
|---|---|---|
| 单色加一点 | 带色温的中性色 + 一个强调色 | 最稳妥，适合绝大多数产品界面 |
| 同色系 | 强调色与中性色同色相，仅明度彩度不同 | 沉静、统一、高级 |
| 互补点缀 | 中性色偏向一个色相，强调色取其对面 | 有张力、醒目 |
| 双色 | 两个地位相当的颜色大面积并置 | 大胆、海报感，适合营销与品牌页 |
| 黑白加一色 | 近黑、近白、一个高彩度色 | 锋利、当代 |

## 9. 常见问题与修正

| 症状 | 原因 | 修正 |
|---|---|---|
| 一片混浊 | 大背景、对象和纹理占了相似明度，或几个信号复用同一种高光 | 暂时隐藏材质，分别调整大底、关键轮廓及纹理出现的位置，最后加回局部质感 |
| 画面灰弱 | 突出区域太小、材质被同一种雾色覆盖，或选中态与默认态相似 | 找到本状态的主角，扩大一个有辨识度的受光面，或用稳定深边和邻接底色拉开层次 |
| 画面刺眼 | 高亮覆盖了长时间停留的工作区，或多处动效在同一拍达峰 | 优先降持续亮度与大面积运动，保留关键信号的瞬时对比 |
| 画面看起来像通用皮肤 | 同一条描边、发光、渐变覆盖了用途和材料完全不同的对象 | 为玻璃、湿石、金属和操作焦点分别指定边缘的宽度与位置，在原视距比较 |
| 不知道哪里能点 | 强调色被用在不可交互的装饰上 | 强调色只留给交互与关键信息 |
| 暗色模式"发灰、发闷" | 直接反色；强调色没有提亮；对比不足 | 按第 5 节逐项重做 |
| 暗色模式"刺眼" | 纯白文字；高彩度颜色大面积出现 | 文字降到 0.94；降彩度 |
| 层次不清 | 表面之间明度差太小，又没有边框 | 表面间 L 差至少 0.02–0.03，或加 1px 边框 |
