# 游戏 UI

先选一段玩家会亲手完成的操作，找出做决定时要看的对象。打开实际游戏，留住这一刻的世界、镜头和输入，把版式、图形和反馈做在这段操作里。网页上的阅读层级、比较方法与状态反馈都可借用，取舍随玩家此刻能分给界面的注意力而变。[前端实作与修稿](frontend-workmanship.md) · [游戏画面与角色](opus-game-art.md)

## 先做一段能玩的界面

| 玩家在做什么 | 值得借的前端工艺 | 放回游戏怎样验 |
|---|---|---|
| 航行、追逐、瞄准或打节拍 | 把读者最想知道的变化放在正在看的对象旁。注意数字与单位的字重，压低长期不变的次要信息 | 在原镜头实际输入。跟着目标看，辨认刚才作用在哪儿、结果是什么、下一次输入看哪儿。保持世界的轮廓和下一拍的通道 |
| 在装备、地图、技能或商店中比较 | 焦点、预览、实装分别有归属。有效的共同尺度、稳定的字段和单位能省掉反复切页背数字 | 从 A 预览 B，再看 C、取消、重开和确认。核对比较基准、图形、资源、返回位置，以及回到世界后的第一次操作 |
| 阅读对话、章节或战后结算 | 用画面占比、字号与揭晓次序决定先看人物、后果还是奖励。沿用作品自己的字面、图像与节奏 | 连续读相邻两句或两页，检查说话者、视线与选择焦点。让跳过直接抵达完整终态。同一次按键只处理当前这层 |

**让这一作的材料承担一项工作。** 海图的等深线解释地势，测深字给出该地点的读数。鼓点轨上的括号标出有效时间窗。对话中的口型、停顿或视线可以先给出角色的反应。决定哪一处值得最大、最亮或最安静，再安排相邻文字和面板。连续看两个状态，玩家应能在相同的位置认回同一物件。宿主插件可沿用原槽位、字体与焦点，只补宿主当下缺的差值或线索。[宿主内的界面](game-mods.md)

**把预览放到能判断后果的地方。** 对象、方向和世界距离决定选择，而且玩家有时间观察时，在原相机下画出候选范围，保留已装或已选的参照。留意正压在界线上的对象，玩家应能看清这一侧算不算命中。预览可以显示可用次数或预计消耗，确认后才扣资源。几件物品需要精确对照时，给它们共用的字段、稳定的行列和单位。实时追逐可把提示并进瞄准或来势，叙事悬念留给角色反应。宿主插件优先在原槽位或提示框里比较。确认实际的比较关系再标差值。[前端比较方法](frontend-workmanship.md)

**让图形和判定使用同一份数据。** 航向、射程、冷却、判定时间、剩余能量随输入立即更新。取一组刚好在边界内外的输入，把运行结果和屏幕上的边线对上。节奏游戏即使持续运行，也需要稳定的时间基线。上一个结果可以在击打处留下短暂轮廓，文字放在邻近空位，让下一拍能看见、能击中。实时生命或储能直接显示真值；战后总分有时间读时才可渐变揭晓。[动作与结果](action-feedback.md)

### 从旧画面到可核对的改稿

《潮标》早期的探头仓居中遮住船，玩家要从小图想象探头能扫到哪站。旧版已把命中的站点由空框变成打勾的实心点，船正好停在站上时船标又遮住了它，27 m 的结果远在左下。新版在实际船位与朝向上叠放两个范围，把边线附近的站位按实际判定标出并列入清单。面板内对齐半径、开角、耗能和间隔。测深后把读数系在实际采样点，船移开后仍能找回这一笔。亮、暗海图用相同的空间关系。[Godot 原生样例](../examples/sonar-station/project.godot)

《翻花鼓》旧版在 1120 像素宽下，提前 180 毫秒击鼓已经可以得分，鼓点中心却还在亮框外。改后用原判定窗口和轨道速度画边界，在击打处留下命中或落空的形状。它与《潮标》共享的是让形状可解释、让结果回到发生处；谱面继续行进，演出的色面、鼓和节庆节奏则由作品决定。[可操作的节奏样例](../examples/festival-beat.html)

### 看图和操作各能回答什么

用相同的镜头、存档、条件与输入取常态、预览、结果三刻。在目标尺寸先看一眼，指出作用的对象与留下的结果。遇到不清楚的地方可以遮掉一块底板或一个标记，检查哪条信息随它消失。亮暗背景、界面比例、长译文或局部遮挡会改变这次判断时，再换那些条件复看。截图能证明取景与遮挡，按键归属、计时时机、返回和实际数值要经引擎或浏览器事件重放。眼动轨迹、实体手柄手感和设备延迟需要相应的实测。

原生样例用方向键或左摇杆移动，空格或手柄 A 测深，E 或 Y 打开探头仓，Esc 或 B 返回，M 或 X 切换海图明暗。在技能目录用 `godot --path examples/sonar-station` 运行。用 `godot --headless --path examples/sonar-station --script res://verify.gd` 重放输入。浏览器样例《守夜》的手柄图标只演示提示样式。[运行与实拍记录](../evals/game-ui-studio.md)

## 玩家此刻能怎样读

| 条件 | 会改变的设计决定 |
|---|---|
| 玩家持续看世界，或正在停下来比较 | 航行只在余光处保留资源，把测量结果放在位置上。暂停整备可以把主视野交给物件与差异。策略地图与谱面本身就是主要界面 |
| 背景变化、机位会动 | 必要标记可用局部底板、描边、形状或世界里的承托物。实测最易混淆的底色，连同相邻物体一起看 |
| 键鼠、方向输入、触控或多人同屏 | 由宿主的实际输入决定焦点、手势和退出方式。每个可操作区给对应玩家与视口，鼠标悬停之外保留任务所需的信息 |
| 高频操作或表演片段 | 反复操作要能立刻从反馈回到下一次输入。剧情或结算可以让画面停留，沿用跳过、重看和减少动态效果的项目约定 |

## 2. 先定 UI 住在哪：四种位置

| 位置 | 是什么 | 例子 | 何时用 |
|---|---|---|---|
| 叙事内（diegetic） | 角色在世界里也看得见 | 枪身上的弹药计数、手腕上的表、车里的仪表盘 | 沉浸优先、信息量少 |
| 空间中（spatial） | 在 3D 空间里但角色看不见 | 地面上的移动范围、敌人头顶的血条、路径指引 | 信息需要附着在物体上 |
| 世界风格的叠层（meta） | 不在空间里，但带世界的质感 | 受伤时屏幕边缘的血迹、冻结时的霜 | 表达状态而非数值 |
| 叠加层（non-diegetic） | 纯界面 | 血条、小地图、技能栏、菜单 | 精确信息、频繁读取 |

选能稳定回答当前决策的位置。驾驶舱里的表盘有利于沉浸，紧急避障时稳定的屏幕边缘提示可能更容易读。看实际游戏视野和读取频率再决定。

## 3. 立场与世界观：UI 的材质来自游戏世界

先取玩家会亲自辨认或操纵的东西。同一艘船，夜间进港要让人从水面找到航标，可以把最亮的一小块留给远处船灯。进舱校表时，玩家要看出一个旋钮带动哪根表针，就把旋钮、刻度和指针排在一起。两处可以沿用同样的字面和材料，画面的重心随玩法移动。

场景中的物件可以直接承担操作。按实际镜头和屏幕大小看，标记是否落在对应物件上，玩家动手前能否看懂当下允许知道的事。几个物件共用一个操作符号时，轮廓、位置或选中反馈可以说明所指。需要名称才能分清时，把已有名称放在作决定的位置。重复索引若承担键盘访问或快速回查，就保留它的用途。寻找暗门或辨认未知物本身就是玩法时，可以保留未知，检查尝试后能否读懂场景的回应。

## 4. HUD

先标出玩家此刻要持续跟踪的视域。以下位置可用于需要从边缘读取状态的 HUD，策略地图、驾驶舱或判定谱线可把主界面放在中央。

- 自身状态可以共用一块稳定区域，让生命、能量与即将执行的动作容易相互核对。
- 时间、目标和小地图依其读取频率与世界位置安排。
- 快捷栏靠近对应输入区域，给需要连续跟踪的路线或鼓点留出空间。
- 任务追踪、聊天与背包快捷可按宿主约定放置。

当前状态需要离开作用点后继续查阅时，再让常驻区域承接摘要或日志。

**三层信息**：

| 层 | 内容 | 显示方式 |
|---|---|---|
| 常驻 | 生命、核心资源、技能 | 永远在，但低调；满血时可以淡出 |
| 情境 | 目标的血条、交互提示、弹药不足 | 只在相关时出现 |
| 瞬时 | 伤害数字、获得物品、成就 | 出现、强调、消失，1–2 秒 |

**在任何画面上可读**：

- 文字与图标加**描边 + 投影**（`text-shadow: 0 1px 0 #000, 0 0 6px rgb(0 0 0 / .6)`）或**底板**（半透明深色，`rgb(0 0 0 / .35–.55)` + `backdrop-filter: blur(6px)`）。只靠颜色的文字在雪地或爆炸里会消失。底板是兜底：每块信息都套同一种底板，四角就成了一组网页卡片。能用世界里的图题栏、刻度边、字重或位置分开层级时，只给真正压在花背景上的那几处加底。
- 在最亮、最暗、最花三种场景截图下检查，而不是在纯色背景上。
- 关键数值用填充条加数字；条有清晰的外框和空槽。

**血条和伤害反馈。** 当前生命随游戏状态立即更新，空槽和分段在明暗场景都可见。需要传递刚才损失了多少时，可给旧值一次短促追随，下一次受击或治疗从真实当前值接续。低生命常驻提示用空槽、断口或形状，受击来向另放到边缘；长时间低血时，给出安静且持续可读的表示。脉冲和震屏服从游戏的减弱动效选项。分段尺度取决于玩家能估算的单位。

**视距与宽高比。** 在宿主支持的窗口、掌机或电视观看距离下读实际数字和最长名称。相机与 UI 可以采用不同的缩放方式。若小窗口把正文压得难读，先让说明换行、调整字号或收起次要内容，再看准星与目标是否仍可见。端口、安全区、文字缩放与竖屏支持范围沿用该游戏的约定。

## 5. 菜单与全屏界面

- **主菜单。** 保留一个能把玩家带回世界的焦点，例如仍在工作的炉火、港口剪影或角色的背负装备。标题与菜单避开轮廓，焦点可见，静止和移动时都能直接继续游戏。
- **暂停与设置。** 从菜单返回时，原地点和操作对象仍可辨认。可用局部实底、压暗或静态背景，确保复杂材质不会穿进正文。分类和肩键操作依照实际输入映射。
- **背包 / 格子**：先用缩小后的外轮廓区别物件类型，焦点、已装备和品质各有单独的线索。快速浏览可在原提示框对固定基准显示差值；停下来跨件比较时再使用固定详情列。
- **技能树**：节点 + 连线；已解锁、可解锁、锁定三种状态用形状和亮度区分；连线在解锁时被"点亮"（SVG 描绘动画）。
- **商店**：价格用游戏货币图标 + 等宽数字；买不起的灰掉并显示差额；购买确认是一次满足感时刻（金币飞向余额、余额数字滚动）。
- **结算与奖励。** 首先让人理解这一局发生了什么。节庆合作任务可先出现共同完成的伙伴，再出现奖励；重复刷取的材料直接读数量更合适。可跳到完整终态，跳过的按键不能顺手领取或关闭下一层。
- **对话框**：说话人名字与头像在一侧；文字逐字出现（可一键补全）；选项与"推进"提示明确。

## 6. 输入：手柄、键鼠、触屏

双人界面还要标明输入与视口归谁。整备中的焦点、相机预览和压暗只作用于该玩家可用的区域。同屏合作时留出队友当前必须看的世界征兆；独立视角则核对遮罩所属的画布。用两路输入重放，一人打开、预览、退出，另一人一直操帆或瞄准；同时检查关闭键的释放、下次独立按下及队友的持续操作。

- 有菜单时给方向输入一个清楚的焦点，按当前场景选择描边、明度、位置或标记。游玩时把控制权交回角色或世界。焦点、悬停、已装备与冷却要有可分别辨认的状态。
- 焦点移动符合空间直觉：方向键按视觉位置走，网格边缘可环绕或停住（选一种，全游戏一致）。
- 按键提示图标随**当前输入设备**切换（手柄 A/B ↔ 键盘 Enter/Esc ↔ 触屏不显示），切换要即时。
- 确认与返回位置全游戏一致；返回永远能退一层。
- 标签页可映射到肩键，数值可映射到方向键，优先沿用游戏已有的分工。危险操作按代价选择撤销、确认或可取消的按住操作，给难以持续按压的玩家等价入口。提示跟随当前焦点与真实映射。
- 触屏需要连续操作时，在目标握姿和分辨率试按主动作、相邻按钮与同时按住的组合。虚拟摇杆、按下态与布局调整取决于原有操作约定。
- 键鼠沿用宿主快捷键。区分仅把指针移过一项、用方向键预览一项和已经装备一项，切换输入设备后仍能辨认三者。

网页游戏里用 `tabindex`、方向键监听与 `:focus-visible` 实现焦点导航（样例里有）；引擎里用各自的导航系统（第 10 节）。

**一次可重做的输入检查。** 打开探头仓，移动焦点而保留原装备，返回并确认世界坐标和装备都没变化。再打开，确认另一枚探头并返回，确认这一按只完成装备，测深次数与储能都没变。换回键鼠，用点击完成同一动作。摇杆微小偏移不应反复抢走提示，按住打开键也不能连续开关。关菜单时仍按着方向，先等摇杆回中或松开方向键再接管移动。联机项目按游戏现有规则处理世界时钟；示例是本地单人，探头仓打开期间暂停测深与储能。

## 7. 手感：游戏里的动效

根据频率和玩家能分给界面的注意选择反馈。射击瞄准、回合规划和结算领奖需要不同的幅度。下表是候选手法，按事件含义选用，原生引擎用其动画与输入系统实现。

| 手法 | 做法 | 用于 |
|---|---|---|
| **数字跳出** | 从 0.6 → 1.15 → 1（bouncy），同时上飘 30–60px 并淡出，800ms；暴击更大、换色、略歪 | 伤害、治疗、获得 |
| **延迟条** | 实色立即变化；延迟层等 300ms 后用 smooth 弹簧追上 | 血量、护盾、经验 |
| **冷却扫描** | `conic-gradient(rgb(0 0 0 / .6) var(--p), transparent 0)` 盖在图标上，`--p` 从 360deg 到 0；结束时图标闪一下（亮度 1.6 → 1，200ms） | 技能、道具 |
| **命中停顿** | 受击瞬间 UI 元素停 60–90ms，然后快速回弹 | 让打击有重量 |
| **轻微震动** | UI 容器 `translate` 随机 2–4px，150–250ms 衰减 | 受到重击、失败；可关闭 |
| **数值滚动** | `Motion.count()`；大额时末尾几位慢下来 | 金币、分数、结算。玩家正据以决策的生命、储能、弹药当帧落定，只给减少的一段短残影 |
| **飞向目标** | 获得的物品从世界位置沿弧线飞向 HUD 的计数器，到达时计数器弹一下 | 拾取、购买 |
| **揭晓编排** | 暗场 → 主体落下 → 逐项亮起 → 最高价值最后、停顿更长 | 结算、抽卡、升级 |
| **待机呼吸** | 可交互的关键按钮缓慢地亮度起伏（2–3s 周期，幅度小） | 只给"现在该按这个"的那一个 |

世界中的水纹、舞台灯或节拍可以同时运动。让玩家在连续几拍里追踪同一个目标，必要时压低干扰阅读的那层。经常打开的菜单应随输入立即就绪，章节或结算可以按作品的节奏安排停顿，并保留既有的跳过方式。

规则：
- 反馈要**即时**（同一帧开始），时长可以长；音效与动效同时触发。
- 越重要越夸张，越频繁越克制：每秒发生多次的事件（普通攻击数字）要短而小，罕见事件（升级、传说掉落）才配大编排。
- 震动、闪烁、慢动作都要有关闭选项。
- 结算揭晓接收跳过时，立即显示最终业务结果并清除旧动画。消费这一次按键，等待释放；下一次独立操作才关闭结果层。连按或长按时分别复验。

## 8. 色彩：稀有度、阵营、状态

- **底色要中性**，游戏画面本身已经很花。HUD 的底板、边框用深色中性（暖或冷取决于世界观），强调色只给可交互与关键状态。
- **稀有度色阶**：常见的"灰—绿—蓝—紫—橙"已是通用语言，可以沿用，但要**按明度对齐**并**加形状区分**（边框样式、角标、光效强度递增），不能只靠色相——色觉缺陷玩家分不清绿和橙。用 `scripts/palette.py` 对每个稀有度色生成一组，统一明度。
- **阵营 / 队伍**：敌我颜色要在色盲模式下仍可区分（蓝—橙比红—绿安全）；同时用形状（友方圆框、敌方菱形框）。
- **状态色。** 先查宿主已经建立的生命、能量、阵营、稀有度和任务色。颜色撞上世界材料时，用形状、位置和文字分开意义。节日礼服可以有多种艳色，队伍与危险仍须独立可认。
- **世界观色调**：从游戏世界的主光源取强调色（灯塔的暖黄、霓虹城的品红、雪原的冰蓝）。
- **当强调色就是世界的主材质时**（蒸汽朋克的黄铜、奇幻的金、科幻的青光），它铺满了画面，就不能再当"可交互"的信号：焦点和当前选中改用与材质对比强烈的颜色（纸白、冷青、炉火红），材质色只表示"这是一个可以按的实体"。
- **明度对齐**：稀有度、阵营、分类这类多色相的组用 `python scripts/palette.py 色1 色2 … --align --on 底色`，它把每个颜色调到同一明度，并给出压在底色上达标的文字色。
- **物件材质的色阶**（黄铜的高光—中间调—暗部、火焰的三层）写成一组变量（`--brass-hi / --brass / --brass-lo`），不要散落成几十个裸值；体检脚本对剩下的提示可以接受。

## 9. 字体与数字

- **标题字**带世界观（刻字、手写、像素、未来感），只用在标题、角色名、大数字。
- **正文与读数。** 先在实机字号、实际背景上看清一条长名称和一组接近的读数。保留原有汉字字形和界面气质，必要时分别调整信息字号、背景明度与数字字重。
- **数字**用等宽数字（tabular-nums 或等宽字体），否则计时器、计数器会抖。带世界观的标题字（Cinzel 一类）往往没有 `tnum` 特性：会变化的数字换用有 tnum 的字体，或者用 `display: inline-block; width: Nch; text-align: right` 固定每一位的宽度。
- **像素风**：用像素字体，按整数倍缩放，关掉抗锯齿（`image-rendering: pixelated` / 引擎里关闭字体平滑），不要用小数缩放。
- **本地化**：预留 30–40% 的文字膨胀空间（德语、俄语）；中日韩字体需要单独指定并检查字重是否齐全；数字、日期格式本地化。

## 10. 引擎落地

已有引擎项目直接在真实场景、目标相机、输入系统和分辨率下制作与验证。独立版式草图可用于讨论美术方向。网页原型只能证明其自身的布局和浏览器行为。

Godot 样例用原生 `Control`、`Button`、`CheckButton` 与焦点邻接。UI 导航和游戏动作各有自己的映射。打开记录来源控件，退出恢复焦点，菜单接管确认与返回。键盘重复、手柄方向与释放、鼠标点击及冷却内重复输入都可以用引擎事件重放。跨引擎迁移时保留这些行为约定，再选对应组件。[Godot 键盘与手柄导航](https://docs.godotengine.org/en/stable/tutorials/ui/gui_navigation.html) · [Xbox 焦点与导航指南](https://learn.microsoft.com/en-us/xbox/accessibility/xbox-accessibility-guidelines/112)

| 本 skill | Unity UI Toolkit | Unity UGUI | Unreal UMG | Godot |
|---|---|---|---|---|
| CSS 变量 / tokens | USS 自定义属性（`--accent: #…;` 再 `var(--accent)`） | ScriptableObject 存色板与尺寸 | 共享样式资产、Data Asset | Theme 资源（颜色、常量、字体、StyleBox） |
| 圆角、边框、底板 | USS `border-radius`、`border-color` | 九宫格 Sprite | Border / 九宫格画刷、Retainer + 材质 | `StyleBoxFlat`（圆角、边框、阴影） |
| 阴影、光、模糊 | 有限支持；常用预渲染贴图 | 预渲染贴图或 Shader | 材质（UI 材质可做光晕、扫描、溶解） | `StyleBoxFlat` 阴影；CanvasItem Shader |
| 按高度缩放 | Panel Settings 的 Scale Mode | Canvas Scaler：随屏幕尺寸缩放，参考 1920×1080 | DPI Scaling 曲线 | Stretch 模式 `canvas_items` + aspect `expand` |
| 焦点导航 | `focusable` + 导航事件 | EventSystem + Selectable 的 Navigation | 焦点系统；手柄优先的项目常用 Common UI 插件 | `focus_neighbor_*`、`grab_focus()` |
| 弹簧与缓动 | 过渡 + 代码驱动 | 补间库（如 DOTween：OutBack、OutElastic 近似弹簧） | Widget 动画曲线 | `Tween`（`TRANS_SPRING`、`TRANS_BACK`、`EASE_OUT`） |
| 数字滚动、延迟条 | 代码驱动 | 代码驱动 | 代码驱动 | 代码驱动 |

搬运要点：
- 弹簧缓动：用 `scripts/springs.py` 算出的时长作为补间时长，用引擎里带回弹的曲线近似；或者在代码里直接积分弹簧（`x'' = -k(x-1) - c·x'`）。
- 颜色：引擎里多用 sRGB，把 OKLCH 换算成 hex 再填（`scripts/palette.py` 的输出可用任何 OKLCH→hex 工具换算）。
- 字体：为中文准备完整字重与字库；引擎里的动态字体图集要覆盖所有用到的字。
- Web / Canvas / WebGL 游戏：HUD 和菜单直接用 HTML + CSS 叠在画布上，本 skill 的全部资产原样可用。

## 11. 可访问性

游戏的无障碍清单比网页更长，而且平台审核越来越看重：

- 文字大小、HUD 缩放、HUD 透明度可调
- 字幕（说话人名字、底板、大小可调）
- 色盲模式（或者从一开始就用形状 + 颜色双重编码）
- 关闭屏幕震动、闪烁、动态模糊；减弱动效
- 按键重映射；"按住"可改为"切换"；连点可改为长按
- 关键提示同时有声音与视觉

## 12. 检查清单

1. 在最亮、最暗、最花三种游戏画面上截图，HUD 每个数字都读得清吗？
2. 主要视域是否服务于当下动作？战斗时看瞄准和目标，策略地图或整备时检查多个对象能否用同一尺度比较。
3. 用手柄方向键和摇杆走过菜单，再用键盘 Tab 走一遍。看得出焦点、装备状态和下一步去向吗？退回时控制权是否交到原处？
4. 受击、获得、冷却结束、升级：每个事件都有即时的视觉反馈吗？频繁事件是否足够克制？
5. 稀有度和敌我在灰度和色盲模拟下还能分辨吗？
6. 窗口缩小、玩家把文字放大或坐到目标观看距离时，关键数字和最长名称仍读得清吗？安全区与布局根据哪个实际屏幕检查过？
7. 跳过揭晓后数值是否立即正确？同一次长按是否只跳过这一层？
8. 震动、闪烁有关闭选项吗？
9. UI 的材质、颜色、动效，说得出来自这个世界里的什么吗？可指认哪一个材料、符号或排印决定帮助辨认玩法吗？设置、字幕与宿主标准控件按熟悉程度判断。
10. 同一视口和存档下并排看改稿，能指出下一次决定需要的对象、条件和结果吗？走一次边界内外的输入，用实际行为复核。
