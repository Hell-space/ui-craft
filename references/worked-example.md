# 一次完整的过程示例

这份记录展示本 skill 的流程在一个真实题目上怎么走：每一步做了什么决定、为什么，以及**渲染后才发现并修掉的问题**。

它示范的是过程，不是样式。不要照搬这里的配色、字体或构图——换一个题目，立场句、贯穿装置和强调色都应该不同。

题目：一家社区图书馆的"我的借阅"页（中文，桌面与手机）。这是八个 Opus 样本都没有做过的类型。

> 这份记录是**第一版**的过程：立场、装置、数据都对，但只停在 1–2 档，成品平淡（`examples/library-v1-flat`）。同一题加上表现力那一步之后的版本是 `examples/library-v2-expressive`，两版的差别和后来修掉的问题见 `examples/README.md`。读这份记录学流程，看那份对照学"好看"。

---

## 1. 这一屏只回答哪一个问题

读者打开这页，想知道的不是"我借了哪些书"，而是**接下来我要去图书馆做什么，最晚哪天**。

所以全屏最大的元素是一个日期——`11.14`，136px——旁边是"周六""还有 3 天"。标题写的是结论："周六前，去一趟图书馆"。

## 2. 立场句与被否掉的方向

**一张夹在书后的期限表，而不是一个账户后台。**

| 否掉的方向 | 理由 |
|---|---|
| 封面墙式的阅读 App | 好看，但回答的是"我读了什么"，不是"我该哪天去还" |
| 电商订单列表（缩略图加彩色状态胶囊） | 把借书做成了购物；四种状态四种颜色，真正要紧的那本反而不显眼 |
| 图书馆系统原样的表格后台 | 信息全，但要自己心算哪本先到期、哪本还能续 |
| 阅读徽章与连续打卡 | 社区图书馆不需要让人焦虑 |

第二条是这个品类最常见的样子。

## 3. 贯穿装置

**期限表。** 每本书一条从"借出"画到"应还"的线，深色是已经过去的日子；一根"今天"贯穿所有行，不用算就能看出哪本离线最近。续借出来的那 14 天画成斜纹。日期盖成章。

颜色只有两种，都来自图书馆的日期戳：**蓝紫印油**（日期章、期限线的端点）和**红印油**（只给三天内到期的那一本）。红色在全页出现三处——大日期旁的"还有 3 天"、那本书的日期章、它那条线的端点——三处指向同一件事。

主按钮是墨色：两种印油都属于内容，不属于"点我"。

## 4. Tokens：只动了三个旋钮

从纸墨语域出发，改了：强调色（印油蓝紫 `#3F4C8C`，L 0.44 / C 0.106）、纸色（偏向借书卡的米黄卡纸 `#F3EEE2`）、圆角（印刷感，2px 与 4px）。其余照校准值：三级墨、两档线、Newsreader 的数字、思源宋体的标题、系统黑体的功能文字、JetBrains Mono 的日期与索书号、零阴影、`cubic-bezier(.2,.8,.2,1)`。

中文层级只用 400 与 600——微软雅黑没有 500。

## 5. 内容：数据自洽，文案说下一步

- 借期 28 天、续借延 14 天写在规则里，四本书的日期全部按这个算：10.17 + 28 = 11.14；10.06 + 28 = 11.03，续借后 11.17。星期也对得上。
- 时间轴上每条线的位置由日期换算（距 10 月 5 日的天数 ÷ 77），不是目测摆的。
- 摘要不复述表格，而是给出一个从数据里推出来的建议：
  > 还《长安的荔枝》——有 2 位读者在等它，所以不能续借。顺便取走已经到馆的《克拉拉与太阳》，它只留到周日。
  >
  > 《置身事内》下周二到期，已经续借过一次；周六读不完，也可以一起带去还。
- 不能续借的书不放一个灰掉的按钮，而是写明原因："有 2 人在等，不能续借""已续借过一次"。
- 页脚如实标注："本页是界面演示，书目真实，借阅记录与日期均为示例。"

唯一的表演性动效：点"续借"时，那条期限线向后延伸出一段斜纹，600ms。它在演示这个动作的含义。

## 6. 渲染后发现的问题

写完自查没有发现问题，静态体检也是零问题。渲染出来后看到四处：

| 现象 | 原因 | 修正 |
|---|---|---|
| 期限线那一列只有两百多像素，刻度标签挤成一团 | 把贯穿装置放在了表格中间的弹性列里，两侧的固定列和右边的侧栏先把宽度占了 | 压窄书目列、操作列和侧栏，把宽度让给期限线；刻度从"每两周一个日期"改成三个月份标记 |
| 线上的"11.07 借出""11.03 续借"小字压在"今天"线上 | 标注的位置跟着数据走，总有一行会撞上 | **做减法**：把这两类标注从线上拿掉，借出日期并进书目信息那一行；斜纹的含义交给一句脚注 |
| 吸顶导航滚动后整条泛粉 | `color-mix(in oklch, 米色 84%, transparent)` 让低彩度颜色丢了色相，渲染时按 0° 处理 | 与 `transparent` 混色一律改 `in srgb`（这一条已写进 tokens、`color.md` 和体检脚本） |
| 手机上"应还"的章在不同书之间左右错位；续借按钮只有 32px 高 | 有无"续借"章导致前面的列宽不同；沿用了桌面的控件高度 | 给每个章位固定最小宽度；触屏下按钮提到 44px |

然后依次确认了 1320px 宽屏、375px（无横向溢出，日期改成一排章，期限线保留在每本书下面）、暗色（暖炭灰底，印油色提亮，主按钮变成浅底深字），并实际点了续借。

**这四个问题没有一个能从代码里读出来。** 第三个尤其如此：代码完全合法，体检脚本当时也查不出，只有画面上那一条不该出现的粉色暴露了它。

## 7. 做完的判据

```
这一屏回答的问题：接下来去图书馆做什么、最晚哪天；回答它的是 11.14（136px，全屏最大）
立场句：是一张夹在书后的期限表，而不是一个账户后台
只属于这个题目的三样东西：
  颜色：印油蓝紫 #3F4C8C（图书馆日期戳的印油）
  文案："有 2 位读者在等它，所以不能续借"
  界面片段：带"今天"线和斜纹续借段的期限线
字号种类：8 种（11 / 12 / 13 / 15 / 17 / 20 / 标题 / 大日期）——比理想的多一种，17px 只用在馆名上
灰色种类：文字 4 + 线 2 + 表面 1（全页没有一张卡片）
圆角种类：2 种（2px、4px）
强调色出现的位置：日期章、期限线端点与斜纹、"你要去的那天"、焦点环

眯眼第一眼落在：11.14
最长内容测试：《置身事内：中国政府与经济发展》在书目列里折成两行，不破版
375px：无横向溢出
暗色：#171512 底，印油 L 0.79，红 L 0.72
删掉的装饰：线上的五处小字标注、两周一个的刻度标签
是否目视验证：是
```
