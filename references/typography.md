## 1. 选字体

### 先分配角色，再挑字体

| 角色 | 用在哪 | 要求 |
|---|---|---|
| 标题（display） | 大标题、数字、品牌时刻 | 可以有性格；只在大字号出现，所以细节经得起放大 |
| 正文（text） | 段落、界面标签、表单 | 耐读、中性、小字号清晰、字重齐全 |
| 等宽（mono） | 代码、ID、时间戳、表格数字、技术感点缀 | 与正文字 x 高度接近 |

最多两族加一个等宽。很多优秀界面只用**一族**，靠字号、字重和字距拉开层次——这比用三种字体难，也更统一。

### 搭配逻辑

- **对比搭配**：衬线标题 + 无衬线正文（或反过来）。差异要明确：一个有人文气的衬线配一个几何无衬线，而不是两个长得差不多的无衬线。
- **同族搭配**：同一家族的 display 与 text 变体，或同一设计师的作品，气质天然统一。
- **避免**：两个性格都很强的字体同台；两个过于相似的字体（看起来像加载错误）。

### 按气质找字体

下列都是可免费商用的开源或免费授权字体（使用前仍应核对各自的许可证）。来源主要是 Google Fonts 与 Fontshare。

| 气质 | 无衬线 | 衬线 |
|---|---|---|
| 中性、现代、工具感 | Geist、Inter、Switzer、Hanken Grotesk、Onest | Source Serif 4、Literata |
| 几何、友好 | Manrope、Plus Jakarta Sans、Outfit、DM Sans、Satoshi、General Sans | — |
| 人文、温暖 | Figtree、Instrument Sans、Source Sans 3、IBM Plex Sans | Newsreader、Lora、Crimson Pro、Sentient |
| 有棱角、有态度 | Space Grotesk、Bricolage Grotesque、Schibsted Grotesk、Cabinet Grotesk、Clash Display | Fraunces、Young Serif、Gloock |
| 优雅、编辑感 | — | Instrument Serif、Cormorant、EB Garamond、Playfair Display、Zodiak、Boska |
| 技术、终端 | JetBrains Mono、Geist Mono、IBM Plex Mono、Commit Mono、Martian Mono | — |

### 字体是否要"有性格"，看产品类型

- **产品界面（后台、工具、设置页）**：标题与正文用同一个无衬线家族——Inter、IBM Plex Sans、Instrument Sans 或系统字体——标题靠 600 字重和按字号收紧的字距立起来，Inter 再开 `cv11`、`ss01`。用户每天看八小时，字体要的是隐身；给后台标题换一款有个性的展示字体，结果往往比用 Inter 更怪。
- **营销、编辑、品牌、阅读**：给"声音"一款衬线——标题、引文、大数字——并且只让它出现在较大的字号上；功能性小字仍用无衬线。

### Opus 5.5 实际用的字体

八个样本里出现的（括号内是次数）：

| 角色 | 字体 | 它给的理由 |
|---|---|---|
| 西文衬线 | **Newsreader**（4） | 为屏幕阅读设计的报刊字体，有光学尺寸轴：大字自动收紧、小字够结实，一个家族撑起全部层级；斜体有"说话感" |
| 中文衬线 | **思源宋体 Noto Serif SC**（4） | 宋体最有"纸上"的感觉；600 做标题不显粗笨，900 可做竖排大字 |
| 西文无衬线 | Inter（3）、IBM Plex Sans（1）、Instrument Sans（1） | Inter 最"诚实"；Plex 有工程感但不冷；Instrument Sans 比 Inter 略窄、字形更有个性 |
| 中文无衬线 | 系统黑体栈（4）、Noto Sans SC（1） | 中文网络字体太大，各平台系统黑体已足够好 |
| 等宽 | JetBrains Mono（2）、IBM Plex Mono（2） | 凡是需要逐位比对或复制的东西都用等宽：ID、时间戳、代码 |
| 数字专用 | Palatino 一类旧式衬线（1） | 思源宋体的西文数字偏窄偏现代，配书卷气的数字更搭 |

它自述里把 Instrument Serif、Fraunces 列为首选衬线，但样本里一次都没用，四次都选了 Newsreader。

它刻意回避的：Roboto 当品牌字、Poppins / Montserrat（"模板站 2018"）、Open Sans / Lato、Playfair Display（"高端婚礼模板"）、手写体、微软雅黑当首选（只放回退）、SimSun 做屏幕正文、一个界面里超过两个家族。

**两款字体之间必须分工明确**：一个负责声音，一个负责信息，x 高度相近。两款相似的无衬线并用（Inter 加 Roboto 这种"差一点"的搭配）最糟。

## 2. 字号阶梯

用一个比率生成阶梯，而不是随手写数字。比率决定了层级的"戏剧性"。

| 场景 | 比率 | 示例阶梯（px） |
|---|---|---|
| 密集应用、后台 | 1.125–1.2 | 12 · 13 · 14 · 16 · 18 · 20 · 24 |
| 一般应用、文档 | 1.2–1.25 | 12 · 14 · 16 · 20 · 24 · 30 · 36 |
| 营销页、编辑风 | 1.25–1.5 | 14 · 16 · 20 · 28 · 40 · 56 · 80 |

要点：

- **一页用到的字号不超过 6–7 种。** 多出来的通常是没对齐阶梯的"差一点"值。
- 正文：应用界面 14px，阅读型内容 16–18px；中文正文建议不小于 14px，阅读型 16–17px。
- 最小字号 12px（中文 12px 已是下限，辅助说明尽量 13px）。
- 展示级标题要敢大。营销页首屏标题 56–96px 很正常；怯生生的 32px 标题是"模板感"的来源之一。
- 大标题用流体字号：

```css
/* 从 36px（窄屏）平滑过渡到 72px（宽屏） */
font-size: clamp(2.25rem, 1.25rem + 4.2vw, 4.5rem);
```

- `rem` 用于字号（尊重用户浏览器设置），`em` 用于随字号缩放的东西（字距、图标尺寸、内联间距）。

## 3. 行高、字距、行长

### 行高：字越大，行高越小

| 文字 | 西文 | 中文 |
|---|---|---|
| 展示标题（≥40px） | 1.0–1.1 | 1.2–1.3 |
| 标题（20–36px） | 1.15–1.3 | 1.3–1.45 |
| 正文 | 1.5–1.6 | 1.7–1.85 |
| 界面小字、标签 | 1.3–1.45 | 1.4–1.6 |

中文没有上伸部和下伸部，字面填满整个方格，同样的行高看起来比西文挤，所以整体要再松一档。

行高用无单位数值（`line-height: 1.6`），这样会随字号正确继承。

### 字距

字距不是"大标题一档、其余一档"，而是随字号连续变化的一条曲线。界面里最多的是 18–32px 的卡片标题和区块标题，它们正好落在两档之间，最容易没人管。

| 字号 | 西文字距（Inter 一类的无衬线） |
|---|---|
| 11–12px 小字 | +0.005 到 +0.01em |
| 13–16px 正文 | 0（Inter 可用 −0.006em） |
| 18–20px | −0.01 到 −0.012em |
| 24px | −0.018em |
| 32–36px | −0.022em |
| 48px | −0.03em |
| 64px 以上 | −0.035em |
| 全大写小标签 | +0.06 到 +0.08em |

- 衬线大标题收得略少（−0.022 到 −0.028em），等宽字可收 −0.01em 避免显得松。
- 这些值是为目标字体调的。网络字体加载不到、回退到 Segoe UI 或苹方时，负字距会显得挤——把幅度减半，或确认回退后依然体面。
- **中文不要负字距**，汉字会相互挤压。黑体标题保持 0 或 +0.01 到 +0.02em；**宋体大标题要加字距**（+0.06 到 +0.14em），不加会显得挤；中文小标签 +0.12 到 +0.16em。

### 行长

一行太长，眼睛回行时会找不到下一行；太短则节奏破碎。

- 西文正文 60–75 字符：`max-width: 65ch`
- 中文正文 28–40 字：`max-width: 36em` 左右
- 标题用 `text-wrap: balance` 让各行长度均衡；段落用 `text-wrap: pretty` 避免末行孤字。

长文可把行长、行距、字号当成一组变量。选一段带专名、数字和标点的真实正文，读完一段再决定是否收窄。操作标签、表格与标题各自按用途验证。英文字数的经验不能直接代入一行汉字。[USWDS 排印指南](https://designsystem.digital.gov/components/typography/)

### 对齐

- 正文左对齐。西文不要两端对齐（会产生难看的词间空洞）；中文两端对齐可以用，方块字天然适合。
- 居中只给短文本（三行以内）和仪式性场景。
- 数字列右对齐，并用等宽数字。

## 4. 字重与层级配方

### 字重

- 用两到三个字重就够：常规（400）、中等（500）或半粗（600）、有时再加一个粗（700）给展示标题。
- 小字号避免 300 及以下，会发虚。
- 层级不只靠加粗。**把次要信息变淡、变小，比把主要信息加粗更有效**，也更安静。
- 中文字重的坑见第 6 节。

### 层级配方

一个信息块通常由三到四层组成。下面是经得起复用的组合（数值按项目阶梯替换）：

```
眉题（eyebrow）  12px · 500 · 全大写/+0.06em 字距 · 次要色     ← 分类、日期、编号
标题            24px · 600 · 行高 1.25 · 主文字色
正文            15px · 400 · 行高 1.6  · 主文字色或略淡
附注（meta）     13px · 400 · 第三级文字色                    ← 时间、作者、计数
```

区分层级的手段，按"安静"到"响亮"排序：颜色深浅 → 字重 → 字号 → 字体 → 色相。**优先用安静的手段**，一次只动一两个变量；同时改字号、字重、颜色、字体会显得用力过猛。

文字颜色至少准备三级（主 / 次 / 辅助），三级都要满足对比度要求。

## 5. 数字与 OpenType 细节

```css
/* 表格、计时器、价格、任何会变化或纵向对齐的数字 */
font-variant-numeric: tabular-nums;

/* 等宽字体里区分 0 和 O */
font-variant-numeric: slashed-zero;

/* 让可变字体按字号自动调整笔画细节 */
font-optical-sizing: auto;

/* 更清晰的渲染（macOS 上常用；按需） */
-webkit-font-smoothing: antialiased;
```

- 大号数据（KPI、价格）是天然的记忆点：28–48px、500–600、字距 −0.02 到 −0.035em；**单位、货币符号、小数部分降到主数字的 0.5–0.6 倍字号并改用次要色**，`¥` 可轻微上移。完整规则见 `calibration.md` 第 5 节。
- 减号用 `−`（U+2212）而不是连字符，和 `+` 等宽等高；数字与单位之间用不换行空格。
- 正文里的年份可用旧式数字（`font-variant-numeric: oldstyle-nums`），表格与标签用等高等宽数字。
- 很多字体藏着备选字形（单层 a、开口更大的数字、带衬线的 I/l）。例如 Inter 可通过 `font-feature-settings: "cv11", "ss01"` 等开关改变面貌——这是把常见字体调成"自己的"最省力的方式。
- 用正确的标点：弯引号 “ ” ‘ ’ 而不是直引号，省略号 … 而不是三个点，区间用短破折号 –（2019–2026），中文用全角标点与「——」。
- 截断：单行 `text-overflow: ellipsis`；多行用 `line-clamp`。被截断的内容要有办法看到全文。

## 6. 中文排版

中文界面不能直接套用西文参数。差别集中在以下几处。

### 字体选择

| 类型 | 系统自带 | 可免费商用的网络字体 |
|---|---|---|
| 黑体（界面首选） | 苹方 PingFang SC（Apple）、微软雅黑 Microsoft YaHei（Windows） | 思源黑体 Noto Sans SC、HarmonyOS Sans SC、MiSans、阿里巴巴普惠体、OPPO Sans |
| 宋体（标题、阅读、人文气质） | 宋体-简 Songti SC（Apple）、中易宋体 SimSun（Windows，小字号观感差） | 思源宋体 Noto Serif SC |
| 楷体、仿宋（点缀、引文） | 楷体 KaiTi、仿宋 FangSong | 霞鹜文楷 LXGW WenKai、朱雀仿宋 |
| 展示（少量大字） | — | 得意黑 Smiley Sans、站酷系列 |

中文字体文件很大（单字重数 MB 到十几 MB）。网页上优先用系统字体；确需网络字体时做子集化、分片加载，或只把它用于少量标题文字。

### 关键参数（与西文的差异）

- **行高更大**：正文 1.7–1.85，标题 1.3–1.45。
- **不用负字距**；不用斜体（中文没有真斜体，浏览器会机械倾斜，很难看）。强调用加粗、换色，或着重号 `text-emphasis: dot`。
- **行长** 28–40 字。
- **字号略大**：同样标称字号下汉字笔画更密，中文正文比同场景的西文大 1px。后台与 App、小程序的列表正文 15px 是甜区（14 稍小、16 太松），连续阅读的正文 16–17px，辅助文字不小于 12–13px（11px 的中文在 Windows 上几乎不可读）。
- **代码里的中文**（示例查询、注释、字符串）：给中文片段单独套无衬线，不要让它落到等宽字体的中文回退上。
- **留白多一点、字重轻一档**：汉字本身视觉密度高，中文版的留白比英文版多一两成；苹方的 600 已经很重，标题常用 500–600 而不是 700。
- **按语义防断行**：标题里的短语用 `inline-block` 包起来，避免"半在 / 山"这种断法。
- **两端对齐可用**：`text-align: justify` 适合中文段落。
- **避头尾**由浏览器默认处理；可加 `line-break: strict` 更严格。

### 字重可用性（重要）

系统中文字体的字重并不齐全，这会让精心设计的层级在某些平台上消失：

- **微软雅黑只有 Light、Regular、Bold 三档。** `font-weight: 500` 会落到 Regular，与 400 完全相同；600 会落到 Bold。也就是说，在 Windows 上靠 400 与 500 区分的层级对中文无效。
- 苹方有六档字重，500 与 600 都能正确显示。

对策：依赖系统中文字体时，层级用 **400 与 600/700** 两档来拉开，并配合字号和颜色，不要把区分度押在 500 上；或者加载带完整字重的字体（如思源黑体可变版本）。

### 中西混排

- **字体顺序**：`font-family` 里西文字体在前、中文字体在后。这样拉丁字母和数字由西文字体渲染（通常比中文字体自带的拉丁字形好看），汉字回退到中文字体。
- **汉字与西文/数字之间留间隙**：约四分之一个字宽。文案里可以手动加空格；较新的浏览器支持 `text-autospace: normal` 自动处理，可作为渐进增强。
- **标点挤压**：连续全角标点（如 `」。`、`，「`）会产生过大空白。较新的浏览器支持 `text-spacing-trim: trim-start` 等值，可作为渐进增强。
- **基线与大小**：西文字体与中文字体的视觉大小可能不一致，混排后若拉丁字母显得偏小，换一个 x 高度更大的西文字体，而不是单独放大。
- **数字**：金额、数据用西文字体的数字并开 `tabular-nums`；不要让数字回退到中文字体的全宽或比例不佳的字形。
- **引号**：简体中文界面用 “ ”，也可用直角引号「」获得更干净的版面（尤其在标题中）；全文统一。

### 中文层级的额外手段

汉字本身信息密度高、字形方正，下列做法尤其有效：

- 大字号宋体标题配小字号黑体正文——中文里最经典的对比搭配。
- 充足的留白与较大的段间距（段落间用间距而非首行缩进，界面里尤其如此）。
- 用编号、短横线、细分隔线组织信息，少用图标堆砌。
- 竖排 `writing-mode: vertical-rl` 可以作为标题或侧边标签的记忆点，慎用于正文。竖排短文字（书脊、侧标）不要放进 flex 容器居中——会被折成多列，而且列从右往左排，读起来是倒的。用绝对定位加 `white-space: nowrap`：`position: absolute; top: …; left: 50%; translate: -50% 0; writing-mode: vertical-rl; white-space: nowrap;`。

## 7. 字体栈与加载

### 推荐的回退栈

```css
:root {
  /* 界面无衬线：自选西文字体放最前，其后是各平台系统字体与中文黑体 */
  --font-sans: "Geist", ui-sans-serif, system-ui, -apple-system, "Segoe UI Variable Text", "Segoe UI",
               "PingFang SC", "HarmonyOS Sans SC", "MiSans", "Noto Sans SC", "Source Han Sans SC",
               "Microsoft YaHei UI", "Microsoft YaHei", sans-serif;

  /* 衬线：西文衬线在前，中文宋体在后 */
  --font-serif: "Newsreader", ui-serif, Georgia, "Times New Roman",
                "Noto Serif SC", "Source Han Serif SC", "Songti SC", "STSong", "SimSun", serif;

  /* 等宽 */
  --font-mono: "JetBrains Mono", ui-monospace, "SF Mono", "Cascadia Code", Consolas, Menlo, monospace;
}
```

### 加载原则

- **界面必须在网络字体缺席时依然成立。** 离线环境、公司内网、中国大陆访问 Google Fonts 都可能加载失败。写完后在脑中（或实际）去掉第一个字体名，检查回退效果是否仍然体面。
- `font-display: swap` 避免文字长时间不可见；用 `size-adjust`、`ascent-override` 让回退字体的度量接近目标字体，减少布局跳动。
- 只加载用到的字重；优先可变字体（一个文件覆盖全部字重）。
- 生产项目自托管字体文件，比依赖第三方 CDN 更可靠。
- 用 `<link rel="preconnect">` 预连接字体域名，首屏关键字体可 `preload`。

## 8. 常见问题与修正

| 症状 | 可能原因 | 修正 |
|---|---|---|
| 标题和正文"糊在一起" | 字号比太小、字重相近 | 拉开到 1.25 倍以上，或换字体角色 |
| 大标题显得松散 | 默认字距在大字号下偏大 | 西文收紧到 −0.02em 左右，行高降到 1.1 |
| 段落读着累 | 行太长、行高太小、对比太低 | 限制行长，行高加到 1.6（中文 1.75），正文颜色加深 |
| 界面"灰蒙蒙" | 次要文字太多太淡 | 主文字用足对比，只有真正次要的信息才用淡色 |
| 数字列对不齐、数字变化时跳动 | 比例数字 | `tabular-nums` |
| 中文看起来挤 | 套用了西文行高与负字距 | 行高 1.7 以上，去掉负字距 |
| 中文 500 字重没效果 | 微软雅黑没有 Medium | 用 600/700，或换带完整字重的字体 |
