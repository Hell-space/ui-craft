# 从参考图还原或借鉴

先打开原图与产品当前状态。精确还原时，优先保留可观察到的比例、取景、信息、颜色与组件行为。借鉴风格时，只提取用户看中的关系，例如大面积摄影与紧凑说明的比例；实际界面使用自己的内容。只有参考图的一个宽度或静态瞬间时，其他断点和交互按内容及现有平台惯例推断，在有影响时向用户说明。

## 对齐画布

1. 找到参考的实际边界。去掉浏览器边框、系统栏、投影外框或拼图旁注等非目标区域。保留用户要求还原的系统元素。记录图像的像素宽高；若已知设备像素比，换算成 CSS 视口。一张 1170 像素宽的图片本身不能确定视口是 390。未知时，先用主要边界的相对位置建模，避免照抄图片像素。
2. 在相同状态取实装图。固定视口、主题、内容、滚动位置、选中项与缩放。等待使用到的字体、图片加载并停在可读状态。明确首屏和全页的区别。相同状态才适合逐像素叠加。
3. 从大到小挑锚点。先看主体占几成宽、顶栏和正文从哪里起、栏边和图边能否对上。再看文字的实际字面高度、标题换行、基线、图的取景和明暗块，最后看边框、半径和图标。摄影背景或半透明层的取色要标明取样区域，压缩边缘的单像素不宜作为令牌。
4. 缩到移动端时保住关键关系。例：参考中“物件全貌 → 铭牌细节 → 操作”的顺序，在小屏可以纵向排。先核对内容是否完整，再看边距是否合适。用长中文或字号放大检查二行文字挤压的情况。

## 比较两幅图

在能打开原始截图的环境里可直接并排看。需要可重复的本地校样时，使用 Pillow 与技能内的 `scripts/proof.py`。原文件保持原样，生成的 PNG 属于检查材料。

```sh
python scripts/proof.py reference.png actual.png --mode side --width 520 --out side.png
python scripts/proof.py reference.png actual.png --mode overlay --out overlay.png
python scripts/proof.py actual.png --mode gray --width 320 --out hierarchy.png
```

并排会按同一比例缩放两幅原图。尺寸不同会保留差异。叠加只接受等大的图，边界重影便于定位容器错位。字符抗锯齿、字库、照片噪点或动态时间戳也能产生差异，回到两幅原图确认原因。灰阶缩略图适合看重心，颜色本身承载意义时回到彩色及文字、轮廓或图案共同判断。图像差异的面积无法衡量艺术质量。

**一次修正如何落地。** 若主体左边、价格栏和底线都重合，只有标题第三个字提前换行，先核对实际使用的字体、可用列宽、字重与字距。挪动整个容器会破坏已经对齐的三个锚点。若标题、图和底线全都同向偏移，先修共有的外边距，再看局部。把同一状态重新截图，确认变化发生在预期的地方。
