## 决定

- **这一屏回答的问题**：一台普通服务器，真能跑十亿级向量检索吗？
- **立场句**：一份带复现命令的岩芯钻探记录，而不是又一个发光的 AI 基础设施官网。
- **否掉的方向**：
  1. 深靛或紫色渐变、光晕球、3D 点云球体，再配一个 "AI-native" 胶囊。这是向量数据库最常见的长相。它只能证明"我们很未来"，证明不了"一台机器 20 ms"。
  2. 居中标题，下面放一张假仪表盘截图。RAG 和推荐工程师判断一个数据库，看的是 benchmark 口径和资源账，不看监控大屏。
  3. 纸墨米白配衬线大标题。这是 Opus 自己的吸引子，用在一份基准报告上太文气；中文衬线还得回退到宋体。
  4. 整页黑底绿字的黑客终端风。会把基础设施做成玩具，长段的中文说明和表格在这种底上也很难读。
- **档位**：4 档（品牌落地页）。
- **预设**：以 `graphite` 为底，取它的 Inter + JetBrains Mono 字体分工和工具语域的精密感；深色舞台的做法借 `midnight` 的"物件在光里"。舞台色不用靛蓝，改成玄武岩那样的暖黑 `oklch(0.205 0.02 55)`。圆角收成 6 / 12 / 22 三级。
- **强调色**：砂岩赭石 `#B4642A`，交给 palette.py 生成整套角色变量。它对应的实物是岩芯里含铁砂岩的锈赭色，而 Strata 这个名字的意思就是"地层"。
- **贯穿装置**：一根索引的岩芯。四层是石灰岩、砂岩、页岩、玄武岩，分别对应路由层、码本层、图层、向量层。**层厚等于一次 p99 查询在这一层停留的时间**，全长 420px 对应 17.8 ms。左侧有一把深度标尺，赭色钻头沿着它往下走，同时底下的读数从 0.0 计到 17.8。同一套地层色出现在四个地方：工作原理区 explain 表格的色标和耗时条、资源账本的内存与 NVMe 两条横条、logo（三条斜地层）、结尾舞台底边的地层带。

## 做完的判据

**0. 截图单看好不好看：没有目视验证。** 按任务约束没有用浏览器或预览工具，所以下面每一条都是按代码和计算推出来的，不是看到的。按设计，五个来源都放进去了：
- 尺度：首屏 h1 最大 128px，是 16px 正文的 8 倍。
- 色面：首尾两块深色舞台；资源账本是整块下沉的色面；两个终端是深色面板。
- 光与深度：岩芯有圆柱明暗（光从左上来）、顶面径向高光、顶缘白色高光、两层接触影；岩芯背后有一团赭色环境光，只在这个物件后面；终端用第 5 档阴影；主按钮有同色投影和内高光；舞台上有颗粒。
- 物件：SVG 画的岩芯，带层理纹理和波状层界。
- 运动：
  - 首屏编排：眉题 80ms → 标题逐行 140ms → 岩芯 260ms 用 gentle 弹簧放大进场 → 层标签 560–740ms 交错 → 钻头和读数 760ms 同时出发，同一条 ease-out-quart 曲线，走 1100ms。
  - 叙事联动：滚到哪一步，右侧 explain 表格对应的行亮起，耗时条对应的段抬高。
  - 其他：账本横条从左向右展开；代码标签页指示条用 smooth 弹簧滑动；复制按钮的对勾用 bouncy 弹出；按钮按下时缩小。

1. **最大的元素是否回答了问题**：回答它的是 h1"十亿向量，一台服务器。"，`clamp(48px…128px)`，字重 700，是首屏最大最重的元素。p99 读数是 36px，属于第二层。证言区的"9 → 1"也用了 display 字号，但它在另一屏。
2. **立场句**：一份带复现命令的岩芯钻探记录，而不是又一个发光的 AI 基础设施官网。
3. **只属于这个题目的三样东西**：
   - 题材色：砂岩赭石，对应岩芯里的含铁砂岩层。
   - 只有这个产品才会写的文案："每次查询，都是一次钻探。"，以及"层厚即耗时：一次 p99 查询在每一层停留的时间。"
   - 只有这个产品才有的物件：按 0.4 / 4.7 / 7.3 / 5.4 ms 定层厚的四层岩芯。另外还有一节"什么时候不该用 Strata"，并写明该换成什么。
4. **字号、灰阶、圆角、强调色**：
   - 字号 7 种：12 / 14 / 16 / 19 / 36，h2 `clamp(32–56)`，display `clamp(48–128)`。
   - 文字灰 4 级（text / muted / subtle / faint），线 2 级；舞台上的文字 3 级。
   - 圆角 3 种：6 / 12 / 22。圆点不算在内。
   - 强调色出现的位置：三处主按钮、标尺上的钻头和钻进线、指标带里的 p99 数字、配置单里 GPU 一栏的"无"、焦点环、标签页指示条、复制成功的对勾、证言区的"1"、代码里的数字。全都是信号，没有大面积使用。
5. **数据自洽**：
   - 0.4 + 4.7 + 7.3 + 5.4 = 17.8 ms；累计值 0.4 / 5.1 / 12.4 / 17.8 ms，和标尺刻度一致。
   - 层厚：0.4 ÷ 17.8 × 420 = 9.4px；三条层界在 y = 23.4 / 134.3 / 306.6。
   - 内存：3.2 + 64 + 48 + 24 + 116.8 = 256 GB。
   - NVMe：1.54 + 0.13 + 0.42 + 5.59 = 7.68 TB，即 2 × 3.84 TB。
   - 路由质心：1,048,576 × 768 × 4B ≈ 3.2 GB。
   - PQ 压缩码：10 亿 × 64B = 64 GB。
   - 邻接图：10 亿 × 32 × 4B = 128 GB，内存里缓存其中 48 GB，小于 128 GB。
   - fp16 原始向量：10 亿 × 768 × 2B = 1.54 TB。
   - 每个分区约 954 条向量，64 个分区共约 61,056 条。
   - 精排读取：320 × 1.5 KB = 480 KB。
   - 证言里的 2.3 亿条，落在"适合 1 亿到 30 亿条"的范围内。
6. **各尺寸与交互：全部未目视，下面是推算或静态核对的结果。**
   - 1440 宽：首屏约 812px 高，小于 900。
   - 1100×760：命令行和按钮之间会折行，为此把命令缩短成 `docker run -p 7700:7700 strata/strata`（约 539px，对 544px 的栏宽），并加了 `max-height: 820px` 时收紧首屏上下留白。岩芯下方的读数可能贴着首屏底边。
   - 375 宽：舞台内宽 319px，等于标尺 16 + 间距 6 + 岩芯 144 + 间距 6 + 标签约 147。标尺数字在这个宽度隐藏，只留刻度线。所有栅格都用 `minmax(0, 1fr)`，命令行超长时以省略号截断。
   - 暗色：所有角色变量都用 `light-dark()` 写，明暗两套对比度全部通过；终端在暗色下改用浅色细边勾出轮廓。
   - 键盘：代码标签页支持左右方向键、Home、End，采用 roving tabindex；舞台和终端里的焦点环换成浅色。
   - 主要交互：复制（有 `execCommand` 回退，结果用 aria-live 播报）、标签页、叙事联动、悬停层标签时其余地层变淡。
   - JS 用 `node --check` 检查通过；HTML 标签嵌套用解析器检查过，没有错位。
7. **删掉的装饰和打磨的细节**：
   - 删掉：
     - 本来想再画一台 2U 服务器的前面板，删了，避免和岩芯抢主角。
     - 标尺上的"0"刻度，删了，因为它和 9px 外的"0.4"相撞。
     - 导航上的入场动画，删了，因为 `.js [data-reveal]` 的 transition 会覆盖导航自己的背景过渡。
   - 打磨：
     - 层标签的引线延长到正好碰到岩芯外缘。
     - 首屏读数改成和钻头同一时刻出发、同一条曲线，不用 `data-count` 的自动触发。
     - 指标带的说明文字改成 `<dd>`，修正 dl 的语义。
     - 元信息之间的"·"全部换成间距。
     - 圆角从 6 种收成 3 种：账本横条改为外层裁切，色块本身做直角。
     - 25 个裸色值全部收进终端、语法高亮、地层的变量。

## skill 里含糊、矛盾、难执行或不适用的地方

1. **"没渲染不算做完"和本任务的约束冲突。** 无法渲染时，skill 让我"选更保守的构图"；同时又要求"拿不准就往上一档"、落地页做 4 档。两条该听哪条没有说。我选了 4 档，并如实注明没有目视。
2. **"圆角全界面不超过三种"和预设本身矛盾。** `styles.css` 里每套预设都定义了四级圆角（sm / md / lg / xl）。色样、条形图的分段这类微小元素需不需要单独一级，也没有说。
3. **"字号 6–7 种"和"每一级都要拉开足够的对比"在落地页上很难同时满足。** worked-example 自己就用了 8 种。我压在 7 种，代价是 h3 只有 19px，和正文 16px 的差距很小，只能靠字重和旁边 36px 的耗时数字撑起层级。
4. **数字用不用等宽，两个文件说法不一。** `compositions.md` 的指标带写的是 `tabular-nums`，`visual-craft.md` 说"单个静态大数字用比例数字"。指标带里的数字正好是"静态但并排比较"的情形，我按 compositions 的写法用了等宽。
5. **软件这类抽象产品，"题材里的实物"不好落地。** 向量数据库没有天然的实物。skill 一边说"至少把强调色换成题材里一件实物的颜色、画题材物件"，一边在 product-types 里说"产品本身的界面通常是最好的主视觉"，没有说两者怎么取舍。我是从名字 Strata（地层）引出岩芯，再让产品界面（explain 终端）在第二屏出场。如果产品名字不带意象，这一步会很难做。
6. **`motion.css` 的 `.js [data-reveal]` 会覆盖元素自己的 transition 简写。** motion.md 只提醒了 transform 冲突，没提这一点。这导致"导航淡入"这条时间表无法直接照做：吸顶导航的背景过渡会被吞掉。
7. **`data-count` 一进入视口就开始滚动，不能延迟。** 首屏里这和"物件 300ms、细节 600ms"的编排表对不上，我只能绕开它，手动调用 `Motion.count`。建议加一个 `data-count-delay`。
8. **palette.py 生成的舞台色彩度偏高。** 生成值是 C 0.056，看起来像巧克力棕。visual-craft 只规定了舞台明度（L 0.18–0.30），没规定彩度，我手动降到了 0.02。
9. **audit.py 有两类提示和其他文件自相矛盾。**
   - 中文页面上的负字距：我的负字距只用在数字和西文上，也照样被提示。
   - 超过 500ms 的过渡：motion.md 自己规定了 1.1s 的数字滚动和 1.4s 的描线，还是会被提示。
10. **"中文不用等宽"没有覆盖代码里出现中文字符串的情况**（比如示例查询）。我给这段中文单独套了无衬线。
11. **"选一套预设"没说能不能混用。** 这个题目最合适的是 graphite 的字体加 midnight 的舞台，这样算不算"选了一套"，skill 没有交代。
12. **判据第 6 条要求逐个给出各尺寸的渲染结果，但没说渲染不了时怎么填。** 我写的是推算值，并标明未目视。
