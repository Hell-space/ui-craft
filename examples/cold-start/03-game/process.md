## 立场、档位、预设、强调色

- **立场句**：是钟匠的表盘和锅炉上的压力表，指针替玩家指路；而不是一套套着金色浮雕边框的蒸汽朋克 UI 皮肤。
- **否掉的方向**：
  1. 金色浮雕边框、羊皮纸卷轴、满屏齿轮贴花：这就是"蒸汽朋克游戏 UI 套件"的默认长相，题材元素全在边框上，内容反而没有形状。
  2. 一条蜿蜒小路串起关卡点（手游关卡图最常见的样子）：在"钟城"里没有因果关系，城市的形状也不会说话。
  3. 升级界面做成技能树网格加一张属性表：两条路线二选一封顶这件事、"值不值得买"这件事，都没法一眼读出来。
  4. 发光蓝边科幻 HUD：材质跟世界对不上。
- **贯穿装置**：黄铜表盘上的指针。
  - 地图：整座城就是一面钟。十二关放在十二个时位上，时针指着当前进度（第 VII 时），**分针就是光标**，跟着焦点转（弹簧动画，走最短的弧）。从钟楼锅炉通到 I→VII 的蒸汽管是热的，有蒸汽流动；VIII 以后是冷铁管。已通汽的街区亮着窗灯，没通汽的街区是冷色、没有灯。
  - 塔坊：两条升级路线画成两根从锅炉往上送汽的管道，每一级是一个阀门手轮。塔座上有一块压力表，预览某一级时指针摆到新值，原来的值留一根虚影。要装上的部件在塔身上半透明地亮着。
- **档位**：4 档（游戏的全屏菜单，按 game-ui 的说法是 4–5 档）。
- **预设**：`midnight` 午夜舞台。用了它的这些东西：深色舞台、物件放在光里、暖色强调配深色底。字体整套换掉了：Inter Tight/Inter 换成 Cinzel（罗马数字、大数字）+ Noto Serif SC 900（标题）+ 系统黑体（正文）。
- **强调色**：黄铜。`palette.py` 用 `#B8863B` 生成的暗色强调色是 `oklch(0.74 0.088 75)`，我把它提到 `oklch(0.80 0.11 82)`，让抛光黄铜在铸铁底上有光泽。其余几种语义色都从世界里取：铜绿 patina 表示变强、已通汽；铁锈 rust 表示变弱、不够钱；炉火 fire 表示当前关；发蓝钢 blued 用在钟针上（真表针就是烤蓝的钢）。焦点用**纸白**，不用黄铜。原因写在下面"含糊之处"第 4 条。

## 做完的判据：逐条证据

**0. 截图单看好不好看？五个来源满了几个？**
没有截图。任务约束禁止用浏览器和预览面板，所以**没有目视验证**。按代码推断，五个来源满了四到五个：
- 尺度：地图直径 84cqh，节点上的字只有 1.7cqh；档案里的罗马数字 10cqh，旁边的标签 1.7cqh，差约 6 倍。
- 色面：整屏是煤烟底，城是一整块圆形色面，左上有台灯打下的暖光。
- 光与深度：同一个光源（左上），表针的投影由外层 g 投出，指针怎么转影子都朝下；黄铜盘有顶边高光；面板有内高光，阴影分两层。
- 物件：城、钟楼齿轮、表盘、两根钟针、蒸汽管、三座塔（部件可以逐级装上）、压力表、阀门手轮。
- 运动：开场编排；分针和时针用弹簧；管道里蒸汽流动；买东西时数字滚动、阀门弹一下、管道充汽、部件长出来；第 III 级要按住 0.9 秒（有进度填充）。

**1. 这一屏回答什么问题，回答它的元素是不是最大的？**
- 地图回答"下一关打哪、我走到哪了"。最大的元素就是城本身：时针指着 VII，VII 后面亮着炉火。
- 塔坊回答"这一级让塔强多少、买得起吗"。最大的字是详情栏里的 7.2cqh 大数（比如每秒伤害 **+31%**），左边塔身的压力表指针摆过去，跟它对应。

**2. 立场句**：见上。

**3. 只属于这个题目的三样东西**
- 题材色：黄铜（表壳、阀门）。另有发蓝钢（表针）、铜绿（老黄铜生出的锈）。
- 只有这个产品才会写的文案："第 VII 时位"；"钟楼报时之前，守住最后一座塔"；"蒸汽甲虫……背着自己的锅炉，打穿它会炸开"；"装上之后，路线 B 的第 III 级会被封住"；"管道还没通汽"。
- 只有这个产品才有的物件和数据：钟面地图（时针表示进度，分针表示光标）、压力表预览、从锅炉往上走的升级管道。

**4. 字号、灰、圆角各几种？强调色用在哪？**
- 字号 token 6 个：1.7 / 2 / 2.6 / 4.4 / 5 / 10cqh。另有几个专用尺寸：节点罗马数字 2.9、升级大数 7.2、单位和小字 1.5–1.6。
- 文字灰 3 档：paper、paper-muted、paper-faint。最低一档在铸铁面板上的对比度是 5.32:1。
- 圆角：token 3 种（.5 / 1 / 1.6cqh）加正圆。细进度条用半高圆角，所以 audit 统计出 10 种。
- 黄铜作为**信号**出现在：页签选中态、主按钮（出发 / 安装）、已得星、按键提示的键帽、齿轮余额、当前可装那一级的手轮。黄铜作为**材质**出现在：关卡盘、塔身、管道法兰。焦点一律用纸白圈，再加放大和指针。

**5. 数据自洽**
- 星数：3+3+2+3+1+2 = 14，显示"14 / 36"。第二章需要 24 颗，"还差 10 颗"由代码算出。
- 汽炮现状是 A I：伤害 40+8 = 48，射速 0.80，每秒伤害 38.4。装 A II 以后：伤害 72，射速 0.80×0.875 = 0.70，每秒伤害 50.4，+31%。齿轮 415 − 340 = 75，详情里写"装完剩 75 齿轮"。
- 星级条件和最好成绩对得上：V 铸钟厂"耐久 9/20"，所以没拿到"不少于 15"那颗星；VI 游丝巷"耐久 12/20、15:48"，所以没拿第二颗，拿到了"16 分钟内"那颗。
- 塔坊顶部"第 6 / 15 波"，与 VII 发条巷的 15 波一致。

**6. 1440、1100×760、375、暗色、键盘、主要交互**
都**没有渲染验证**。下面是按代码推算的结果：
- 1440×900（宽高比 1.6）：画面铺满，1cqh = 9px，最小字 15.3px。
- 1100×760（1.447）：宽高比被夹在 1.42–2.1 之间，所以铺满，没有黑边，1cqh = 7.6px，最小字 12.9px。按这个宽度逐项算过档案栏：标题 `d-head` 不换行（XII＋"正午钟楼"约 35.8cqh，栏宽 36.1cqh）；档案总高约 74/75cqh，接近溢出，这是风险最大的地方。
- 375 竖屏：显示"把手机横过来"的提示（手机图标转 90°），另有一个 44px 的"仍然竖着看"按钮。塔防是横屏游戏，我没有做竖屏排版。
- 暗色：这是一个只有暗色的游戏界面，没有做浅色主题。
- 键盘：方向键 / WASD 在地图上按空间方向找最近的节点（只在前方 70° 扇面里找，找不到就晃一下）；Enter 出发或安装；第 III 级按住 Enter；Esc 返回；Q/E 切页签；C 回到当前关；1/2/3 换塔。Tab 走原生焦点，节点和手轮都用 roving tabindex。
- 手柄：轮询标准映射。十字键或左摇杆移动，按住有连发（首次 380ms，之后每 140ms 一次）；A 确认，按住也算；B 返回；X 回到当前；LB/RB 切页签；LT/RT 换塔。连上手柄时按键提示自动切换，也可以手动切换。
- 用 `node --check` 检查了三段脚本的语法，都通过。手算了 `statsOf` 的几组结果。没有运行过任何交互。

**7. 删掉的装饰与打磨的细节**
- 删掉的：
  - 地图四角原本想放的"幽灵齿轮"底纹。跟内容没有因果，删了。
  - 钟楼表盘上的罗马数字。节点本身已经是时标，表盘上再写一遍是重复。
  - 节点外圈的街区名。会和城墙刻度、星级挤在一起，改成写在内环路上。
  - 面板的金色浮雕边框。只留一圈 1px 嵌入的细黄铜线和四颗铆钉。
- 打磨的：
  - 表针的影子由外层 g 投出，跟着光源走，不跟着指针转。
  - 分针改成走最短的弧；开场时则顺时针扫到焦点。
  - 地图推近到选中的街区再切到塔坊（`transform-origin` 算到那个节点上）。
  - 一碰键盘或手柄，按键提示就即时切换。
  - 三星关卡多一圈齿轮外缘，把形状当成第二重编码。锁定关卡用铁色加锁形徽标，不只靠颜色区分。
  - 属性变化同时用 ▲▼、颜色、斜纹（增加是铜绿实纹，减少是铁锈空心纹）三重编码。
  - 换选中项时，正在按住的安装会作废，避免买错。
  - 在鼠标上，悬停就选中、点击就确认；在触屏上，第一下选中看档案，第二下才确认。
  - 竖屏时给出横屏提示。

## skill 里含糊、矛盾、难执行或不适用的地方

1. **"没看过渲染的界面不算做完"和本次约束冲突。** SKILL 给的退路是"选更保守的构图并明说"。但 game-ui 要求全屏菜单至少 4–5 档，两条放在一起，不知道该保守到什么程度。我按 4 档做了，在这里明说没有目视验证。建议在 skill 里写清楚：不能渲染时，哪些手法风险高、应当回避（比如 cqh 布局的溢出、SVG 叠 HTML 时的对位）。
2. **"375 宽"这一项对横屏游戏不适用。** game-ui 的样例本身就是 16:9 加黑边、按高度缩放。在 375 竖屏上整块画面只有约 211px 高，根本无法阅读。skill 没说横屏游戏应该怎么交代这一项。我做了横屏提示。
3. **"暗色"这一项对游戏不适用。** 判据第 6 条要求检查暗色，但游戏 UI 通常只有一套配色，预设里的 `light-dark()` 写法在这里也用不上。
4. **黄铜既是世界的材质，又是强调色。** 规则是"颜色作为交互信号要稀缺（≤5%），作为氛围要有面积"。但在蒸汽朋克里，黄铜就是满屏的材质（关卡盘、塔身）。如果焦点也用黄铜，就会淹没在材质里。我的处理是：焦点改用纸白圈，黄铜只当作"可按的实体"。skill 应该说明"强调色等于世界主材质"的时候怎么办，game-ui 第 8 节只说了"底色要中性"。
5. **"颜色全部走 CSS 变量"和"用 SVG 画物件"冲突。** SVG 的 presentation attribute 不能稳定地使用 `var()`（我在阀门手轮上改成了 `style=`），而材质渐变又需要很多中间色阶。audit 报了 68 种裸色值，基本都来自插画里的渐变色标。建议 audit 把 `<stop>` 和插画 SVG 排除掉，或者 skill 明确说物件插画可以例外。
6. **"无限循环"的边界不清楚。** SKILL 说"只有'正在发生'的东西循环"，game-ui 又说主菜单背景要是"活的游戏世界"，还允许"待机呼吸"。我留了这些循环：钟楼齿轮、管道里的蒸汽、当前关的炉火和蒸汽、预览部件的闪烁、烟囱冒汽。audit 计为 10 处。到底多少算过量，skill 没给标准。
7. **数字字体的两条规则互相打架。** game-ui 说"数字用等宽数字"，SKILL 说"单个静态大数字用比例数字"。还有一个更实际的问题：带世界观的标题字（Cinzel）大多没有 `tnum` 特性，`tabular-nums` 写了也不生效。我的处理是：会变化的余额数字用 Cinzel，接受它轻微抖动；表格里的数字用系统字体的等宽数字。skill 应该提醒"选的标题字有没有 tnum"。
8. **"1080p 下最小 18px"和"按高度缩放"放在 1100×760 上，结果不到 13px。** game-ui 的做法（cqh 加 16:9 黑边）在笔记本窗口里会更小，只有 1100×619。我把宽高比放宽到 1.42–2.1 来减少黑边，但这需要布局能吸收宽度变化，而 skill 没讲游戏界面的宽高比应该怎么处理。
9. **首屏编排时长。** motion.md 写的是"总长 ≤ 1.2s"，game-ui 允许结算编排 2–4s，菜单类全屏界面落在中间，没有说法。我的地图开场约 1.3s，蒸汽淡入收尾到约 1.9s。
10. **palette.py 不适合给游戏配语义色。** game-ui 说"用 palette.py 对每个稀有度色生成一组、统一明度"，但脚本输出的是一整套网页角色变量（bg/surface/text…），不会对齐多个色相的明度。铜绿、铁锈、炉火这几种颜色，我只能手选，再用 contrast.py 逐对验证。
11. **"物件留一点不完美"和钟表题材的精确感冲突。** 表盘、齿轮、时标本来就应该是精确的。我把不完美放在城市上：街区随机切分、窗灯随机、河道是曲线、炮管斜着指向右上。skill 可以补一句：精密机械题材的不完美应该放在哪里。
12. **肩键和扳机键的分工。** game-ui 说"肩键切标签页、扳机键调数值"，但塔坊同时需要"切页签"和"换塔"两种切换。我把换塔放在了扳机键（LT/RT）上，这偏离了"扳机调数值"的说法。skill 只给了一种分工，没有覆盖这种二级切换。
