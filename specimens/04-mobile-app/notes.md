# 细水 · 记账首页 设计笔记

## 模型

Opus 5.5（模型 ID：`claude-opus-5-5`）

## 设计立场

首页只回答一个问题：**这个月我还能花多少，节奏对不对**。所以最大的数字不是"总资产"也不是"本月支出"，而是"本月还可以花 ¥4,113.60"，紧跟着把它换算成"剩 21 天，平均每天可用 ¥195.89"——一个人在午饭前真正会用到的数字。

整体方向是"安静的纸本账簿"：暖白纸色底、近黑墨色字、只有一个墨绿作为动作色，一个赭石作为"超出节奏"的提醒色。记账是每天要打开好几次的工具，它应该像一本好用的本子，而不是一个在每次打开时都对你喊叫的仪表盘。

贯穿全页的一个核心概念是**节奏线（pace）**：今天是 11 月 10 日，月份过去了 1/3，所以总预算条、每个分类的小条上都有一根竖刻度标在 33.3% 处。用户不需要算就能看出"购物已经用了 71%，而月份才过 33%"。日支出图里的虚线是同一概念的日维度版本（日均预算 216.67）。我故意让数据讲一个有轻微张力的真实故事：总体比节奏多花 ¥219.73，主要来自购物（买了件优衣库外套），提示条给出可执行的建议"往后每天少花 ¥10 左右"，而不是一句空泛的"注意消费"。

考虑过又放弃的方向：
- **深色 + 霓虹渐变的金融卡片风**：最常见的"金融科技"样貌，渐变银行卡、发光数字。它让钱看起来像游戏积分，也和"每天平静地记一笔"的情绪相反。
- **大环形图 / 饼图作为首屏主视觉**：好看但信息效率低，分类比例在环上很难读，而且它不回答"还能花多少"。
- **高饱和多色分类体系**（餐饮橙、交通蓝、购物粉……）：一屏五六种颜色会让真正需要注意的赭石警示失去信号意义。所以分类图标全部是中性灰底，只有收入用墨绿底。

## 字体

- **Noto Sans SC**（400 / 500 / 600）：所有中文。字形中性、字重齐全、和 Inter 的 x 高度比例协调。回退：`-apple-system, "PingFang SC", "Hiragino Sans GB", "Microsoft YaHei", sans-serif`，离线时在 Mac/iOS 上落到苹方、Windows 上落到微软雅黑，都体面。
- **Inter**（400 / 500 / 600）：所有数字。开启 `tnum` 等宽数字，保证金额列、日期、百分比纵向对齐；开 `cv11`（单层 a 的替代形）让数字旁的字母更安静。回退：`"SF Pro Text", -apple-system, "Segoe UI", Roboto, "Helvetica Neue", Arial`。
- **Noto Serif SC** 600：只用在画框外左侧的品牌字"细水"上，一处。给画框外的"说明牌"一点书卷气，和 App 内的无衬线拉开层级。回退：`"Songti SC", STSong, SimSun`。

主金额的小数部分降为一半字号并用灰色：分是真实的，但不该和元抢注意力。

## 色彩

| 值 | 角色 | 理由 |
|---|---|---|
| `#E6E2D9` | 画框外桌面底色（叠加一层径向渐变 `#EEEBE4 → #DEDACF`） | 比 App 纸色更深一档的暖灰，让手机像放在一张亚麻桌面上，画框边缘自然被衬出来 |
| `#8A8478` | 画框外说明文字 | 和桌面同色相，低对比，不抢手机 |
| `#F7F5F0` | App 底色（纸） | 暖白而非纯白，长时间看不刺眼；也让纯白卡片能"浮"出来 |
| `#FFFFFF` | 卡片 | 与纸色只差一点点，形成极轻的层次 |
| `#1E1D1A` | 主文字、今日柱、主进度 | 带一点暖的近黑，比 #000 柔和 |
| `#4A4741` | 二级文字、图标描边 | |
| `#8C877D` | 说明、元数据 | 在 #F7F5F0 上对比约 3.6:1，只用于 12–13px 的辅助信息 |
| `#BDB8AD` | 极弱文字、坐标、节奏刻度 | |
| `#E9E5DC` / `#F0EDE6` | 分隔线、轨道、图标底 | 两档线色：一档给进度轨道，一档给列表分隔 |
| `#2E6A4E` 墨绿 | 唯一的动作色："记一笔"按钮、收入金额、焦点环 | 绿在中文语境里不像红那样带"亏损"暗示，墨绿又足够沉稳，不像荧光绿那么"理财 App" |
| `#E3EEE7` | 收入图标底 | 墨绿的浅底 |
| `#B4532F` 赭石 | 超出节奏：超额部分的斜纹、超日均的柱、预警分类 | 用赭石而非正红：是"提醒"不是"报警" |
| `#F6E7DF` / `#7A3519` | 提示条底 / 字 | 同色相浅底深字，文字对比 > 7:1 |

**支出金额用墨色，不用红色。**记账 App 里绝大多数条目都是支出，全部染红等于全屏报警；用"−"号（真正的减号 U+2212）表达方向就够了。

## 构图与间距

- 屏幕左右统一 20px 边距；卡片内 16px。所有区块左缘对齐在同一条 20px 竖线上，卡片内容对齐在 36px（20+16）。
- 间距基于 4 的倍数：4 / 8 / 12 / 16 / 20 / 28。区块之间 28px，区块标题到内容 12px，日期组之间 18px。
- 信息顺序按"决策优先级"：剩余金额 → 节奏条 → 一句解释 → 日趋势 → 分类 → 流水。前三项不放进卡片，直接排在纸面上，作为"标题区"；从图表开始才用卡片，形成"上半页是结论、下半页是证据"的节奏。
- 列表三列栅格：36px 图标 / 弹性内容 / 右对齐金额，分类预算与流水共用这套栅格，上下滚动时图标列始终在同一位置。
- 图表 30 列等分，坐标只标 1、5、10、15…30，今天（10）加粗为墨色；未来日子画成 3px 的灰色短条而不是留空，让人看到"月份还剩多少格"。
- 底栏 88px（含 Home Indicator 安全区），中间 84px 留给凸起的"记一笔"。内容底部预留 120px，最后一条不会被底栏遮住。

## 几何、深度与质感

- 圆角分三级：机身 56px、卡片 18px、分类图标 11px（约为 36px 的 0.3，和 iOS 图标的连续曲率观感接近）；进度条用高度的一半做全圆角。
- 卡片不用描边也不用明显阴影：`0 0 0 1px #F0EDE6` 一圈极淡的"线"加 `0 1px 2px rgba(60,50,30,.04)`，几乎看不出，只是让白卡片在纸面上有边。
- 唯一真正有投影的是"记一笔"按钮：`0 0 0 5px 纸色` 的描边环把它从底栏"挖"出来，加一个带墨绿色相的下投影。
- 底栏是 86% 透明纸色 + `blur(16px) saturate(1.4)`，滚动时内容在下面若隐若现；状态栏则用纸色向下渐隐的渐变，避免内容在灵动岛下方硬切。
- 超额部分用 45° 斜纹（赭石 + 浅赭石 2px 交替），"超出的那一段"在视觉上像被标记出来的区域，比单纯换色更容易被理解为"多出来的"。
- 机身：两层 `box-shadow` 环做出黑色金属边框和一圈更亮的倒角，再叠两层大而暖的投影，让它落在桌面上而不是悬空。没有画按键、没有反光高光——画框是展台，不是主角。

## 动效与交互状态

- 首次加载：每日柱从底部生长，`cubic-bezier(.2,.8,.2,1)` 0.6s，按日期依次延迟 18ms，像一行字被写出来。`prefers-reduced-motion` 时全部关闭。
- 图表交互：悬停柱子时顶部读数实时显示那天的日期、星期和金额；离开恢复到选中日；点击把选中日固定下来。默认选中"今天"。未来的日子不可交互、不可聚焦。
- 小眼睛按钮：一键隐藏所有金额（地铁上打开 App 时的常见需求）。主金额模糊 10px，其他金额替换为"＊＊＊＊"，布局完全不跳动；图标在睁眼/闭眼之间切换，`aria-pressed` 同步。
- 列表行：悬停变为 `#FBFAF7`，按下变为 `#F0EDE6`，可 Tab 聚焦。
- "记一笔"：悬停上浮 1px，按下缩到 0.94，回弹曲线带一点过冲 `(.3,.7,.4,1.4)`。
- 所有可聚焦元素统一墨绿 2px `focus-visible` 外环。

## 我在意的细节

1. 金额用 Inter 的等宽数字，整列金额的小数点上下对齐。
2. 支出前用真正的减号"−"（U+2212），不是连字符"-"，和"+"等宽等高。
3. 主金额的"¥"比数字小、颜色淡、轻微上移对齐基线；小数部分降一半字号——分保留，但不抢戏。
4. 节奏刻度在总预算条和每个分类条上都出现，位置精确为 10/30；总条上的刻度外面包了一圈纸色，让它在任何填充色上都能被看见。
5. 日支出图的"日均预算 216.67"标签放在右侧，因为右边是未来的日子、柱子很矮，标签永远不会压到数据。
6. 超过日均预算的历史柱用赭石，但"今天"始终是墨色——今天还没过完，不该提前评判。
7. 分类按"超出节奏的程度"排序，不按金额排序：最需要注意的永远在第一行。
8. 预警阈值是"比时间进度快 15 个百分点以上"，所以餐饮 51% 不报警、购物 71% 报警——避免每个分类都在变色。
9. 流水里每一笔的副标题写的是"东西 · 时间 · 支付方式"（如"生椰拿铁 · 08:42 · 微信"），这是用户回忆一笔账时真正依赖的线索。
10. 日期组头右侧显示当天支出合计，且与图表中对应柱子的数值一致（今天 148.70、昨天 286.20）；所有数字前后自洽：每日之和 = 已花 2,386.40 = 分类之和，预算 6,500 − 2,386.40 = 4,113.60，÷21 天 = 195.89。
11. 收入（工资）只是一行墨绿，没有庆祝动画，也不把它并入"还可以花"——工资不应该让人觉得预算变多了。
12. 列表末尾一行"本月已记 37 笔"，给滚动一个安静的终点，也是对坚持记账的一点点肯定。
13. 状态栏、灵动岛、Home Indicator 都按 iPhone 尺寸画，但图标都是纯色内联 SVG，不引外部图片。
14. 窄屏（<430px）时整台手机等比缩放，左侧说明牌在 <760px 时隐藏，页面不出现横向滚动。

## 我刻意回避的做法

- 紫蓝渐变、玻璃拟态卡片、发光数字这类"金融科技"默认审美。
- 首屏放环形图或饼图。
- 支出一律标红。
- 每个分类一个高饱和颜色。
- emoji 当分类图标（🍔🚇🛍️）：在不同系统上渲染不一致，风格也无法统一；全部手绘为 1.6px 描边的线性图标。
- "你好，XX！今天也要好好记账哦"这类问候语和吉祥物占据首屏。
- 把"总资产"、"净值"放在首页：多数人记账关心的是现金流，不是资产负债表。
- 假数据的"整数感"（1000、2000、500）：账目金额都是带分的真实价格。
- 卡片套卡片、处处描边。

## 这是"我"的习惯

大多数设计里我都会做的：
- 先确定"这一屏只回答哪一个问题"，然后让最大的那个元素回答它。
- 暖白底 + 近黑墨色 + 一个克制的强调色，强调色只给动作和极少数正向信号；警示色单独再留一个，且只在真正需要时出现。
- 数字一律等宽（tnum），小数位和单位降级处理。
- 中西文分别指定字体，中文用思源/Noto 系，数字用 Inter，回退栈写到各平台系统字体。
- 阴影极浅、宁用一圈 1px 的"影子线"也不用描边。
- 间距 4 的倍数，左缘对齐一条线。
- 所有交互都有 hover / active / focus-visible 三态，并尊重 `prefers-reduced-motion`。
- 用一句可执行的话解释数据（"往后每天少花 ¥10"），而不是只摆数字。

只为这个题目做的：
- "节奏线"这个贯穿全页的概念，是记账/预算场景特有的。
- 金额隐藏开关（公共场合打开记账 App 的真实需求）。
- 支出不标红、减号用 U+2212 这类金融数字的细节。
- 画框外的"说明牌"和亚麻色桌面：这是"展示一张手机稿"的展台处理，不属于 App 本身。
- 赭石斜纹表示超额。

## 如果再给我一倍时间

- 做暗色模式：纸色换成暖炭灰 `#1A1917`，墨绿提亮，赭石降饱和，重新检查所有对比度。
- 把"记一笔"的弹出面板也做出来：金额键盘 + 最近常用分类 + 一句话识别（"午饭 28.8"），因为首页的价值最终取决于记一笔有多快。
- 左右滑动切换月份，图表与数字带过渡动画。
- 列表行左滑出现"编辑 / 删除"，长按改分类。
- 为图表补上键盘方向键导航和屏幕阅读器的逐日播报。
- 在真机 Safari 和 Windows Chrome 上分别核对中文回退字体下的字重与行高，必要时为微软雅黑单独调整 500 字重的表现（雅黑没有 500，会落到 400 或 700）。
- 让"提示条"根据数据状态切换三种文案：节奏内（墨绿、鼓励）、略超（赭石、建议）、严重超支（更强的视觉 + 具体的削减建议）。
