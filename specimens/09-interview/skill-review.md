# 评审：ui-craft skill（以我自己的审美为参照）

> 评审者：Opus 5.5（`claude-opus-5-5`）。先写了 `taste.md`，之后才读这份 skill。下面凡说"我"，指的都是 `taste.md` 里写下的那套实际习惯。

## 与我一致的地方

- **整体立场**：克制是默认、一屏一个焦点、强调色稀缺、中性色带色温、先灰度后上色、状态完整才算做完。这和我在 A、J 节写的几乎一样。
- **数值层面高度重合**：4px 间距阶梯；控件 28/32/36/44；按钮横向内边距约为高度的 0.4 倍；标题负字距、中文不用负字距；全大写标签 +0.06em；西文正文行高 1.5–1.6、中文 1.7–1.85；65ch / 36em 的行长；`cubic-bezier(0.16, 1, 0.3, 1)` 做进入、退出更快；只动 transform/opacity；不写 `transition: all`；`tabular-nums`、`text-wrap: balance/pretty`、同心圆角、`:focus-visible` 2px + 2px offset。
- **暗色模式的做法**：不用纯黑、表面越高越亮、半透明白边框、强调色提亮降彩、顶部 1px 内高光——和我一致。
- **"AI 味"清单**：紫蓝渐变、渐变文字、emoji 图标、彩色左边框卡、满屏阴影白卡、到处毛玻璃、`✨ 全新` 胶囊——这些我也列为丑或廉价的做法。
- **中文排版部分**写得比我自己写的更细（微软雅黑缺 500 档、`text-spacing-trim`、宋体标题配黑体正文），我认同。
- **Windows / macOS / 小程序 / 邮件**这些平台惯例的部分扎实，这些不是我的审美，是常识，写进去是对的。
- **"渲染后再看一遍"闭环**和 worked-example 里"代码里读不出来的四个问题"，是这份 skill 最有价值的部分之一。

## 我不同意或会做得不一样的地方

1. **它说**：不假思索地用 Inter 是"没有做过选择"，"至少给标题一个有立场的字体"。
   **我会**：产品界面（后台、工具、设置页）默认就用 Inter 或系统字体，标题也一样，只靠字重 600、字距 −0.02em 和 `cv11/ss01` 把它调成"我的"。只有营销页、品牌页、编辑类页面才换有性格的 display 字体。
   **为什么**：工具型界面里，标题字体"有性格"往往在拖后腿：用户每天看八小时，要的是隐身。这条规则会把模型推去给后台标题换 Fraunces、Bricolage 这类字体，结果比用 Inter 更怪。是否"有立场"应该看产品类型，而不是对 Inter 一刀切。

2. **它说**：反收敛，"不要连续几个项目都用同一款字体""每次当作真正的开放问题"，"先列出三个明显不同的方向"。
   **我会**：对营销页和品牌页这样做；对工具型和数据型界面，我会刻意收敛到一套已经验证过的默认值，只改强调色色相和密度。
   **为什么**：工具 UI 好不好看，九成在执行精度，不在新意。逼模型在后台题目上追求"不同"，换来的是可读性下降、组件比例失调。新意应当有预算：营销页预算高，工具页接近零。

3. **它说（隐含）**：暖纸底、陶土色强调、Instrument Serif / Newsreader 标题，是"暖调极简"的推荐方向，色板示例第一个就是"暖纸 · 陶土"。
   **我会**：把这一组明确标成"2025–26 年新的 AI 默认"，和紫蓝渐变放在同一张警示表里。
   **为什么**：模型被"别用紫蓝渐变、别用 Inter"推开之后，最常落到的就是米白 `oklch(0.98 0.01 80)` 底 + 陶土橙 + 衬线大标题 + 等宽小眉题。这已经是一眼可辨的新模板。这份 skill 的示例在主动喂这个方向，它自己的"避免收敛"一节却没点名这个吸引子。

4. **它说**：边框和阴影"二选一"，"同时出现通常是多余的"。
   **我会**：浮层（下拉、popover、弹窗）一定同时用：`0 0 0 1px` 的环形边框加多层投影；浅色模式的卡片常用 1px 边框加 `0 1px 2px` 的极轻阴影。
   **为什么**：只有阴影的浮层在白底上轮廓发虚，只有边框的浮层没有高度感。"环 + 投影"是 Linear、Vercel、Radix 一路的标准做法，也是"精致感"的主要来源。skill 在 components.md 里其实写了"一条低对比边框让轮廓清晰，阴影说明高度"，和 SKILL.md 的说法自相矛盾，应统一成后者。

5. **它说**：Disabled "不要只靠 `opacity: 0.5`"。
   **我会**：承认我实际常用 `opacity: 0.5`。读完我同意它更对，但会给一个折中：按钮这类自身有实底的组件，`opacity: 0.5` 是可以接受的；叠在彩色或图像背景上的元素才必须用 `--text-disabled`。
   **为什么**：完全禁止会让模型为每种组件手写 disabled 色，增加出错面；问题只出在半透明叠到复杂背景上。

6. **它说**：次要文字、占位符都要过 4.5:1，三级文字"均满足 4.5:1"。
   **我会**：前两级（主文字、次要文字）过 4.5；第三级（时间戳、计数、占位符）允许在 3:1–4.5:1 之间，只用于非必要信息，并且不低于 12px/500。
   **为什么**：如果三级都过 4.5，在近白底上第二、三级的明度差只剩 0.08 左右，层级被压扁，于是模型又开始用字号去区分，界面变吵。这是在可访问性和层级之间有意做的取舍，应该写明，而不是假装三级都能过 4.5 又拉得开。（我知道这是偏好，严格的 WCAG 项目应当按它的写法。）

7. **它说**：标题默认 `line-height: var(--leading-snug)` = 1.3（tokens.css 基础样式里 h1–h4 统一用它）。
   **我会**：h1/display 1.05–1.1，h2 1.2，h3/h4 1.3；并且基础样式里直接给大标题加 −0.02em 字距（`:lang(zh)` 下归零）。
   **为什么**：基础样式是模型最可能原样保留的东西。48px 以上标题用 1.3 行高会两行散开，正是"模板感"的来源之一，而这里的默认值在把它写进去。

8. **它说**：`--dur-3: 260ms` 用于面板、对话框；对话框配方入场 `scale(0.96) translateY(8px)`。
   **我会**：对话框 200ms 入场、150ms 退出；位移 4px；抽屉 280–300ms。
   **为什么**：260ms 配 expo-out 曲线，后半段拖得很长，感受上接近 350ms。工具类产品里弹窗是高频操作，我宁可更快。

9. **它说**：`--radius-xl = base × 2.5` = 20px。
   **我会**：圆角阶梯 6 / 8 / 12 / 16 / 全圆，最大的非全圆值是 16px（弹窗），不用 20px。
   **为什么**：20px 的弹窗配 8px 的按钮，比例上太软，像消费类 App。而且乘法推导的阶梯（4/8/12/20）在 base 改成 6 或 10 时会出现 3px、25px 这种尴尬值。

10. **它说**：tokens 起点 `--hue-accent: 255`，同时注释"不要默认科技蓝"。
    **我会**：起点就不给一个"看起来能用"的色相，或者给一个明显需要改的值（比如 0 彩度），强迫模型做选择。
    **为什么**：默认值就是 255 蓝，模型十有八九不会改。注释挡不住默认值。

11. **它说**："首屏构图不要默认'居中标题 + 下方大图'"。
    **我会**：对 SaaS 落地页，居中标题 + 下方带边框的真实产品截图仍然是我最常用、也常常是最对的构图。我会把禁令改成条件：产品界面本身好看、能当主视觉时，居中 + 截图完全成立；问题出在下方是抽象插画、渐变球或假的仪表盘。
    **为什么**：一律禁止会把模型推向左文右图的 5:7 分栏，这又成了新的固定套路。真正的失败不在构图，在于主视觉没有内容。

12. **它说**：评分表"总分低于 16 或任何一项为 0，继续改"。
    **我会**：保留评分表，但改成"每一项写出一个具体证据（哪个元素、什么值）"，而不是打分。
    **为什么**：模型给自己打分几乎永远是 17–19 分。打分不产生信息，写证据才会逼它去看。

## 我的审美里有、而它没写到的东西

这一节最重要。这份 skill 讲了大量"怎么判断"，但我审美里很多真正起作用的东西是**具体的手法和校准值**，它没有写，或者只写了原则没写做法。

### 1. 一套"好的默认套装"本身
skill 的哲学是"不给固定风格"，结果模型手里没有一个可以对照的、经过校准的基线。我的实际做法恰恰相反：我有一套默认值（Inter、stone/zinc 灰阶、一个强调色、8/12/16 圆角、1px 边框、环形浮层阴影），先保证它在任何题目上都 7 分，再按题目改 2–3 个旋钮去拿 9 分。没有基线，"做选择"就只能靠随机。（我在最后一节把这一页写出来了。）

### 2. 精确的边框与发丝线体系
- 浅色：`--border` 用于卡片和分隔，`--border-strong` 用于输入框和 hover 态，两者明度差约 0.05。skill 有这几个变量，但没写**用在哪**、**hover 时从哪个变到哪个**。
- 暗色：边框用 `rgba(255,255,255,0.06–0.10)` 的半透明白，而不是实色，这样同一条边框放在 0.16 和 0.20 两层表面上都协调。
- 图片和截图容器加内描边：`outline: 1px solid rgb(0 0 0 / 0.06); outline-offset: -1px`，防止白底图片融进白底页面。skill 完全没提。
- 分隔线不通栏，左侧缩进到文字起点（skill 提到了，好）；表格行只要底边线（提到了）。

### 3. 浮层的"环 + 投影"阴影写法
```css
--shadow-popover:
  0 0 0 1px oklch(0.2 0.01 260 / 0.08),
  0 2px 4px -1px oklch(0.2 0.01 260 / 0.06),
  0 12px 24px -6px oklch(0.2 0.01 260 / 0.14);
```
以及主按钮的"可按"质感：`inset 0 1px 0 rgb(255 255 255 / 0.12), 0 1px 2px oklch(0.2 0.02 hue / 0.2)`。这两个是让界面从"干净"变成"精致"的最小手段，skill 只给了抽象的 `--shadow-1/2/3`，没说哪个组件用哪个。

### 4. 字距随字号连续变化的函数，而不是两档
我实际用的是一条曲线：12px +0.01em、14px 0、16px −0.006em、20px −0.012em、24px −0.018em、32px −0.022em、48px −0.03em、64px+ −0.035em（Inter 系）。skill 只有"大标题 −0.02"和"全大写 +0.06"两档，中间字号（18–32px 的卡片标题、区块标题）就没人管，而那正是界面里最多的标题。

### 5. 数字与单位的排版
- KPI 数值：`28–36px / 600 / tabular-nums / -0.02em`；单位和货币符号降到 0.6 倍字号、改用 `--text-muted`、`vertical-align` 对齐到 cap height（或用 baseline 对齐 + `margin-left: 2px`）。
- 涨跌：`+12.4%` 用语义色**文字**，不用实底徽标；前面加 ▲▼ 或 +/− 符号。
- 表格数字列的表头也右对齐。
skill 提到"把单位做小做淡"，但没给比例和对齐方法。

### 6. 没有图片时，用"假界面"做主视觉的方法
skill 说"产品本身的界面通常是最好的主视觉"，也说"没有素材时用纯排版、几何图形、SVG"，但没教**怎么用 HTML/CSS 搭一个可信的产品截图**。这是我在落地页里最常做、也最影响成品水准的一件事：
- 一个带 `12px` 圆角、1px 边框、`--shadow-popover` 的窗口框，顶部 36px 的标题栏（可选三个 10px 的灰点）；
- 里面放真实感的 UI：侧栏 + 列表 + 详情，文字用真实内容，字号比真实界面小一档（12–13px），保证缩小后仍清楚；
- 截图宽于文字列（文字 640px，截图 1080–1200px），下边缘用 `mask-image: linear-gradient(to bottom, #000 70%, transparent)` 淡出，或者向下溢出首屏；
- 顶部加一层很淡的径向光晕：`radial-gradient(60% 50% at 50% 0%, oklch(0.7 0.12 hue / 0.18), transparent)`。

### 7. 吸顶导航"滚动后才出现边框"
导航默认透明、无边框；`scrollY > 8` 之后才出现 `--border` 底边和 `bg 80% + blur(12px)`。skill 的吸顶导航配方是一直有边框和模糊，首屏会多一条无意义的线。

### 8. 图标与文字的匹配
- 图标线宽跟随字重：正文 400 配 `stroke-width: 1.5`，500/600 的按钮文字配 1.75–2。
- 图标颜色比相邻文字淡一档（skill 有），**但当前选中项的图标要回到主文字色**（skill 没有）。
- 16px 图标配 13–14px 文字，20px 图标配 16px 文字；图标按钮 28/32/36 正方形，图标居中。

### 9. 选中态与 hover 态的明确区分规则
我会写死：hover = 中性叠层 `--text 5%`；selected = 中性叠层 `--text 8%` + 主文字色 + 500 字重（侧栏），或者 `--accent-subtle` 底 + `--accent-text`（筛选胶囊、分段控件）。skill 只说"必须可区分"，没给配方，模型就会把 hover 和 selected 做成同一个灰。

### 10. 侧栏和顶栏的具体尺寸关系
侧栏宽 240、项高 32、项内边距 8、图标 16、gap 8、字号 13–14、项间距 1–2px、分组标题 11–12px 全大写 text-subtle、分组间距 16–24px；顶栏 48–56px，与侧栏顶部的 workspace 切换器同高、底边对齐。这些"相互对齐"的关系是后台显得规整的关键，skill 只给了区间。

### 11. `<kbd>` 键帽、快捷键提示
```css
kbd { font: 500 11px/1 var(--font-mono); padding: 3px 5px; min-width: 18px;
      border: 1px solid var(--border); border-bottom-width: 2px; border-radius: 4px;
      color: var(--text-muted); background: var(--surface); }
```
"专业工具暗色"一节提到了键帽，但没有写法。

### 12. 滚动容器的边缘淡出、自定义滚动条
`mask-image` 让横向滚动的标签栏、长列表的上下边缘淡出；滚动条 `scrollbar-width: thin; scrollbar-color: var(--border-strong) transparent`。小处，但很影响"做完了"的观感。

### 13. 动效的具体数值组合
skill 给了时长和曲线的区间，没给我实际用的**组合**：
- hover 背景：`150ms ease`（是的，用普通 ease 就够，颜色变化不需要 expo）
- 下拉/popover：入场 `opacity + scale(0.97) + translateY(-2px)`，160ms `--ease-out`；退出 100ms `ease-in`，只做 opacity
- 弹窗：入场 200ms；退出 150ms
- tab 指示条：240ms `cubic-bezier(0.65, 0, 0.35, 1)`
- 列表 stagger：40ms，最多 6 项
- 命令面板：0ms，或只做 80ms 的 opacity
- 弹簧（Motion）：`{ type: "spring", bounce: 0, duration: 0.3 }`——无过冲才是我的默认，skill 的 `--ease-spring` 有 8% 过冲，我在严肃产品里不会用。

### 14. "安静的外壳，响亮的内容"这个比例概念
我判断一个工具型界面好不好，会看"chrome 的视觉重量 / 内容的视觉重量"。导航、工具栏、边框、标签加起来应该明显轻于内容：外壳全部用 `--text-muted`、13px、500 字重，图标用淡一档的色，选中态只用中性叠层。skill 有"外壳最小化"这句话，但没有可执行的检查方法。

### 15. 文案的语气与长度规则（尤其是标题）
- 区块标题写结论，不写栏目名（worked-example 里有这条，很好，但没提升到 SKILL.md）。
- Hero 标题 4–9 个英文词 / 8–16 个汉字；副标题不超过两行（`max-width: 44ch` / `30em`）。
- 按钮 1–3 个词 / 2–4 个汉字，动词开头。
- 空状态标题 = 现状，描述 = 下一步能做什么，一个主按钮。

### 16. 在真实环境下的取舍
- 网络字体加载不了时（离线、中国大陆），Inter 回退到 Segoe UI / PingFang 时，负字距会让 Segoe UI 显得挤：我会把负字距写在 `@supports (font-variation-settings: normal)` 或字体加载后的类上，或者把负字距幅度减半。skill 讲了回退栈要体面，没讲**参数**也要跟着回退。

### 17. 承认"看不见图像"的偏差并补偿
我知道自己因为看不到图，倾向于避开摄影和插画，做纯排版。如果 skill 想让模型达到我"最好时"的水准，应当明确写：**没有渲染工具时，宁可选更保守的版式（左对齐、单列、少层叠、少绝对定位），因为越复杂的构图越依赖目视校正。** 这是我真实的决策规则，skill 没写。

### 18. 中文里的几个具体值
- 中文标题字重：苹方 600、微软雅黑 700（同一个 token 在两个平台上不同，可以用 `@supports` 无法区分，所以我实际会用 600 并接受 Windows 上变 700）。
- 中文正文 15px 是后台的甜区（14 稍小、16 太松）。
- 中英混排时西文字体放前面，但 **Inter 的数字比苹方的数字窄**，同一行中文 + 数字的视觉高度会不一致，我会给数字所在的元素加 `font-size: 1.02em` 或换 x-height 更大的西文字体。skill 提到了这个现象，但处方偏抽象。

## 写得太泛的地方

1. 原句（SKILL.md 第 4 条）："**标题字可以有性格，正文字要耐读。**"
   替换为："产品界面（后台、工具、设置）：标题与正文同一族（Inter / Geist / 系统字体），标题 600、字距按字号收紧（24px −0.018em，32px −0.022em，48px −0.03em）。营销页与编辑页：标题可换 display 字体，但只用在 ≥32px 处，每屏最多出现两次；正文仍是无衬线 15–17px / 400 / 1.6。"

2. 原句（SKILL.md 第 5 条）："**中性色不要用纯灰——向品牌色相偏一点点（chroma 0.005–0.02）。**"
   替换为："中性色彩度：浅色端（L>0.9）0.002–0.006，中段（L 0.4–0.7）0.008–0.014，深色端（L<0.25）0.01–0.02。超过 0.02 灰色会被读成'有颜色'。色相二选一：跟随强调色（同色系、冷静），或暖灰 H=70–85（纸感）；不要选跟强调色相差 90° 左右的色相，会脏。"

3. 原句："**一个记忆点（signature）——整个界面里唯一'大声'的东西。**"
