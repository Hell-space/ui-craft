# 我的界面审美自述

> 写作时未读取任何外部文件。尽量写我"实际会做的"，包括惯性和偏见。

## 模型

- 名称：Opus 5.5
- 模型 ID：`claude-opus-5-5`

## A 什么是美

我认为美的界面，是**每一个像素都"有理由在那里"，并且这种理由能被眼睛直接感到，而不需要被解释**。具体说，美来自四个来源，按我实际看重的顺序：

1. **克制带来的秩序。** 一个界面里只用 1 款（最多 2 款）字体、3–4 个字号层级、一个强调色、一套间距倍数。当元素数量少于"可以被感知的规则"时，眼睛会自动读出规则，这种"读出规则"的愉悦就是秩序美。廉价界面的问题几乎总是"规则太多"——6 种字号、4 种圆角、3 种灰。
2. **对比的精确。** 美不是"柔和"，而是**该强的地方非常强、该弱的地方非常弱**。标题和正文的字号比至少 1.6 倍以上，主按钮是整页唯一的高饱和色块，次要信息降到 55%–60% 的对比。平庸界面的典型症状是一切都是"中等"：中等字号、中等灰、中等阴影。
3. **材质的诚实。** 屏幕是发光的平面，所以我喜欢接近"印刷品 + 极轻微的物理感"——1px 的发丝边框、几乎看不到的阴影、纸张一样的背景色。我不喜欢假装是玻璃、塑料或霓虹的东西，除非品牌本身就是那个。
4. **内容先于装饰。** 最好的界面在去掉所有装饰后仍然成立。真实的数据、真实的文案、真实的长度（一个超长的用户名、一个 0 的状态）比任何插画都更能让界面显得"高级"。我判断美丑的时候，会把它想象成灰度、无阴影、无图片的版本——如果那个版本已经好看，加回颜色只是锦上添花。

美的"感觉"上，我偏好：**安静、紧凑、精密、有一点点温度**。像一本排版很好的技术书、一把做工好的工具，而不是一张海报。我欣赏 Linear、Stripe 文档、Vercel、Things、iA Writer、Teenage Engineering 的说明书、瑞士国际主义平面设计。我对"情绪板式"的美（大面积渐变、3D 插画、玻璃拟态）是有偏见的——我承认它们可以美，但那不是我自发会做的东西。

## B 字体

### 西文标题（按偏好排序）
1. **Inter**（实际上是我最常用的，坦白说过度使用了）——通用、中性，设 `font-feature-settings: "ss01", "cv11"` 和负字距后在标题上很利落。用于产品界面、后台、SaaS 落地页。
2. **Geist** —— 比 Inter 更几何、更"开发者工具"气质。用于开发者产品、技术品牌。
3. **Instrument Serif** —— 我想要"编辑感 / 有品位 / 有一点文艺"时的第一选择，通常只用在大号 display 标题（48px 以上），配无衬线正文。
4. **Fraunces**（可变，opsz 轴）—— 更温暖、更有个性的衬线，用于生活方式、出版、偏人文的品牌。常设 `font-variation-settings: "SOFT" 50, "opsz" 144`。
5. **Söhne / 若不可用则 Inter Display** —— 想要"冷静的高级感"。
6. **Space Grotesk** —— 需要一点科技怪趣感时用，但我知道它已经被用滥了，所以越来越少用。
7. **IBM Plex Sans** —— 企业、工程、偏严肃的场景。
8. **Newsreader / Source Serif 4** —— 长文阅读型产品的标题。

### 西文正文
1. **Inter**（`font-size: 15px` 或 `16px`，`line-height: 1.5–1.6`）
2. **Geist**
3. **系统字体栈** `-apple-system, BlinkMacSystemFont, "Segoe UI", Roboto, "Helvetica Neue", Arial, sans-serif` —— 在工具型/嵌入型界面里，我真的经常直接用系统字体，因为它最快、最原生。
4. **IBM Plex Sans**
5. **Source Serif 4 / Newsreader** —— 长文阅读正文，18–20px。
6. **Literata** —— 电子书式阅读。

### 等宽
1. **JetBrains Mono**
2. **Geist Mono**
3. **ui-monospace, SFMono-Regular, "SF Mono", Menlo, Consolas** 系统栈
4. **IBM Plex Mono** —— 当我想把等宽当"风格"用（标签、标题小字）时
5. **Berkeley Mono**（若可用）
6. **Fira Code** —— 只在需要连字的代码编辑场景

### 中文
1. **系统栈**：`"PingFang SC", "Hiragino Sans GB", "Microsoft YaHei", "Noto Sans SC", sans-serif` —— 绝大多数情况我实际就是这么写的。
2. **Noto Sans SC / 思源黑体** —— 需要跨平台一致、或需要多字重时 webfont 引入。
3. **HarmonyOS Sans SC** —— 想要比思源更现代、更"产品化"的黑体。
4. **MiSans** —— 类似定位，偏年轻。
5. **Noto Serif SC / 思源宋体** —— 编辑、文化、品牌页标题，配西文 Instrument Serif 或 Fraunces。
6. **霞鹜文楷 LXGW WenKai** —— 文艺、个人博客、读书笔记气质。我知道它很流行，用时会节制。
7. **OPPO Sans / 阿里巴巴普惠体** —— 商业品牌页。

### 刻意回避
- **Roboto 作为品牌字体**：太"安卓默认"，没有态度。
- **Poppins / Montserrat**：几何感过强、字母 a/g 太圆，一眼"模板站 2018"。Montserrat 大写标题尤其廉价。
- **Open Sans / Lato**：2014 年 Bootstrap 气味。
- **Playfair Display**：被"高端婚礼模板"用烂，对比度过高、小字号难看。
- **Comic/手写体、Pacifico、Lobster**：几乎所有场景都不合适。
- **Arial 作为有意选择**：它只该出现在 fallback 里。
- **中文：微软雅黑作为首选**（只放 fallback）、**宋体 SimSun 用于屏幕正文**（hinting 糟糕）、**各种"创意"中文字体**（站酷快乐体等）用于正文。
- 在一个界面里用超过两款家族。

### 字号阶梯（我实际会写的值，产品界面，基准 16px 网页 / 14px 后台）
- 网页/落地页：`12 / 14 / 16 / 18 / 20 / 24 / 30 / 36 / 48 / 60 / 72`，hero 有时 `clamp(40px, 6vw, 72px)`。
- 产品后台：`11 / 12 / 13 / 14 / 16 / 20 / 24`。后台正文我默认 **13px 或 14px**，而不是 16px。
- 比例上我更常用接近 1.25（Major Third）的阶梯，但 display 层会跳级。

### 行高
- 正文：`1.5`（UI）/ `1.6–1.7`（长文英文）/ `1.75–1.8`（长文中文）
- 小字（12–13px）：`1.4`
- 标题 24–36px：`1.2`；48px 以上：`1.05–1.1`；超大 hero：`1.0`
- 按钮、徽标等单行控件：`line-height: 1` 或固定高度居中

### 字距
- 48px 以上：`-0.03em`（Inter 时 `-0.035em`）
- 24–36px：`-0.02em`
- 18–20px：`-0.01em`
- 正文 14–16px：`0` 或 `-0.006em`（Inter 时我常用 `-0.011em`）
- 全大写小标签（eyebrow）：`11–12px`，`letter-spacing: 0.06em–0.08em`，`font-weight: 500/600`，`text-transform: uppercase`
- 中文：正文 `0` 或 `0.02em`，标题 `0` 到 `0.01em`，**绝不用负字距**。

### 字重
- 正文 400；强调/标签/按钮 500；标题 600；hero display 600 或 700（Inter），衬线 display 用 400。
- 我几乎不用 300 以下和 800 以上。不用 bold(700) 做正文强调，用 500/600。
- 暗色模式下，正文我有时会降一档视觉重量（或改用 `-webkit-font-smoothing: antialiased`）。

### 怎么搭配两款字体
- 最常见：**同一家族解决一切**（Inter 全站 + JetBrains Mono 用于数字/代码）。
- 第二常见：**衬线 display + 无衬线正文**：Instrument Serif（hero、章节标题，400，字距 -0.02em）+ Inter（其余全部）。规则是衬线只出现在 ≥32px 处，且每屏最多一两次。
- 第三：**无衬线 + 等宽做"技术味"点缀**：Geist + Geist Mono，等宽用于 eyebrow、数据、标签、快捷键。
- 原则：两款字体之间要有**明确的分工**（一个负责声音、一个负责信息），且 x-height 相近；不要用两款相似的无衬线（Inter + Roboto 这种"差一点"的搭配最糟）。

## C 色彩

### 浅色默认（不给任何要求时）
```
--bg:            #FAFAF9   (oklch(98.5% 0.001 106)) 微暖的近白，stone-50
--surface:       #FFFFFF
--surface-2:     #F5F5F4   (二级面板、hover 行、代码块)
--border:        #E7E5E4   (oklch(92.3% 0.003 49))
--border-strong: #D6D3D1
--text-1:        #1C1917   (近黑，不用纯 #000)
--text-2:        #57534E   (次要)
--text-3:        #A8A29E   (占位、元信息；注意它只能用于非必要信息，对比不达 AA)
--accent:        #4F46E5   (indigo-600) 或 oklch(55% 0.2 270)
--accent-hover:  #4338CA
--accent-subtle: #EEF2FF
--focus-ring:    0 0 0 3px oklch(55% 0.2 270 / 0.25)
--danger:        #DC2626   --success: #16A34A   --warning: #D97706
```
坦白：如果完全没人约束我，我会在 **zinc/slate 冷灰 + indigo/blue** 与 **stone 暖灰 + 一个更有个性的强调色**之间摇摆。前者是我的"惯性默认"，后者是我"想做得更好时"的默认。上面写的是后者。冷灰版本是：bg `#FAFAFA`，border `#E4E4E7`，text `#18181B / #52525B / #A1A1AA`，accent `#2563EB`。

### 暗色默认
```
--bg:            #0C0C0D   (不是纯黑；有时 #0A0A0B 或 oklch(16% 0.005 270))
--surface:       #141416
--surface-2:     #1C1C1F
--border:        #27272A   或 rgba(255,255,255,0.08)
--border-strong: #3F3F46   或 rgba(255,255,255,0.14)
--text-1:        #EDEDEF   (不是纯白)
--text-2:        #A1A1AA
--text-3:        #71717A
--accent:        #818CF8   (indigo-400；暗色下强调色要提亮、略降彩度)
--accent-subtle: rgba(129,140,248,0.12)
```
暗色里我用"表面越高越亮"来表达层级，而不是阴影：bg 16% → surface 19% → surface-2 22% → 弹窗 24% 的亮度阶梯（oklch L）。

### 偏爱的强调色色相
- **Indigo / 蓝紫（oklch hue 265–280）**：我的惯性。
- **深绿 / 墨绿**（`#166534`、`oklch(45% 0.12 155)`）：想要"沉稳、有品位、自然"时。
- **橙 / 朱红**（`#EA580C`、`#E5484D`、`oklch(64% 0.2 40)`）：想要"有能量但不廉价"时，配暖灰效果最好。
- **黄绿 / 荧光柠檬**（`#D4FF3A`）：只在暗色、开发者/潮流品牌里做点缀。
- **克莱因蓝** `#002FA7`：编辑、艺术类品牌。

### 回避
- 纯 `#FF0000`、`#00FF00`、`#0000FF` 等 sRGB 原色。
- **紫粉渐变**（#8B5CF6 → #EC4899）作为主视觉——"AI 产品模板"的标志。
- Bootstrap 蓝 `#007BFF`。
- 高饱和青色 + 洋红的"赛博"配色（除非品牌需要）。
- 多个强调色并列（蓝按钮 + 绿按钮 + 紫徽标）。

### 中性色怎么调
- 我几乎从不用纯中性灰（彩度 0）。浅色系里给中性色 **oklch 彩度 0.003–0.01**，色相要么偏暖（hue 60–90，石头/纸张感），要么偏向强调色（如强调色是蓝，灰就带 hue 260 的 0.005 彩度）。
- 原则："灰色借强调色的色相"，让整套颜色像是同一种光照下的东西。
- 暗色背景我倾向冷一点（hue 260–285，彩度 0.005–0.015），浅色背景倾向暖一点。
- 文本层级靠**亮度**拉开，不靠透明度（透明度文字叠在彩色背景上会脏）。例外：暗色边框我常用 `rgba(255,255,255,0.08)`。

### 渐变
- 我对渐变持**怀疑但不排斥**的态度。可以接受的渐变：
  - 同色相、亮度相差 3–6% 的极轻微纵向渐变（让大按钮或卡片有一点"光"）：`linear-gradient(180deg, oklch(58% 0.2 270), oklch(53% 0.2 270))`
  - 背景上一块非常模糊、低透明的径向光晕：`radial-gradient(600px circle at 50% 0%, oklch(70% 0.15 270 / 0.15), transparent 70%)`
  - 渐隐遮罩（`mask-image: linear-gradient(to bottom, black 70%, transparent)`）用于滚动内容的边缘。
- 不接受的：跨色相的高饱和渐变做文字、按钮、整块背景；彩虹边框；"渐变文字"标题（我承认偶尔被要求时会做，但自己不主动做）。
- 必须插值的话用 `in oklch` 避免中间发灰。

## D 构图

### 栅格与分栏
- 网页：12 栏，gutter `24px`（桌面）/ `16px`（移动），外边距 `clamp(16px, 5vw, 64px)`。
- 但实际上我更多用 **"单列内容 + 偶尔的不对称两栏"**：
  - 文字 + 视觉：`5 / 7` 或 `1fr 1.2fr`
  - 侧栏 + 内容：侧栏固定 `240–264px`（后台）或 `220px`（文档）
  - 标签 + 内容（设置页、定价比较）：`1fr 2fr`（即 4/8）
  - 我喜欢让标题列左对齐、窄（4 栏），正文在右侧 7–8 栏——编辑式左右不对称。
- 卡片网格：`repeat(auto-fill, minmax(280px, 1fr))`，gap `16px`（后台）/ `24px`（营销）。

### 容器宽度
- 营销页最大宽度 `1200px`（有时 `1120px`），内容型 `1080px`。
- 正文阅读宽度 `65ch`（英文）/ `36–40em`（中文，约 680–720px）。
- 后台：全宽，但内容区内部 `max-width: 1440px`；表单/设置 `max-width: 640px`。
- 弹窗：`480px`（确认）/ `560px`（表单）/ `720px`（复杂）。

### 留白量
- 间距刻度：`4, 8, 12, 16, 20, 24, 32, 40, 48, 64, 80, 96, 128`。
- 营销页 section 之间：`96–128px`（桌面），`64px`（移动）。
- 后台卡片内边距 `16–20px`，营销卡片 `24–32px`。
- 标题与其下段落：`8–12px`；段落与按钮组：`24–32px`；eyebrow 与标题：`12px`。
- 原则："组内紧、组间松"，组间距至少是组内距的 2 倍。

### 对齐
- 默认**左对齐**。居中只用于：营销 hero（且行数 ≤ 3）、空状态、单一 CTA 区块、登录页卡片。
- 数字在表格中右对齐 + `font-variant-numeric: tabular-nums`。
- 所有东西对齐到同一条左边线——我会专门检查 icon、标题、正文、按钮文字是否在同一垂直线上（光学对齐：图标按钮有时左移 2px）。

### 首屏
- 营销页首屏我最常见的构图：
  - 顶部 64px 导航（logo 左、链接中/右、一个主 CTA 右）；
  - 下方 96–128px 留白后，一个 eyebrow（小徽标或等宽小字）→ 一个 48–72px 的标题（最多两行，`max-width: 16–20ch`）→ 18–20px 副标题（`max-width: 40–52ch`，text-2 颜色）→ 两个按钮（主 + 次/幽灵）→ 下方一张**真实的产品截图或 UI 拼贴**，宽于文字列，带 1px 边框和大圆角（12–16px），有时向下溢出首屏。
  - 我知道这就是"Linear/Vercel 模板"，它是我的舒适区。
- 想避免套路时，我会做左对齐的大标题 + 右侧留白/小元信息，或编辑式的超大衬线标题占满宽度。

### 焦点与节奏
- 焦点：每屏一个最大最暗（或最彩）的东西，其余至少降两档。用尺寸对比 > 颜色对比 > 位置。
- 节奏：section 之间交替"宽/窄""密/疏""文字/视觉"；特性区我常做 3 列 → 大图 → 2 列不对称 → 引用 → CTA。背景色交替用 bg 和 surface-2，而不是用强彩色带。
- 用重复的小元素（同一格式的 eyebrow、编号 01/02/03、同样的分隔线）制造"拍子"。

## E 几何与深度

### 圆角
- 我的默认值：**按钮/输入 `8px`**（后台小控件 `6px`），**卡片 `12px`**，**弹窗 `16px`**，**大截图容器 `12–16px`**，**徽标 `6px` 或全圆 `9999px`**，**头像全圆**，**tooltip `6px`**。
- 嵌套圆角遵循 `外 = 内 + 内边距`（如卡片 12px、内边距 4px → 内部 8px）。
- 风格变体：锐利/编辑风全用 `0–2px`；友好/消费风用 `12–20px`。我不在一个界面里混用风格。

### 边框还是阴影
- **边框优先**。浅色模式下：1px `--border` 是我的主力分隔手段；阴影只用于"浮起来"的东西（下拉、弹窗、popover、拖拽中元素）。
- 卡片在浅色模式：**1px 边框 + 极轻阴影**或仅边框；在暗色模式：仅边框（阴影在暗色几乎不可见），靠表面亮度分层。
- 我常用"边框 + 内高光"：`box-shadow: inset 0 1px 0 rgba(255,255,255,0.05)` 在暗色卡片顶部。

### 阴影写法（实际会写的）
```css
--shadow-xs: 0 1px 2px rgba(16, 24, 40, 0.05);
--shadow-sm: 0 1px 2px rgba(16, 24, 40, 0.06), 0 1px 3px rgba(16, 24, 40, 0.10);
--shadow-md: 0 4px 8px -2px rgba(16, 24, 40, 0.10), 0 2px 4px -2px rgba(16, 24, 40, 0.06);
--shadow-lg: 0 12px 16px -4px rgba(16, 24, 40, 0.08), 0 4px 6px -2px rgba(16, 24, 40, 0.03);
--shadow-xl: 0 20px 24px -4px rgba(16, 24, 40, 0.08), 0 8px 8px -4px rgba(16, 24, 40, 0.03);
/* 弹窗/popover 常用"边框阴影 + 投影"组合 */
--shadow-popover: 0 0 0 1px rgba(0,0,0,0.06), 0 8px 24px -4px rgba(0,0,0,0.12), 0 2px 6px -2px rgba(0,0,0,0.06);
```
- 阴影颜色带一点色相（蓝灰 `rgba(16,24,40,…)` 或 `oklch(20% 0.02 260 / 0.1)`），不用纯黑。
- 多层叠加、负扩散（spread 负值），让阴影集中在下方而不是四周晕开。
- 主按钮我常加：`box-shadow: 0 1px 2px rgba(0,0,0,0.1), inset 0 1px 0 rgba(255,255,255,0.15)`——一点点"可按"的立体感。

### 纹理、噪点、底纹
- 默认不用。
- 会用的情况：
  - 营销页背景的**点阵或网格底纹**：`background-image: radial-gradient(circle, var(--border) 1px, transparent 1px); background-size: 24px 24px;` 加径向遮罩让它在边缘淡出。这是我比较常用的"高级感"手法（也是套路）。
  - 大面积暗色渐变上加 **2–4% 不透明度的 SVG 噪点**（feTurbulence baseFrequency 0.8）消除色带。
  - 编辑/品牌页的纸张纹理：极少。

## F 组件默认值

### 按钮
- 高度：`36px`（默认）/ `32px`（后台紧凑、表格内）/ `40px`（营销/表单主操作）/ `44–48px`（营销 hero、移动端）
- 水平内边距：`14px`（36 高）/ `12px`（32 高）/ `16–20px`（40+ 高）
- 圆角 `8px`（32 高时 `6px`）
- 字号 `14px`（32 高时 `13px`），字重 `500`，`letter-spacing: -0.006em`
- 图标 `16px`，图标与文字 gap `6–8px`；有图标的一侧内边距减 2px
- 主按钮：accent 底 + 白字；次按钮：surface 底 + 1px border + text-1；幽灵：透明，hover `surface-2`；危险：红底仅用于确认动作
- hover：背景亮度变化 4–6%；active：`transform: translateY(0.5px)` 或 `scale(0.98)`；focus：`outline: 2px solid var(--accent); outline-offset: 2px`（`:focus-visible`）
- disabled：`opacity: 0.5; cursor: not-allowed`

### 输入框
- 高度 `36px`（与按钮一致），内边距 `0 12px`，圆角 `8px`，字号 `14px`（移动端 `16px` 防 iOS 缩放）
- 1px `--border-strong`（输入框边框比卡片边框深一档），背景 `--surface`
- hover：边框加深；focus：边框变 accent + `box-shadow: 0 0 0 3px accent/20%`
- 标签在上方，`13px / 500`，与输入框间距 `6px`；帮助文字 `12–13px / text-2`，间距 `6px`；错误文字 danger 色
- 占位符用 `--text-3`，不写"请输入…"这类废话，写示例值

### 卡片
- 内边距 `20px`（后台）/ `24px`（营销）/ `32px`（大特性卡）
- 圆角 `12px`，1px 边框，`--shadow-xs` 或无阴影
- 卡片标题 `15–16px / 600`，描述 `14px / text-2`，标题与描述 `4–6px`
- 可点击卡片 hover：边框加深到 `--border-strong`，不做大幅上浮（最多 `translateY(-1px)`）

### 表格行
- 行高 `40px`（紧凑 `32–36px`，宽松 `48px`）
- 单元格内边距 `0 12px`（首尾列 `16px`）
- 字号 `13px`（后台）/ `14px`
- 表头：`12px / 500 / text-2`，有时全大写 + `0.04em` 字距，背景 `surface-2` 或透明 + 底边框
- 行分隔：仅底部 1px border，不用斑马纹（数据极密时才用极淡斑马纹 `surface-2` 的一半）
- hover 行：`background: surface-2`
- 数字右对齐 + tabular-nums；状态用小圆点 + 文字；操作列放右侧，hover 时才完全显现（但保持可聚焦）

### 导航
- 顶部导航高度 `56px`（后台）/ `64px`（营销），`position: sticky`，背景 `bg / 80%` + `backdrop-filter: blur(12px) saturate(180%)` + 底部 1px border（滚动后才出现边框更好）
- 链接 `14px / 500 / text-2`，hover `text-1`，当前项 `text-1`
- 侧边栏：宽 `240px`，项高 `32px`，内边距 `0 8–10px`，圆角 `6px`，图标 `16px`，字号 `13–14px`；当前项背景 `surface-2` + text-1 + 字重 500；分组标题 `11–12px` 大写 text-3
- 不在导航里放超过 7 个顶级项

### 徽标（Badge）
- 高度 `20px`（小）/ `22–24px`，内边距 `0 6–8px`，圆角 `6px`（或全圆用于状态 pill）
- 字号 `12px / 500`，有时 `11px`
- 配色：语义色的 subtle 底 + 深一档的同色字（如 `bg: #DCFCE7; color: #166534`），或"中性徽标" `surface-2` + text-2 + 1px border
- 状态徽标常带 `6px` 圆点

### 弹窗
- 宽 `480px` / `560px`，圆角 `16px`（有时 `12px`），内边距 `24px`
- 标题 `18px / 600`，描述 `14px / text-2`，标题区与内容 `8px`，内容与底部按钮 `24px`
- 底部按钮右对齐，主操作在最右，次操作在左（"取消"永远是次按钮）
- 遮罩 `rgba(0,0,0,0.4)`（暗色 `0.6`），有时加 `backdrop-filter: blur(2px)`
- `--shadow-xl` 或 popover 阴影
- 进入：`opacity 0→1` + `scale(0.96→1)` + `translateY(4px→0)`，200ms
- Esc 关闭、焦点陷阱、关闭后焦点回到触发器

## G 动效

### 默认值
```css
--ease-out:     cubic-bezier(0.16, 1, 0.3, 1);    /* expo-out，我最常用的"进入" */
--ease-in-out:  cubic-bezier(0.65, 0, 0.35, 1);
--ease-standard:cubic-bezier(0.2, 0, 0, 1);       /* Material 3 standard 的变体 */
--ease-in:      cubic-bezier(0.4, 0, 1, 1);        /* 退出 */
--dur-instant:  100ms;   /* hover 颜色 */
--dur-fast:     150ms;   /* 按钮、开关、hover 背景 */
--dur-base:     200ms;   /* 下拉、tooltip、弹窗进入 */
--dur-slow:     300ms;   /* 抽屉、页面区块 */
--dur-slower:   500ms;   /* 营销页滚动入场 */
```
- hover 颜色变化：`transition: background-color 150ms ease, border-color 150ms ease, color 150ms ease;`（我不写 `transition: all`）
- 弹出层：进入 200ms `--ease-out`，退出 150ms `--ease-in`（退出比进入快）
- 滚动入场：`opacity 0→1, translateY(8–16px→0)`，500–700ms expo-out，列表项 stagger `40–60ms`，最多 stagger 6–8 个
- 弹簧（若用 Framer Motion）：`{ type: "spring", stiffness: 400, damping: 30 }` 或 `{ bounce: 0, duration: 0.3 }`

### 什么时候加
- 状态变化需要被注意到（保存成功、展开/折叠、切换 tab 的指示条滑动）
- 空间关系需要解释（抽屉从右边来、popover 从触发器长出——`transform-origin` 对准触发器）
- 反馈（按下、加载中骨架屏的 shimmer 1.5s 线性循环）
- 营销页适度的入场与"产品演示"动画

### 坚决不加
- 高频操作（键盘导航、表格排序、输入、命令面板打开——命令面板我最多 100ms 或干脆无动画）
- 超过 400ms 的 UI 过渡
- 弹跳/回弹（overshoot）用在严肃产品里
- 视差、滚动劫持、鼠标跟随光标、无限旋转的装饰
- 只为"好看"而让内容延迟可读
- 永远尊重 `@media (prefers-reduced-motion: reduce)`：把位移动画降为纯淡入或取消

## H 我一定会做的小细节

1. `font-variant-numeric: tabular-nums` 用于所有会变动或需要对齐的数字（表格、计时、价格、统计）。
2. 全局 `-webkit-font-smoothing: antialiased; text-rendering: optimizeLegibility;`（至少在暗色区域）。
3. 标题加 `text-wrap: balance`，段落加 `text-wrap: pretty`，避免孤字。
4. 大标题负字距（见 B 节具体值）。
5. 只用 `:focus-visible` 显示焦点环，而且焦点环清晰可见（2px accent + 2px offset），不删除 outline 了事。
6. 所有可点击元素有 hover、active、focus、disabled 四态，加载态按钮保持宽度不跳动。
7. 输入框在移动端字号 ≥16px。
8. 触控目标 ≥ 44×44px（视觉可以小，命中区用 padding 或伪元素扩大）。
9. 空状态、加载状态（骨架屏形状与真实内容一致）、错误状态、超长文本（`text-overflow: ellipsis` + `title`）都设计到。
10. 用真实感的数据和文案代替 Lorem ipsum（真实人名、合理的数字、有长有短）。
11. 图标统一一个库（Lucide 优先）、统一 `16px / 20px` 尺寸、统一 `stroke-width: 1.5`（或 1.75），颜色跟随 `currentColor`。
12. 暗色模式不是颜色反转：重新调强调色亮度、去掉阴影、用表面亮度分层、图片略降亮度。
13. `::selection` 用强调色的淡色版本：`background: oklch(from var(--accent) l c h / 0.2)` 或具体 hex。
14. 链接下划线用 `text-underline-offset: 3px; text-decoration-thickness: 1px;`，颜色比文字淡（`text-decoration-color: currentColor/40%`）。
15. 滚动容器边缘用 mask 渐隐，横向滚动隐藏滚动条但保留可滚性提示。
16. 键盘快捷键用 `<kbd>` 样式：`font: 11px/1 mono; padding: 2px 5px; border: 1px solid var(--border); border-bottom-width: 2px; border-radius: 4px;`
17. 导航在滚动后才出现底边框/背景模糊。
18. 嵌套圆角满足"外 = 内 + 间距"。
19. `color-scheme: light dark` 写在 `:root`，让滚动条和表单控件跟随主题。
20. 图片/截图容器加 1px 内描边（`box-shadow: inset 0 0 0 1px rgba(0,0,0,0.06)` 或 `outline: 1px solid rgba(0,0,0,0.06); outline-offset: -1px`），防止白底图片融进背景。
21. 中英文混排时数字与西文两侧留空隙（见 L）。
22. 分隔线用 1px 且颜色比边框还淡一点；不用 `<hr>` 的默认样式。
23. 数字统计（KPI）里，数值大、单位小且颜色淡（`$` 与 `%` 降一档字号与颜色）。
24. 相对时间（"3 分钟前"）+ hover 显示绝对时间。

## I 我认为丑或廉价的做法

1. **紫→粉/蓝→紫的大面积渐变背景或渐变文字标题**——"AI 生成的 SaaS 模板"最强信号，说明没有品牌决策。
2. **每个卡片都有大而散的阴影**（`0 10px 30px rgba(0,0,0,0.2)`）——脏、浮、廉价，像 2016 年的 Material 误用。
3. **所有东西都居中**——失去阅读起点，长文居中尤其难读。
4. **emoji 当图标**（🚀 ✨ 💡 做特性图标）——显得随意、不同平台渲染不一致。
5. **太多字号和字重**——层级反而消失。
6. **纯黑 `#000` 背景 + 纯白 `#FFF` 文字**——对比过刺、光晕感强；暗色应 `#0A–#12` 级。
7. **灰字放在彩色背景上**——灰会显得脏；应该用该背景色相的浅/深版本。
8. **三个等宽的特性卡片 + 圆形图标背景 + 标题 + 两行描述**，重复三遍不加变化——最模板化的营销区块（我自己也常犯）。
9. **玻璃拟态到处都是**（`backdrop-filter: blur(20px)` + 半透明白卡）——可读性差、性能差、过时。
10. **按钮和输入框高度不一致**并排出现——一眼"没对齐"。
11. **彩色左边框卡片**（`border-left: 4px solid` 各种颜色）当作设计语言——廉价的"信息提示框"感，被 AI 界面用滥。
12. **过多的徽标/标签/"NEW"/"HOT"**——视觉噪音，稀释真正重要的东西。
13. **Lorem ipsum 和 "John Doe"、"Acme Inc"**——暴露没思考真实内容。
14. **图标风格混用**（线性 + 面性 + 不同粗细）——细节不统一显得廉价。
15. **`transition: all 0.3s ease`**——动画到不该动的属性，节奏拖沓。
16. **hover 时大幅放大（`scale(1.05)`）卡片**——晃眼、像电商广告。
17. **蓝色下划线默认链接 + Times New Roman**（未样式化的浏览器默认）。
18. **过大的圆角配小控件**（24px 圆角的 32px 按钮不是 pill 却也不是方）——介于两种风格之间，犹豫不决。
19. **低对比的浅灰正文**（#999 在白底上）——为了"高级"牺牲可读性。
20. **假数据仪表盘上全是"+12.5% ↑"绿色**——不可信、没有信息量。
21. **随机插画人物（扁平大手大脚风）**——2019 年 SaaS 套路，与产品无关。
22. **一屏里出现三个以上的主按钮**——没有决定"最重要的动作是什么"。
23. **文字直接压在照片上而不加遮罩**——可读性赌运气。

## J 我的实际判断过程

1. **先问"这是什么东西、谁在什么状态下用"。** 我会迅速把题目归类：是"看一眼就走"的（落地页）、"每天用八小时"的（工具/后台）、还是"沉浸阅读"的。这一步决定密度：落地页疏、工具密、阅读中等但行长严格。
2. **找一个参照物/气质词。** 我脑中会冒出一个具体参照："像 Linear 一样"、"像一本好杂志"、"像 Things 3"、"像 Stripe 文档"。我会用 2–3 个形容词定调（如"安静、精密、温暖"），并且这几个词会直接映射到参数：安静 → 低彩度、少颜色；精密 → 小字号、1px 边框、等宽数字；温暖 → 暖灰、衬线标题、稍大圆角。
3. **定 token，再画东西。** 我会先在心里/代码顶部写下：字体、字号阶梯、一套灰、一个强调色、圆角、间距。坦白说，这一步很多时候是我把"默认套装"（Inter + 暖/冷灰 + 一个强调色 + 8/12px 圆角）拿出来，再根据气质词改 2–3 个变量。
4. **从最重要的那一屏/那个组件开始**，而不是从导航开始。先把核心内容的排版做对（标题、正文、数据），再加外围。
5. **先灰度，后颜色。** 先用层级（字号、字重、间距、灰阶）把结构做清楚，再只把强调色放在 1–2 个关键动作上。
6. **填真实内容与边界情况**：长名字、空列表、错误、加载。
7. **自查一遍"眯眼测试"**：眯眼看，最先跳出来的是不是最重要的东西？是否有东西在"抢"？对齐线有几条（越少越好）？有没有超过 3 种灰、超过 2 种圆角？
8. **做减法**：删掉一个装饰、一条分隔线、一个颜色。如果删了不影响，就删。
9. **"做完了"的标准**：
   - 没有任何一个值是"随手"的（每个间距、颜色都来自 token）；
   - 眯眼测试的焦点正确；
   - 状态全（hover/focus/空/错/加载）；
   - 暗色模式（如适用）不是事后补丁；
   - 我再也找不到一个可以删的东西；
   - 移动端 375px 下不破。
   老实说，在没有渲染反馈的情况下，我判断"做完"更多依赖心理模拟和规则核对，所以会偏向保守、可预期的方案——这是我审美趋于"安全"的原因之一。

- **品牌页**：这是我最"放得开"但也最容易落回套路的地方。我会用超大 display 字（120px+，字距 -0.04em）、更大胆的强调色大面积铺底、编辑式不对称排版、全幅图片。

## L 中文界面

1. **字体栈**：`"PingFang SC", "HarmonyOS Sans SC", "Hiragino Sans GB", "Microsoft YaHei UI", "Microsoft YaHei", "Noto Sans SC", sans-serif`；西文字体放在中文字体**之前**（如 `Inter, "PingFang SC", …`），让西文和数字用 Inter 渲染，中文回落到苹方。
2. **字号**：中文正文比同场景西文大 1px（后台 14px 而不是 13px；阅读 17–18px）。中文不用 12px 以下（11px 中文在 Windows 上几乎不可读）。
3. **行高**：中文正文 `1.75`（阅读）/ `1.6`（UI），标题 `1.3–1.4`（中文标题行高不能像西文那样压到 1.1，方块字会挤）。
4. **字距**：正文 `0`–`0.02em`；标题可以 `0.01–0.02em`；**不用负字距**；不做全角字符的大字距"高级感"（如 `letter-spacing: 0.3em` 的四字标题，除非是刻意的品牌风格）。
5. **字重**：中文 600 在苹方下已经很重，标题我常用 **500–600** 而不是 700；Windows 微软雅黑只有 400/700 两档，所以 500/600 会退化——我会接受这个降级或在关键处用 webfont。
6. **中英混排间距**：在中文与西文/数字之间加空格（文案层面）或用 `text-autospace: ideograph-alpha ideograph-numeric`（支持时）。
7. **标点**：使用全角标点；行首不出现标点（`line-break: strict`）；`text-spacing-trim: space-first` 处理连续标点挤压（支持时）。
8. **不用斜体**：中文没有真正的斜体，强调用加粗、颜色或着重号 `text-emphasis: dot`（文学场景）。
9. **对齐**：中文长段落用 `text-align: justify` 效果很好（方块字天然齐整），但含长英文单词时要配 `hyphens` 或避免。
10. **行长**：中文每行 30–40 字为宜，`max-width: 36em`。
11. **气质**：
    - 中文产品界面我会更"克制"：中文字形本身视觉密度高，所以留白比英文版多 10–20%，字重整体轻一档。
    - 营销页大标题用思源宋体 / Noto Serif SC 600 能立刻有"文化感、高级感"；黑体大标题则显得"互联网"。
    - 避免机翻腔文案，按钮用动词短语且 2–4 字（"保存""新建项目"），不写"点击这里"。
    - 数字和日期格式本地化：`2026年11月10日` 或 `2026-11-10`，金额 `¥1,280.00`。
12. **字号阶梯（中文产品）**：`12 / 13 / 14 / 16 / 18 / 20 / 24 / 30 / 36 / 48`。

## M 我的指纹

别人能认出"这是我做的"的特征：

1. **Inter（或 Geist）+ 一个冷/暖灰阶 + 一个蓝紫/靛蓝强调色**。这是最强的指纹，也是我知道的过度使用。
2. **1px 发丝边框无处不在**，阴影几乎不可见。卡片 12px 圆角、按钮 8px 圆角——这组数字几乎是我的签名。
3. **eyebrow 小标签**：标题上方一个小号全大写（或等宽）字、或一个带圆点的 pill（"● Now in beta"）。
4. **hero 下面放一张带边框的大圆角产品截图**，常带顶部径向光晕和点阵底纹。
5. **大标题负字距 + `text-wrap: balance`**。
6. **text-2 用于副标题，副标题 max-width 约 40–50ch**。
7. **等宽字体做小数据/元信息**（版本号、时间、快捷键）。
8. **顶栏 sticky + backdrop blur**。
9. **暗色模式 `#0A0A0B` 级背景 + `rgba(255,255,255,0.08)` 边框**。
10. **三栏特性网格 + Lucide 图标**——我会反复做，并且知道它是套路。
11. **expo-out `cubic-bezier(0.16, 1, 0.3, 1)`** 几乎所有进入动画都用它。
12. **状态徽标 = subtle 底 + 同色深字 + 6px 圆点**。
13. **定价页中间那档用边框强调色 + "Most popular" 徽标**。

引以为傲的：
- 对细节的一致性（tabular-nums、focus-visible、嵌套圆角、状态完整）；
- 层级清晰、信息密度合适；
- 暗色模式做得像样；
- 克制——很少做出"难看"的东西。

自知的偏见/过度使用：
- **太安全**：我的默认结果"不会错但不令人记住"。很多我做的界面看起来像同一家公司出品（"Vercel/Linear 系"）。
- **偏冷偏技术**：即使给消费品牌，我也容易做成开发者工具的气质。
- **偏好英文语境的排版**，中文场景下我需要有意识地调整，否则会把西文的负字距、紧行高带过去。
- **过度依赖"眯眼可见的层级"而忽视个性**：缺少插画、摄影、独特版式这类"性格资产"，因为我无法真正看见图像，就倾向回避。
- **靛蓝强调色**和**三栏卡片**——我知道该少用。
- **点阵底纹 + 光晕**作为"高级感"捷径。

## N 二十条指令

1. 只用一个字体家族解决全部 UI（默认 Inter，`font-feature-settings: "cv11","ss01"`），最多再加一款等宽（JetBrains Mono）用于数字/代码，或一款衬线（Instrument Serif）只用于 ≥40px 的 display 标题。
2. 字号只从这组里选：`12/13/14/16/18/20/24/30/36/48/60`；一屏内最多出现 4 个不同字号。
3. 标题字距：≥48px 用 `-0.03em`，24–36px 用 `-0.02em`；正文 0；全大写小标签 `+0.06em`。中文一律不用负字距。
4. 字重只用 400/500/600；正文 400，按钮与标签 500，标题 600。
5. 中性色带 0.003–0.01 的 oklch 彩度，色相跟随强调色或偏暖；文本三级：`#1C1917 / #57534E / #A8A29E`（浅色），`#EDEDEF / #A1A1AA / #71717A`（暗色）。永远不用纯黑纯白。
6. 整个界面只有一个强调色，只出现在主按钮、链接、选中态和焦点环上；面积不超过视口的 5%。
7. 浅色背景 `#FAFAF9`、表面 `#FFFFFF`、边框 `#E7E5E4`；暗色背景 `#0C0C0D`、表面 `#141416`、边框 `rgba(255,255,255,0.08)`。
8. 分隔与容器用 1px 边框；阴影只给浮层，写成多层、负扩散、带色相的低不透明度：`0 1px 2px rgba(16,24,40,.06), 0 1px 3px rgba(16,24,40,.1)`。
9. 圆角：控件 8px、卡片 12px、弹窗 16px、徽标 6px 或全圆；嵌套时外 = 内 + 内边距。全界面不超过 3 种圆角值。
10. 间距只用 4 的倍数：`4/8/12/16/20/24/32/48/64/96/128`；组内间距 ≤ 组间间距的一半。
11. 控件高度统一：按钮与输入框同高（36px 默认、32px 紧凑、44px 移动/营销），字号 14px/500。
12. 默认左对齐；只有 hero 与空状态允许居中。
13. 正文行长 ≤ 65ch（中文 ≤ 36em）；标题 `text-wrap: balance`，段落 `text-wrap: pretty`。
14. 所有数字 `font-variant-numeric: tabular-nums`，表格数字右对齐。
15. 每个交互元素都有 hover/active/focus-visible/disabled 四态；焦点环 `2px solid accent, offset 2px`。
16. 动效：hover 150ms ease；浮层进入 200ms `cubic-bezier(0.16,1,0.3,1)`，退出 150ms；绝不 `transition: all`；尊重 reduced-motion；高频操作无动画。
17. 用真实、具体、长短不一的内容，并设计空、加载（形状一致的骨架屏）、错误、超长文本四种状态。
18. 禁止：紫粉渐变、渐变文字、emoji 图标、彩色左边框卡片、大而散的阴影、玻璃拟态、hover 放大卡片、Lorem ipsum。
19. 图标只用 Lucide，16/20px，stroke 1.5，`currentColor`。
20. 完成前做三件事：眯眼看焦点是否正确；数一数字号/灰/圆角种类是否超限；删掉一个不影响理解的装饰元素——然后再检查一遍 375px 宽度。
