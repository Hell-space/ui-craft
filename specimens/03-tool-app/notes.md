# 03 · Issue tracker 主工作屏 — 设计笔记

## 模型

Opus 5.5（模型 ID：`claude-opus-5-5`）

## 设计立场

方向：**安静、密、可以整天开着的工具**。一个小团队（虚构的发票 SaaS "Ledgerline" 的 Billing 组，5 人，Cycle 24）的日常工作面：左侧导航 / 中间按状态分组的问题列表 / 右侧选中问题的完整详情。三栏同时可见，因为这类工具最高频的动作是"在列表里上下走、在右边读"，不应该有任何页面跳转或抽屉开合。

几个核心判断：

- **界面本身退后，内容向前。** 整天开着的工具，chrome 越响，疲劳越快。所以几乎全部用中性灰 + 一条细线来分区，颜色只留给"状态"这种真正承载信息的东西，以及一个蓝紫色强调色（选中、焦点、主按钮）。
- **明暗都做，跟随系统，可手动切换。** 全天使用的工具里，有人白天亮色晚上暗色，这是正当需求而不是装饰；且两套都是认真调过的，不是简单反色。
- **键盘优先但不键盘独占。** J/K、S/P/A、R、C、/、Esc 都能用，列表底部常驻快捷键提示，但每个动作都有可点的入口。
- **详情是"文档"，不是"表单"。** 标题直接可编辑、属性是一行行可点的值而非输入框、描述按正文排版（14px、66ch 行宽），活动流是时间线。

考虑过又放弃的：

- **纯暗色、"开发者工具"美学**（霓虹强调、等宽字体满屏）：好看但不适合全天阅读长描述，也有点表演性。
- **表格式（列头可排序的 data grid）**：信息更全，但小团队 15 个 issue 规模下，分组列表比表格更容易扫读，表格的列头是负担。
- **右侧详情做成浮层/抽屉**：会遮住列表，破坏"上下走 + 右边读"的节奏。
- **右侧再加一个属性侧栏（第四栏）**：在 1280–1440 宽的屏幕上会把正文挤窄，改为标题下方的 2×3 属性网格。

## 字体

- **IBM Plex Sans**（400 / 500 / 600，及 400 italic）——全部界面文字与正文。选它是因为它有工程感但不冷：字形略方、x 高度适中、在 13px 下依然清楚，比 Inter 多一点个性，又不像几何无衬线那样在小字号下发糊。和 Plex Mono 是同一家族，ID 与正文并排时气质一致。
- **IBM Plex Mono**（400 / 500）——issue ID（LED-482）、代码、PR 编号、内联 code。ID 用等宽让一列 ID 自然对齐，`letter-spacing: -0.01em` 收一点，避免等宽字显得松。
- 回退栈：`system-ui, -apple-system, "Segoe UI", Roboto, "Helvetica Neue", Arial, sans-serif`；等宽 `ui-monospace, "SFMono-Regular", "Cascadia Mono", Consolas, Menlo, monospace`。离线时 Windows 上落到 Segoe UI / Cascadia Mono，依旧体面。

字号阶梯（px / 行高）：

| 用途 | 字号 | 行高 | 字重 | 字距 |
|---|---|---|---|---|
| 次要元信息、计数、kbd | 11–12 | 16 | 400 | 0 |
| 界面基础字号（列表行、导航、按钮） | 13 | 20 | 400 / 500 | 0 |
| 活动流事件 | 12.5 | 20 | 400 | 0 |
| 描述正文、评论 | 14 | 23 / 22 | 400 | 0 |
| 栏标题（h1） | 14 | 20 | 600 | -0.005em |
| 详情标题 | 22 | 30 | 600 | -0.015em |

只有 6 档，13 是锚点。大标题负字距是因为 Plex 在 20px 以上默认偏松。数字一律 `tabular-nums`（计数、日期、+184/−42、"2 of 14"），避免数字跳动。

## 色彩

全部用 OKLCH 定义，中性色带一点暖（亮色 hue 85）/ 冷（暗色 hue 265）的极低彩度，避免纯灰的死板。

亮色：

| Token | 值 | 角色 |
|---|---|---|
| `--canvas` | `oklch(0.972 0.004 85)` | 侧栏与外框，略暖的纸灰，让工作区比它"亮一级" |
| `--surface` | `oklch(0.995 0.002 85)` | 列表和详情底色，接近白但不刺眼 |
| `--raised` | `oklch(1 0 0)` | 菜单、评论卡片 |
| `--hover` / `--press` | `0.955` / `0.93` 同色相 | 悬停与按下，只靠明度区分 |
| `--line` / `--line-2` | `0.912` / `0.86` | 分隔线 / 输入框与按钮边框 |
| `--text` / `--text-2` / `--text-3` | `oklch(0.235 0.012 265)` / `0.45` / `0.6` | 三级文字，冷一点的墨色 |
| `--accent` | `oklch(0.53 0.16 264)` | 唯一强调色：选中条、焦点环、主按钮、勾选框 |
| `--sel` | `oklch(0.952 0.02 264)` | 选中行底色，强调色的极淡版本 |
| `--st-progress` | `oklch(0.72 0.15 72)` | 进行中（琥珀） |
| `--st-review` | `oklch(0.58 0.14 295)` | 评审中（紫） |
| `--st-done` | `oklch(0.6 0.13 155)` | 完成（绿） |
| `--st-todo` / `--st-canceled` | 中性灰 | 未开始与取消不该抢眼 |
| `--urgent` | `oklch(0.61 0.19 32)` | 紧急优先级、截止日期临近、错误链接 |

暗色：底色 `0.165 / 0.19 / 0.235`（canvas / surface / raised），层级靠"越高越亮"；文字 `0.93 / 0.74 / 0.57`；强调色提亮到 `oklch(0.68 0.14 264)` 并略降彩度，避免在暗底上发光；状态色整体 L +0.06~0.12；菜单阴影换成 1px 亮描边 + 深投影，因为暗色里阴影几乎看不见。

标签色点、头像底色由同一套 L/C 参数 + 各自 hue 生成（`--label-l/--label-c`、`--av-l/--av-c`），所以换主题时只换两个数就整体一致。

为什么一个强调色：选中、焦点、可提交，这三件事在一个工具里是同一种"注意这里"，用同一个颜色反而让人学得快。状态色只在小图标上出现，从不铺大面积底色。

## 构图与间距

- 三栏栅格：`228px | minmax(440px, 5fr) | minmax(500px, 6fr)`，最小总宽 1168px。详情比列表略宽（6:5），因为详情要读，列表只扫。
- 所有栏顶部统一 48px 的工具条，底边一条线贯通三栏（侧栏除外），形成一条视觉地平线。
- 4px 基础单位，常用 4 / 8 / 10 / 12 / 16 / 20 / 24 / 28 / 40。
- 列表行高 38px，组头 34px；行内 7 列网格：`16 | 60 | 16 | 1fr | auto | 20 | 42`，所以优先级、ID、状态、头像、时间在所有行上纵向对齐成列，不需要列头。
- 列表左内边距 20px，与栏标题 `h1` 的左边、组头图标左边对齐。
- 详情正文容器 `max-width: 720px` 居中，左右 40px；正文段落再限制 66ch。宽屏下两侧留白，不让一行拉到 100 字以上。
- 属性用 4 列定义列表（92px 标签 / 值 / 92px 标签 / 值），3 行装下 6 个属性，下接一条分隔线，与正文分区。
- 值按钮 `margin-left: -8px` 抵消自身内边距，使文字与标签列严格对齐，悬停时底色向外扩而不是把文字推开。
- Section 间距：标题→属性 18px，属性→正文 24px，正文→"Linked"/"Activity" 34px —— 越大的语义断点留白越多。

## 几何、深度与质感

- 圆角分三级：4px（kbd、内联 code、焦点环）、6px（按钮、输入框、可点值、菜单项 5px）、8px（卡片、菜单、代码块、链接组）。头像和标签胶囊是全圆。
- 边框是主要的分层手段：1px `--line`。行与行之间用 55% 透明度的线，比栏之间的线更轻，层级靠线的轻重而不是阴影。
- 阴影只用在真正浮起来的东西：菜单（`0 1px 2px` + `0 8px 24px -4px`，带蓝灰色相而非纯黑）、toast。卡片和按钮几乎无阴影，"New issue" 按钮只有一道 1px 的底部微影，让它像一个能按下去的东西。
- kbd 底边 2px，模拟键帽。
- 组头 sticky，背景 92% 不透明 + `backdrop-filter: blur(6px)`，滚动时内容在下面若隐若现，但不影响阅读。
- 选中行：淡强调底色 + 左侧 2px 强调色竖条。竖条是给余光看的，底色是给正视看的。
- 没有纹理、没有渐变。工具界面里纹理是噪声。
- Logo 是内联 SVG：深色圆角方块 + 一个 "L" 形账本线，跟随主题反色。

## 动效与交互状态

- 动效一律短：hover/颜色 120ms，搜索框展开 180ms，菜单弹出 120ms（scale .97 → 1，原点左上），toast 160ms，新评论入场 450ms 上移 4px。没有任何弹簧或延迟入场；`prefers-reduced-motion` 时全部关闭。
- 列表行：hover 底色、选中底色 + 竖条、选中再 hover 加深一级、键盘焦点为 2px 内描边（`outline-offset: -2px`，避免被滚动容器裁切）。
- 鼠标点击不显示焦点环，键盘才显示（`:focus-visible`）。
- 列表是 `role="listbox"`，行是 `option` + `aria-selected`，roving tabindex，只有选中行可 Tab 进入。
- 快捷键：`J/K/↑/↓` 移动，`/` 聚焦过滤，`Esc` 清空过滤或退出输入，`S/P/A` 打开状态 / 优先级 / 负责人菜单，`R` 写评论，`C` 新建，行上 `Enter` 编辑标题。
- 菜单：打开时焦点落在当前值上；方向键或 J/K 移动；数字键直接选；Esc / Tab 关闭并把焦点还给触发按钮；点外部关闭；空间不够时向上翻。
- 改状态/优先级/负责人会实时：更新列表分组、写一条 "Priya moved from … to …  · just now" 的活动记录、更新行的时间为 "now"。如果改动让该 issue 离开了当前视图，toast 提示，但详情保持不变，不会突然换掉你正在看的东西。
- 过滤：输入即过滤，匹配部分在标题里高亮；无结果时给出可操作的空状态文案。
- 计划清单可勾选，详情里 "2 of 4" 与列表行上的 "2/4" 同步。
- 评论框自动增高，空内容时按钮禁用，Ctrl/⌘+Enter 发送，新评论带入场动画并滚动到底。
- 标题 `contenteditable="plaintext-only"`，Enter 提交，Esc 撤销。
- 组头可折叠（Canceled 默认折叠），chevron 旋转。
- 复制 ID：面包屑里的 ID 悬停才露出复制图标，点击后 toast "Copied LED-482"。
- 视图选择与主题存入 localStorage（try/catch 包裹），选中 issue 写入 URL hash，刷新后回到同一个 issue。

## 我在意的细节

1. **所有数字等宽**：计数、日期、"+184 −42"、"2 of 14"，切换时不抖动。
2. **组内按优先级排序**，紧急的永远在每组最上面；"No priority" 排在 Low 之后而不是之前。
3. **Urgent 用实心方块+感叹号，其余用三格信号条**——紧急在扫视时必须从形状上就不同，而不只是颜色。
4. **状态图标是"进度饼"**：Todo 空环、In progress 半饼、In review 四分之三饼、Done 实心勾。图标本身编码了进度顺序，色盲用户也能读。
5. **Backlog 用虚线环**，与侧栏 Backlog 导航图标一致。
6. **Canceled 行加删除线、Done 行文字降一级**，已关闭的东西在视觉上退后。
7. **属性值与标签列严格对齐**（负 margin 抵消内边距），悬停底色外扩。
8. **截止日期 4 天内显示为警示色并附"· 4 days"**，不需要人去心算。
9. **列表行上的计划进度 "2/4"** 只在未完成的 issue 上显示，完成了就不再打扰。
10. **焦点环在滚动容器里向内描边**，避免被 `overflow` 裁掉一半。
11. **菜单关闭后焦点回到触发它的按钮**，键盘用户不会"丢失位置"。
12. **改动让 issue 离开当前视图时，不自动切换详情**，只用 toast 告知。
13. **kbd 提示在搜索框获得焦点或有内容时隐藏**，不和输入文字重叠。
14. **暗色下菜单用 1px 亮描边代替阴影**；头像、标签在暗色里换一套 L/C，而不是同一颜色硬放到暗底上。
15. **文案是可信的**：Stripe webhook 重试导致重复入账、瑞士法郎符号、闰日的循环账单、VAT OSS 报表……都是发票类产品真实会遇到的问题；评论有人的语气和具体日期（"month-end close on the 28th"）。
16. **页面 `<title>` 随选中 issue 变化**，多标签页时能认出来。

## 我刻意回避的做法

- 大面积渐变、玻璃拟态、彩色侧栏、发光按钮。
- 给每个状态一个彩色背景胶囊（"In progress" 黄底标签那种）——列表里会变成彩虹。状态只用 14px 图标。
- 卡片套卡片：列表行不是卡片，详情区不是卡片，只有评论和链接组有边框。
- 用 emoji 当图标；所有图标都是 14/16px 网格上手绘的内联 SVG，统一 1.3–1.5 描边。
- 全大写的小标题加宽字距（"STATUS"、"ASSIGNEE"）：在工具里显得喊叫，换成 12px 次要色的普通大小写。
- 做不起作用的假按钮：侧栏里所有可点的都真的可用；"Projects" 只是静态进度展示，不做悬停态，不假装可点。
- 头像用随机照片或渐变：用首字母 + 由人名固定的色相。
- 用阴影区分区块：分区全靠线和底色明度。
- 把列表做成纯表格加列头。

## 这是"我"的习惯

**大多数设计里都会做的（个人风格）：**

- 用 OKLCH 写 token，中性色加极低彩度的色温，从不使用纯 `#888` 灰。
- 只用一个强调色，状态/语义色只出现在小面积元素上。
- 三级文字颜色（text / text-2 / text-3），而不是用透明度调灰。
- 层级优先靠"线 + 明度"，阴影只给浮层。
- 13–14px 基础字号、4px 间距单位、6/8 的圆角体系。
- `tabular-nums`、`:focus-visible`、`prefers-reduced-motion`、`text-wrap: pretty`、正文 66ch 行宽——这些几乎是条件反射。
- 明暗两套主题 + 同时支持系统偏好与手动覆盖。
- 自己画小 SVG 图标，而不是引图标库。
- 克制的动效：120–180ms，只做"出现"和"状态变化"，不做装饰性动画。
- 写有具体细节、有人物和日期的假数据。

**只为这个题目做的：**

- IBM Plex 家族（换一个更偏内容/品牌的题目我会选别的字体）。
- 38px 行高的高密度列表和按状态分组。
- 进度饼式的状态图标和信号条式优先级。
- 键盘快捷键体系和常驻的快捷键提示条。
- 详情页的"文档式"排版（可编辑标题、属性网格、时间线）。
- 暖纸灰的亮色底（为了全天看着不累）。

## 如果再给我一倍时间

- 真的渲染出来、在 1280 / 1440 / 1920 三个宽度和两种主题下逐屏检查、校对对比度（尤其 `--text-3` 在暗色 canvas 上、状态色在白底上的 3:1）。这次没有使用浏览器预览，所有判断都是在代码里完成的，这是最大的遗憾。
- 命令面板（⌘K），把所有动作统一到一个入口。
- 多选（Shift/⌘ 点击、X 键）与批量改状态。
- 拖拽行到另一个组来改状态。
- 标签与估点也做成可编辑的菜单；描述做成真正的 Markdown 编辑器。
- 窄屏策略：<1168px 时折叠侧栏为图标栏，<900px 时详情改为覆盖层。
- 列表顶部的"显示选项"：按负责人/优先级分组、显示/隐藏列。
- 活动流里的相对时间随时间推移自动更新，"just now" → "2m"。
- 撤销（改状态后 toast 带 Undo）。
