# 游戏内 UI 的同场景复验

2026-11-14，Claude Code 的 Opus 5.5「超高」看了 Godot《潮标》的航行、探头预览和回波原图，对照游戏与前端两份指南讨论。它建议把候选范围放回船的实际航向，把测量结果留在采样点，让界面所用的线和字解释海图。首轮讨论后它写了游戏指南初稿，维护者结合引擎输入、游戏源码和第二轮看图评审整理成现版。[游戏 UI 指南](../references/game-ui.md)

## 《潮标》从船到测站

旧版居中显示探头仓，玩家只能在独立图框里看扇形。一次测深后，左下角显示 27 m，左上站位变成 1 / 3。原站点已经由空框变成带勾的圆点，船停在站上时，这个变化会被船标遮住。新版让探头仓避开船位，用实际的船头方向、原点和比例画出两种覆盖范围。预览与已装的四组数值共用行列。测站与船重叠时错开标识并用线引回原位；深度保留在实际采样点。[同机位实拍](evidence/sonar-ui-transfer.webp)

第二轮只给 Opus 看运行截图。它读出了广域的 210 m / 360°、定向的 140 m / 86°，以及测得 A1 时的 27 m、剩余 76% 和可测 3 次。它指出初始船位的 B2 几乎压在虚线上，读者很难判断算不算覆盖。最后一次改稿让图上标记和面板清单都调用实际测站判定。该船位的广域探头可测 C3，定向探头没有可测站位，B2 在广域范围外。取消预览时也会立即恢复实装探头的可测次数，保留船位、储能与焦点。

Godot 4.7.2 在 1120 × 680、800 × 480 渲染了航行、预览、回波、浅色海图和换装后的画面。在无窗口与 OpenGL 渲染模式中，各通过 47 项引擎事件和状态检查，包括 140 m 半径两侧、86° 扇形两侧、图上清单与实际命中、一次确认、取消、归还焦点、冷却、储能不足和关闭动效。键鼠和手柄输入由引擎重放。[原生工程](../examples/sonar-station/project.godot) · [回归脚本](../examples/sonar-station/verify.gd)

## 《翻花鼓》从时间窗到屏幕上的线

独立执行者从原始节奏页入手，保留八拍谱面、原速度和 ±210 毫秒判定。在 1120 × 680 下，首次提前 180 毫秒按键会得 1 分。原版按下前一帧的鼓点中心在 x=621，而亮框右界只有 x=582.5。改后按拍点速度和同一时间窗绘图，右界为 x=627.5。合拍的轮廓留在打中的位置，落空标记在判定轨，下一拍继续经过。360 像素宽触控仿真也走通落空、命中、结算和重开。[节奏谱面实拍](evidence/festival-ui-transfer.webp) · [可玩的单文件](../examples/festival-beat.html)

固定浏览器时钟下，提前或延后 209 毫秒得分，211 毫秒落空。普通时钟另外经鼠标和触摸跑过完整一局，窄屏同时启用减弱动效。可在技能目录运行 `python -B evals/rhythm-window-regression.py --browser "允许的浏览器路径"` 重放像素边界、命中和重开。两个案例检验的是画面与操作的对应关系。看图意见来自模型，测试覆盖软件输入与渲染，实体手柄、触屏手感、音频延迟和真人反应时间仍待相应设备与观察者验证。
