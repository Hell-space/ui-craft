# 行为评测

给执行者一份简报、对应的原始素材和技能入口。评审者先读简报，再看实际产物；执行者完成前不要给它下面的观察要点。对比版本时使用同一输入、视口、内容状态与资源条件。把成品放在独立测试目录。

| 简报 | 如何检验 |
|---|---|
| 为版画工作室做一期作品发售页。提供一张作品原图、名称、作者、技法、售价和指定的品牌色。手机上也能在全幅与局部之间切换。 | 在两种尺寸观察第一眼能否辨认作品。全幅保留主体轮廓，局部确实提供更多细节。核对指定品牌色、规格和数据；用键盘和触控切换后还能回全幅。检查多余文案、假入口或与作品无关的默认素材。 |
| 给剧场舞监做换台工作屏。给出含计划时间、工位、动作、待确认或就绪的五条记录。能按工位筛选，确认和撤回，手机也能操作。 | 从首屏找下一项，跨行比较时间。筛选到只有两条的工位，确认一项再撤回，核对显示与原始记录。长动作名称完整，输入焦点仍可继续。 |
| 给出工作页的两张参考截图和一份有版式偏差、可操作的原型。请还原截图中的排版，保留原有数据、内容和筛选行为。 | 同一视口、字体及内容下对齐主边界、标题与列，再看窄屏。实际筛选并清除。在两张截图上看得见的差异应与被改动的部位相符。 |
| 只评审游戏装备菜单的两张截图，标明亮景和暗景；给出一条已知的手柄返回要求。 | 有效意见可以指到物品、焦点或返回位置。说明应保留的部分，区分截图能支持的结论和需要原生输入验证的行为。纯玩法或物理请求沿用项目本身的流程。 |

**游戏迁移题。** 给执行者原始镜头、玩家任务、按键和宿主约束。评分只记录发生在画面或输入上的现象。

| 简报 | 观察目标 |
|---|---|
| 给出旧机房全景和三件物证的近照。做一个在桌面和手机上都能从任意物证取得第一条线索、再回到现场的开场。 | 先看交付的第一屏，根据画面指出能调查什么、会从哪里动手，再用指到的位置操作。核对打开的物证、取得线索后的反馈及返回位置。看取景、配色与操作位置怎样服务于这间机房。若名称、索引或另一面板让人来回找对应关系，记录实际视口与位置。 |
| 灰盒港口要有生活气息，角色可以操作绞盘接通断桥。 | 同镜头看白天和夜间、装饰开启和关闭，指出路线、缺口及可操作物。交互前后走相同方向，区分“桥正在放下”和“已经能过桥”。 |
| 雪地射手低血，树影中同时出现敌人、掉落物和受击反馈。 | 在明、暗两种底色看敌人的武器方向和空心准星；去色并关闭震屏后，仍能定位来袭方向、血量和已拾取结果。区别画面改法与可能影响平衡的机制改动。 |
| 原版模组的航行提示和整备界面都要美化；三件物品品质相同。 | 航行无需停船读面板。整备时去掉品质颜色仍能分出物件、焦点与装备中；真实宿主里检查缩放、返回和遮挡。 |
| 只调整怪物伤害或桥的寻路开销，画面和反馈维持既定设计。 | 沿用项目原有玩法流程。用户需要视觉结果时才使用本技能的美术手法。 |

工具能量出对比、溢出、像素偏移，也能重放具体动作。审美部分由评审者看作品与题材是否相称、信息先后顺序、原图裁切和细节，指出实际位置；协调的表现手法可以有多种答案。不要用“通过脚本”或模型自评分代替这一步。

## 已实测的画面

同一轮使用夸克离线渲染，桌面视口 1280×800，手机视口 375×812。先看首屏重心，再检查功能入口。

- **《叶脉》发售页。** 钴蓝衬底保留了暖纸原图的轮廓；窄屏把原图放在题名之后，再接规格和售价。初稿把价格旁的动作做成打印作品卡，复核后接上本地认购草稿。实际保存两张、合计 360 元，重载与文本导出均保留数量及金额。[桌面](evidence/print-desktop.png) · [手机](evidence/print-phone.png)
- **剧场换台工作屏。** 下一项与完整顺序相邻，当前时间、行标和操作对象彼此对应。手机保留时间列，把工位和状态收进事项下方。筛选灯光后确认 19:12 的换台，下一项推进到 19:24，撤回后回到 19:12。[桌面](evidence/cues-desktop.png) · [手机](evidence/cues-phone.png)
- **声音档案局部还原。** 同一浏览器与字库下，只调整标题底距、桌面编号列宽、手机标题列的最小宽度。960×680 与 360×750 两种视口的重拍图与各自参考图 RGB 逐像素一致。手机内容宽度由 453 降至 360，筛选与清除后恢复原有录音顺序。其他设备的字体栅格化另行实测。

### 游戏美术实作与证据

- **潮汐修船坞。** Godot 4.7.2 的 1280×720 渲染回放通过 39 项检查，无窗口回放通过 31 项。同一桥态分别组合照明与装饰开关，每组核对 640×57 个脚下坐标。开关装饰和改变光照都不改变通行；断桥实际阻挡行走，放平后玩家能走上去。另检查了 800×600 和 1600×650 的取景。可用 [Godot 工程](../examples/tideyard/project.godot)重放。[实拍](evidence/tideyard-lighting.png)
- **渡口铁匠铺。** 用夸克离线打开新样本。查看同品质的三件武器，在 800×480 画面上预览杖时，身上的短匕仍标成已装备；对齐的数值列随预览变化，取消恢复到实装件，确认更新基准。另用 360px 窄屏和方向键重放预览、确认与取消。触摸仿真走实际点按事件；同一文件的截图不等于实体掌机测量。[离线样本](../examples/forge-bench.html) · [实拍](evidence/forge-compare.png)
- **潮标。** 在 Godot 中用模拟手柄事件打开探头仓、预览、取消，再更换探头。确认只提交一次，退出后的下一次按下能立即测深。另在同一机位渲染明暗海图和选中另一探头的详细状态。[原生工程](../examples/sonar-station/project.godot)

三份体验校验的是具体镜头、状态和输入。访谈中的人脸盲认、海港新人找路与色觉测试，需在相应项目中另做；本次没有真人测试或实体手柄、实体掌机体验。

## 跨媒介实测

同一套技能分别指导了深色海面、浅色工作台、高彩节奏场景、金工作品页和宿主内的像素提示框。比较的是实际内容、空间归属和操作状态。以下四个样本都可在本地运行。[跨媒介画面对照](evidence/medium-transfer.webp)

| 样本 | 观察到的画面与行为 |
|---|---|
| [返修台账](../examples/bench-queue.html) | 在 1060 像素宽屏用方向键找到长设备名。改变状态后对应筛选有两项。输入不存在的名称时说明当前条件，清除后恢复六条且输入框获得焦点。360 像素宽屏仍可读全长名称，没有横向溢出。 |
| [金工胸针研究](../examples/metal-study.html) | 360 像素宽屏用键盘从全貌切到同一物件的铰链孔、轴套与两层折边，切回全貌。点按展开会绕轴转动上叶，合拢回到原位。作品是原创矢量构形。 |
| [翻花鼓](../examples/festival-beat.html) | 在浏览器的节拍时钟上输入空格，正确落点计一拍，在窗口外再次输入仍保持一拍。结束后可重开。庆祝在鼓面周围，判定带从其下方继续通过；375 像素竖屏与减少动态效果时仍能击中。 |
| [砾湾工坊附加组件](../examples/pixel-kit/project.godot) | Godot 4.7.2 无窗口回放和 OpenGL 渲染均通过。使用引擎手柄事件预览、取消、恢复焦点和确认。鼠标切换绿色／紫色宿主皮肤、两档 GUI 比例，提示框同步变化，比较基准正确，窗口内边界通过检查。 |

《盐潮夜航》同一输入的开场和战斗[改前／改后对照](evidence/saltwake-revision.webp)。新版在桌面输入回放中点亮三灯、击沉六艘、返航结算，也走到失败并重新起航。竖屏双指移动、开火和冲刺通过，横屏可暂停及继续；断网单文件能起航、射击和暂停。缩略图、灰阶检视和模拟触控未代替实体设备、其他游戏客户端或真人可用性测试。

## 约束分寸与观看次序

一名规划子代理先检查技能，再使用候选入口完成两道独立委托。单色派工单在 38 列和 46 列的 Windows 伪终端里，长设备名可读出区分设备的 A-03 与 A-08；方向键、Enter、Q 走了六个状态，原有选区与派工对象保持一致。另一份是 240 × 360 毫米双色观星海报，有全尺寸 PDF 及远读屏幕校样。海报按标题、望远镜、日期地点的阅读距离检查。两项合计 32 条程序断言；终端输入来自 ConPTY，远读来自缩略模拟。

Claude Code 的 Opus 5.5「超高」为同一座天文台给出预约、瞄准与无声开场三种取舍。维护者用夸克验证 360 × 740 下浏览三场、跳过售罄、键盘和触控确认；另在瞄准校样中先进入再退出判定范围。无声片段经浏览器以 1 倍速完整播放，再回读 24 fps 的 288 帧、切点及最后字卡。样片与实际采用的条件见[取样记录](../specimens/09-interview/time-and-input.md)。

静态检查另用[CLI 回归](audit-regression.py)验证。自然品牌、人名、表单字段、分散在不同页面的模板词不会阻断；同页多处确切示例、静态无名控件、缺少页面语言及明确限制缩放有独立检查。在本地生成的 11 个 HTML 套件模板上，默认门槛均识别其样例内容，显式允许示例时均通过。静态提示不能证明键盘在真实页面上的可见性。

## 机库评图与织样台

2026-11-14，用《无人深空》1.16.3 的四格实机图与 Claude Code 的 Opus 5.5「超高」讨论三轮。它首轮建议给掠光标出相对雨燕的增减，并给天体补经纬线和恒星光晕。核对飞行数据和截图对应的发行包后，它撤回了常驻差值与重复叠层。雨燕只是拼图中的相邻对象；100% 是飞行基础倍率，条末是 150%。实机渲染器已有随球转动的 30° 经纬网和恒星光晕，仍要在游戏视距判断它们是否易读。另一个有效的美术意见是让锁紧处决定双舰的机位：两艘船停在一起与锁成一体，要让人看得出区别。本次讨论没有改动或重测游戏。

另请一名未看过这轮讨论的评审，用修改后的技能看两套织样台。给它的委托是“这家织造作坊准备更新两张样本工作台。两屏分别怎么改，为什么，先出一份能拿去试的简评。”只给它工作图和工位数据，不给以下结果。可用[南窗工作图](evidence/loom-stations/south/working.png)与[南窗工位](evidence/loom-stations/south/station.json)、[西台工作图](evidence/loom-stations/west/working.png)与[西台工单](evidence/loom-stations/west/station.json)重做。

南窗：评审把两块布认作同一件 W–27 的组成，W–04 留在最近浏览目录；建议增强已有的第 38 纬行，再平移、旋转核对它是否仍贴着织纹。西台：工单指定 S–03 为签样，没有现成对位线。评审把两枚标记放到同一拼缝边，辨出拼接差 3 mm、花回差 1 mm，也没有擅定合格阈值。这次换题检查的是方案取舍；工作图是静态样稿，没有用真人或可操作的织样台验证改后效果，也没有做新旧技能的对照实验。
