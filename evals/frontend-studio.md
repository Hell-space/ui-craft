# 前端实作与迁移记录

原作由用户指定的 Claude Code 在 Opus 5.5 · 超高下直接写入隔离目录。风洞与电影检查台都把真实截图交回原会话返工。另一个执行者只能读技能入口、相应 references 和原始简报，看不到原作、评测要点或其他人的实现。文中的手机尺寸指夸克的窄视口与触控仿真。 Claude Code 参与的是本次技能采样；日常执行和验收由当前执行者在本地完成。

## 同题的风洞比较工具

[Opus 原作](../specimens/10-wind-tunnel/index.html) 与[技能独立作品](evidence/wind-workbench.html)使用相同任务，各自定义演示数据。前者用固定头模、烟线、基准虚线和阻力/散热读数；后者用有绑带、通风孔和分层壳体的产品近景，并把三档风速下的数值放进一张全表。两者各自全部九组读数、切换固定基准、恢复初始基准、刷新和键盘输入均在四种宽度核对。独立执行者另按三种可选基准走过 27 种组合。

前者首屏返工后，360 像素宽下两组主读数同排于第 318 像素。后者的两项结果在第 511、639 像素，能在首屏读到，壳体占据更大的可辨面积。前者的通风演示使用加热头模散热功率 W，后者使用体积流量 L/s。两份演示的绝对值不能互相换算。[并排实拍](evidence/wind-authors.webp) · [Opus 自己的手机初稿与修稿](evidence/wind-revision.webp)

**匿名看图。** 随机字母替代作者名，另开的 Opus 5.5 · 超高会话只读两幅桌面与两幅 360 像素截图。揭盲后，原作是 A，独立作品是 B。评稿认为 B 的长尾、风槽、系带和卡扣更能辨认实物，A 的头模、支架、绕流烟线和尾迹更能说明风洞题材。比较证据和手机现场选择两项都倾向 A；B 的全风速表能做 A 所没有的跨档查询。评稿指出在强日光、允许固定三款之一为基准时可能会改选 B。现场光照判断是评审推断；运行状态另行实测。这场评稿由同一模型家族完成，并非真人偏好调查。

独立执行者根据更新后的本地技能修了自己的同题作品，未读原作。它保留壳体细节、原数据和跨风速总表，在同一坐标画出当前尾迹与固定基准尾迹，并让两个下降量分别显示“阻力降低”和“通风减弱”。手机首屏也能同时看见风速、两项数值与设定基准。该版由当前执行者本地完成、实测，未再请 Opus 复核。[独立修稿成品](evidence/wind-refined.html)

**独立修稿后的本地盲评。** 重新随机化后，另一位从未看见作者身份、源码与前一轮意见的本地评审，只看两套页面在桌面与手机上的初始、切换后画面。揭盲后，P 是技能独立修稿，Q 是 Opus 修稿。评审认为两者均能作为完整设计交付。P 的三款外形、风槽、绑带与扣件更易辨认，手机先选款再读数的顺序更直接，跨风速总表也保留了。Q 的头模支架、绕流和穿过孔位的气流更利于解释试验，四种外形的同速位置容易比较。P 的尾流集中在壳尾，壳内空气如何换热仍较难看清；Q 的窄屏用 W 表示通风，却把“头模散热”藏进了详细条件。判断来自两名作品作者以外的一位模型评审；实际交互已另行在本机核对。

## 既有 React 产品里的修改

[电影拷贝检查台](../specimens/11-film-inspection/index.html)由一个能编译但会错配数据的页面改造。原版选中 R31 后，迟到的 R17 会换掉标题；备注却会写回 R31。搜索也会被旧结果覆盖，单条记录失败后界面留白，手机整页宽 822 像素。两次 Opus 改稿后，沿用宿主、数据和存储接口，固定这些故障的操作次序重走，具体读数和写入归属均正确。复测了读取失败时单独保存备注、重试后的焦点以及窄屏键盘。

在相同初始源码和接口上，维护者另作了一版。过期请求被丢弃，跨盘草稿和窄屏返回焦点都成立。但该版把备注绑在详情区渲染，读数失败便一同隐藏；原作可以在失败时继续写回对应片号。新版技能由此明确区分“还可独立工作的区域”和“因读不到已有值必须暂缓覆盖的区域”。[组件和改稿依据](../specimens/11-film-inspection/notes.md) · [手机前后](evidence/film-revision.webp)

## 跨题材的光艺节

独立执行者另外从空白完成[折光夜场](evidence/prism-nights.html)。它用紫黑底、珊瑚色排印和分片光带组成展演海报，六场各有画面、场地和作品介绍。1366、360、320 三种宽度均从实际列表打开六份详情；关闭后焦点回到原项。重叠场可保留原场或确认替换；19:45 结束与 19:45 开始可以接排。第二晚的一场同时撞两场，确认替换只移除这两场，第一晚行程保留。刷新、移除再刷新都读回正确结果。最后一次本地看图指出，暗场下的结束时间、场地偏小，且一次替换两场时按钮没有带数量。成品加大窄屏时刻和场地的字号，让确认按钮带上实际受影响的场次数，并重走相邻时段、单冲突和双冲突流程。[手机冲突选择](evidence/festival-conflict.webp) 同时曾发起一份附加的 Opus 同题创作，停止时尚未产出页面；这一题只计入技能独立迁移结果。

## 原八作复测

在 1366×864、360×780 各打开八件既有样本并实际操作一个主要入口。16 次操作均观察到相应变化，四件在窄屏出现整页横向溢出。复测保留了离线字体回退条件和原作者指定的页面尺寸。[逐项结果](../specimens/README.md)

通用能力还取决于执行模型、宿主约束、输入素材和反馈条件。同题实测记录可复查的行为，设计评价须同时指出作品、任务和观看条件。

## 扫描配准的全幅与细节

2026-11-14，在 Claude Code 的 Opus 5.5「超高」会话中用同一幅银杏线稿往返评了三轮。首轮输入是旧页的宽窄屏截图和两张 2000 × 1300 原图。Opus 在叶柄端点看到左边两道红青轮廓，右边只剩一道褐线，指出这些静图无法解释朱红稿是对准了还是被隐藏了。另一位独立执行者用夸克量得旧“全幅”在 1366 像素视口裁去约 18.2% 原稿高度，在 360 像素视口裁去约 24.6% 宽度。图内标签和端点手柄还会遮掉校准标记。

新版用固定底稿决定画幅，将手柄移出纸面。用同一线稿、纸色与两种墨色重建配准前后，另外保留可单看的青蓝稿。第二轮，Opus 复看三种画面，在缺口和叶柄都辨认出青色轮廓原地变深。按它的意见补入深褐色的含义，移动默认分界。第三轮它认出了宽屏两道错开的轮廓，但发现窄屏全幅的缺口仍被分界切开。最后将分界移到本图宽度的 75%，在夸克的 320、360、375 像素视口逐像素对照原稿缺口。初始画面这一区域与全开“配准前”一致，和“配准后”有可见差异。这个位置取决于本图的缺口；清稿服务展示交付外观时，可以直接呈现客户会拿到的单色净稿。[实拍对照](evidence/scan-comparison.webp)

夸克的窄屏触控仿真另复现了纵向翻页把分界从 78% 改成 64% 的问题。修后横拖改变分界，纵向滚动保留原值。另测了键盘到两端、开关叠层、禁用脚本时的静态对照，以及普通目录与两种单文件生成方式的离线使用。横稿和竖稿的边缘与局部校验可用[回归脚本](compare-regression.py)重放。静态评稿来自模型，触控来自浏览器仿真，实体手机手感仍待实测。
